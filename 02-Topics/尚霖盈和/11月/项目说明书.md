# 项目说明书：会员充值同步系统

## 一、项目背景

目前公司采用 **EZR 系统** 和 **伯俊系统** 分别管理会员数据与销售终端。

在现有流程中，会员充值操作发生在 **EZR 系统** 中，而 **伯俊系统** 并不会自动同步充值信息。

因此，工作人员需要在 EZR 中导出或查看充值记录后，**手动登录伯俊系统重新填写并充值**，这造成了以下问题：

1. **操作繁琐**：每次充值都需人工二次输入；
2. **易出错**：金额、会员号或时间填写不一致；
3. **效率低**：人工延迟会导致会员账户余额更新滞后，影响客户体验；
4. **缺乏监控**：没有统一的审核流程记录。

本项目旨在通过自动化流程简化该工作，减少人工操作、提高效率与准确性。

---

## 二、项目目标

建立一个**会员充值同步系统**，实现以下功能：

1. **实时监听 EZR 系统充值事件**；
2. **将充值记录推送到内部审核页面**；
3. **审核人员在页面上确认信息无误后**，系统自动调用接口完成 **伯俊系统充值**；
4. **保存操作日志**，记录每笔同步充值的状态（成功/失败/原因）。

---

## 三、系统总体设计

### 1. 系统架构概述

系统分为三个主要模块：

- **充值监听模块（EZR接口监听）**
	负责监听 EZR 系统的充值事件。
	当检测到新的充值记录时，将相关信息（会员号、金额、时间、操作人）发送至消息队列或通知服务。
	
- **审核页面（Web前端 + 审核API）**
	提供一个 Web 页面，列出所有待审核充值记录。
	审核人员登录后，可逐条核对信息并点击“确认充值”按钮。
	该操作会调用后台接口，触发充值执行逻辑。
	
- **充值执行模块（伯俊接口调用）**
	在审核通过后，通过伯俊系统的 API 接口执行充值操作。
	同时更新记录状态，并记录日志（时间、结果、错误原因）。

### 2. 数据流简图

```
EZR系统 → [充值事件监听] → 通知队列 → 审核页面 → 审核确认 → 伯俊充值接口
```

## 四、功能设计

|模块|功能|输入|输出|
|---|---|---|---|
|EZR监听|监听充值事件并推送通知|EZR API事件|通知消息|
|审核页面|展示待审核充值记录|通知消息|审核指令|
|充值执行|调用伯俊接口充值|审核指令|充值结果与日志|

---

## 五、技术方案

1. **通信机制**
	
	- EZR 系统通过 Webhook 或轮询接口提供充值事件。
	- 系统接收到事件后存入数据库并触发通知。
		
2. **消息通知**
	
	- 可使用 Redis、RabbitMQ 或简单的数据库状态标记实现。
	- 前端页面实时刷新或使用 WebSocket 提示有新充值待审核。
		
3. **审核与安全控制**
	
	- 页面需账号登录，操作有权限控制。
	- 每笔审核操作均有日志追踪，确保可追溯性。
		
4. **接口调用**
	
	- 伯俊系统提供 HTTP/REST 接口，由程序自动提交充值请求。
	- 失败时自动记录日志并重试或人工处理。
