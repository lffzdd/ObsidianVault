以下是对这篇《Agent 的基本架构由哪些核心组件构成？》内容的表格化总结。

**四大核心组件概览**

| 核心组件       | 公司类比   | 核心职责                                 | 关键要点                                                                                                    |
| ---------- | ------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| **LLM 核心** | 老板     | 理解所有输入并做决策，判断下一步是继续思考、调用工具，还是给出最终答案  | System Prompt 定义角色与行为边界；模型选型需权衡推理能力、工具调用稳定性、上下文窗口；推理模型（o1/o3、DeepSeek-R1）适合做大脑；常用"强模型做核心决策 + 小模型处理简单任务" |
| **工具系统**   | 外包执行团队 | Agent 与外部世界交互的唯一入口，负责搜索、执行代码、调 API 等 | 工具定义只含"名字 + 描述 + 参数"；模型负责"决定做什么"、代码负责"真正执行"（决策与执行分离）；description 质量直接影响调用准确性；MCP 协议统一标准化（USB-C 接口）      |
| **记忆系统**   | 公司档案室  | 让 Agent 在任务执行中保持状态，不会"失忆"            | 短期记忆存 context window，长期记忆用向量数据库 + 语义检索；可类比为语义/情景/程序性记忆；工程挑战是上下文压缩、重要性评估、记忆衰减                            |
| **规划模块**   | 项目经理   | 把复杂目标拆解成可执行的步骤列表                     | 底层依赖 LLM 推理能力；推理技术有 CoT、ToT；运作上分 Plan-and-Execute 与 ReAct 两种模式                                          |

**记忆系统的分层**

| 记忆类型 | 实现方式 | 特点 | 子类（仅类比） |
|---|---|---|---|
| **短期记忆** | 装在 context window 里 | 容量有限，存当前任务中间状态，任务结束即清空，类似"工作记忆" | —— |
| **长期记忆** | 向量数据库 + embedding 语义检索 | 容量大、可跨天保留，需主动"回忆"才能调出 | 语义记忆（事实知识）、情景记忆（具体经历）、程序性记忆（做事方法论） |

**规划模块的两种主流模式**

| 模式 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **Plan-and-Execute** | 先让 LLM 输出完整步骤列表，再按顺序逐步执行 | 结构清晰，执行前可看到完整计划、便于人工审核 | 中途结果与预期不符时，原计划可能失效需重新调整 |
| **ReAct** | 每走一步根据当前结果再决定下一步，不提前制定完整计划 | 灵活性极高，可随时根据实际情况调整 | 容易"走偏"，每步局部最优可能忽略整体目标 |

整体运行节奏可概括为：**规划 → 决策 → 执行 → 结果存入记忆 → 再决策**，循环往复直到任务完成；其中 LLM 始终是决策者，工具系统是执行者，记忆系统防止"失忆"，规划模块负责拆解大目标。LangChain、LlamaIndex、AutoGen 等主流框架本质上都围绕这四个组件设计。
