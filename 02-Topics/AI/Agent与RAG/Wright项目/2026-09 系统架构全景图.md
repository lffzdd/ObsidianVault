### 二、动态端到端协作图（三大核心流向）

整个系统有三种不同的运转方式，它们在内部的流通路径截然不同：

```mermaid
sequenceDiagram
    autonumber
    actor Human as 👤 用户
    participant Svc as SessionService (前台接待)
    participant Host as ApplicationHost (物业底座)
    participant Agent as Agent (大脑)
    participant Exec as ToolExecutor (双手)
    participant Backend as ExecutionBackend (隔离后端)
    participant Pool as BackgroundPool (8-Worker线程池)
    participant DB as SQLite WAL Store (持久化中枢)

    %% 链路 1: 前台人机交互流
    rect rgb(235, 245, 255)
    Note over Human, DB: 链路 1：前台交互流（用户提问 -> 思考 -> 执行 -> 答复）
    Human->>Svc: 1.1 终端输入指令: "修改 main.py"
    Svc->>Agent: 1.2 唤醒 wright-session 线程开始推理
    Agent->>DB: 1.3 记流水: user_input
    Agent->>Agent: 1.4 调用 LLM 决策，产生 edit_file 调用
    Agent->>DB: 1.5 记流水: model_step
    Agent->>Exec: 1.6 命令 Executor 执行
    Exec->>DB: 1.7 副作用一阶段: record_intent (pending)
    Exec->>Backend: 1.8 越界检查 + 执行写入
    Backend-->>Exec: 1.9 写入完成
    Exec->>DB: 1.10 副作用三阶段: record_result (succeeded)
    Exec-->>Agent: 1.11 返回执行结果
    Agent->>Svc: 1.12 给出最终解答
    Svc-->>Human: 1.13 UI 渲染流式输出
    end

    %% 链路 2: 子 Agent 递归分派流
    rect rgb(255, 248, 240)
    Note over Agent, Pool: 链路 2：并发子任务流（主 Agent 遇到大任务派生小弟）
    Agent->>Pool: 2.1 主 Agent 调用 spawn_agent，向后台线程池提交子任务
    Pool->>Pool: 2.2 捞取空闲 Worker 线程 (wright-agent-X)
    Pool->>DB: 2.3 继承 parent_agent_task_id，记录独立子任务审计流水
    Pool-->>Agent: 2.4 子任务跑完，通过事件队列通知主 Agent
    end

    %% 链路 3: 后台无人自主巡检流
    rect rgb(240, 244, 248)
    Note over Host, DB: 链路 3：后台宿主自治流（完全脱离人类，深夜自主执行）
    Note over Host: 3.1 用户早就关掉了终端...
    Host->>DB: 3.2 轮询线程 wright-scheduler 每 0.5s 查表: "到期了吗?"
    DB-->>Host: 3.3 发现一条 Cron: "0 3 * * *" 到期
    Host->>DB: 3.4 原子抢占任务 (claim_run)
    Host->>Pool: 3.5 启动无头 SilentAgent 提交给线程池
    Pool->>Backend: 3.6 自动执行测试脚本，产物存入 artifacts/
    Pool->>DB: 3.7 终态落盘 (completed)
    end
```

### 三、主客从属与生命周期速查表

为了防止再次混淆这几个主体的“上下级”，请牢记这张**权力与生命周期对照表**：

| 实体名称 | 谁拥有/创建它？ | 它活多久？（生命周期） | 线程归属 | 核心权力与职责 |
| :--- | :--- | :--- | :--- | :--- |
| **`ApplicationHost`** | 项目根目录启动时创建（单例） | **最长**（与工作区同寿，会话关了它还在） | 独占调度线程、事件线程、8-Worker 线程池 | **最高主权**：锁住工作区、托管后台守护任务、管理外部 MCP 插件子进程。 |
| **`SessionService`** | UI（TUI / Web 引擎） | 会话期（用户关闭当前 Tab 即销毁） | 拥有独立前台工作线程 `wright-session` | **对外接待门面**：接收用户输入、转发流式事件、挂载交互等待。 |
| **`WrightRuntime`** | 由装配函数装配而成 | 会话期（跟随当前 Session 销毁） | 跨线程对象黏合剂 | **接线板**：把 Session、Agent、DB、Renderer 捆绑在一起，没有专属线程。 |
| **`Agent`** | 由 Runtime 装配 | 单次 Run 或单次对话 | 运行在 `wright-session` 或后台 Worker 线程中 | **推理大脑**：构造 Prompt，请求 LLM，驱动 ReAct 循环。 |
| **`ToolExecutor`** | 由 Agent 装配 | 跟随 Agent 生命周期 | 运行在 Agent 所在的工作线程中 | **执行双手**：查权限、做三阶段 SQLite 提交、盲盒式分发工具调用。 |
| **`Session`** | 由装配层或快照恢复 | 存活于内存，定期序列化落盘 | **无线程**（纯数据结构，只提供方法） | **档案袋**：存储消息列表、快照记录，严禁包含活进程。 |
| **`Coordination`** | 由 Host 或 Session 持有 | 跟随 Host 或 Session | **无线程**（纯仲裁数据结构） | **裁判所**：多 Agent 步数配额、父子从属树、级联取消。 |
| **`AutonomyStore`** | 由 ApplicationHost / Runtime 打开 | 全程保持连接，进程退出才 close | 多线程安全（通过 RLock + WAL） | **可信中枢**：所有状态跃迁的唯一持久化事实源。 |
