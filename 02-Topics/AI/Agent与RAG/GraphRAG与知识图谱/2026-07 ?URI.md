我们可以用一个经典的分类和生活中的例子来彻底厘清 **URI**、**URL** 和 **URN** 的关系：

---

### 1. 关系图解：URI 是“父亲”，URL 和 URN 是“儿子”

```
          [ URI ] (统一资源标识符)
         /       \
        /         \
  [ URL ]         [ URN ]
(统一资源定位符)   (统一资源名称)
```

*   **URI (Uniform Resource Identifier，统一资源标识符)**：是一个**大概念**。只要能**唯一标识**一个资源的东西，都叫 URI。
*   **URL (Uniform Resource Locator，统一资源定位符)**：是 URI 的一种。它不仅能标识资源，还能告诉你**它在哪里，以及怎么找到它**（即通过 `http`、`ftp` 等协议定位）。
*   **URN (Uniform Resource Name，统一资源名称)**：也是 URI 的一种。它只给资源起一个**在特定范围内绝对唯一的名字**，但不管它在哪、怎么获取。

---

### 2. 生活中的类比

假设我们要标识“张三”这个人：

*   **URN（名字/身份）**：`张三的身份证号：11010119900101XXXX`。
    *   这个号码全世界唯一，一看到它就知道是张三，但你**无法通过这个号码直接走到他家里去**。
*   **URL（地址/定位）**：`北京市朝阳区XX路XX小区X号楼X单元X室`。
    *   这个地址也是唯一的，并且你**可以直接顺着这个地址找到张三**。
*   **URI（标识符）**：**身份证号和住址，都是 URI**。因为它们都能起到“唯一标识张三”的作用。

所以，**URL 确实只是用来“定位”的 URI**，它最常用于描述网页地址（比如 `https://baidu.com`），告诉浏览器去哪里下载这个页面。

---

### 3. RDF 为什么喜欢用“长得像 URL”的 URI？

在 RDF 中，我们要描述实体（比如姚明），通常会写成：
`http://example.org/person/YaoMing`

这看起来像一个网页地址（URL），但它在 RDF 里的主要作用是作为 **URI（唯一标识符）**。
*   **即使你把这个网址复制到浏览器里打不开（404）**，它在知识图谱里依然是一个合格的、全球唯一的“姚明”标识符。
*   **但是（最佳实践）**：W3C 极力推荐大家把 RDF 中的 URI 设计成**真正的 URL**（即可访问的网页）。这样当别人访问 `http://example.org/person/YaoMing` 时，服务器真的能返回一段关于姚明的 RDF 数据或网页介绍。这就叫 **Linked Data（关联数据）**。
