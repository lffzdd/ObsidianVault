在微软的 **GraphRAG** 中，社区检测（Community Detection）是实现从“零散知识点”提升为“宏观知识图谱摘要”的核心步骤。

GraphRAG 采用的是 **自底向上（Bottom-Up）** 的分层社区检测机制，其底层数学与算法基础是 **Leiden 算法**。

以下从**底层图建模**到**算法迭代**再到**上层摘要生成**，自底向上完整拆解其实现原理：

---

### 第一层（最底层）：原始数据到加权图建模

在运行社区检测之前，GraphRAG 首先从非结构化文本中抽取图结构：

1. **实体与关系抽取**：LLM 扫描文本块（Chunks），提取出节点（实体 Entity）与边（关系 Relationship）。
2. **构建原始知识图谱 $G_0 = (V_0, E_0)$**：
   - **节点 $V_0$**：所有抽取的实体（如 `OpenAI`、`Sam Altman`、`GPT-4`）。
   - **边 $E_0$**：实体之间的关联（如 `Sam Altman --[CEO of]--> OpenAI`）。
   - **边权重 $W_0$**：结合关系出现的频次（Frequency）与 LLM 设定的关联强度（Weight）。
   
此时，每个实体节点都代表图中最底层的最小单位（Level 0 基础节点）。

---

### 第二层：Leiden 算法的自底向上聚类

GraphRAG 没有采用传统的 Louvain 算法，而是采用了更优的 **Leiden 算法**（在 Python 中基于 `graspologic` 或 `igraph` 库实现）。Leiden 算法解决了 Louvain 可能会产生“不连通或断裂社区”的问题。

Leiden 算法本身就是一个递归自底向上的过程，由以下三个核心步骤交替循环：

```mermaid
graph TD
    A[单节点社区 (Level 0)] --> B[1. 局部节点移动 Local Movement]
    B --> C[2. 社区细化 Refinement]
    C --> D[3. 社区聚合 Aggregation to Super-nodes]
    D --> E{是否满足停止条件/无法提高模块度?}
    E -- 否 (生成上一层图) --> B
    E -- 是 --> F[输出分层社区树 Hierarchy]
```

#### 步骤 1：局部节点移动（Local Movement of Nodes）
- **初始状态**：图中的每一个节点各自属于一个独立的社区（$C_1, C_2, \dots, C_n$）。
- **优化目标**：寻找使图的**模块度（Modularity）**或 **CPM（Constant Potts Model）质量函数** 最大化的划分方式。
- **动作**：按随机顺序遍历节点 $v$，计算将其从当前社区移动到相邻社区后的品质函数增量 $\Delta H$。若 $\Delta H > 0$，则将节点移入能产生最大增量的相邻社区中，直到收敛。

#### 步骤 2：社区细化（Community Refinement）
- 为防止生成内部断裂的死角社区，Leiden 在步骤 1 生成的大社区内部进行一次**随机化细化**。
- 允许在大社区内部进一步分裂或重新合并子社区，确保每个划分出来的子社区**内部都是强连通的**。

#### 步骤 3：图的聚合（Aggregation into Super-nodes）
- 将步骤 2 划分出的每个细化社区**收缩压缩为一个“超级节点（Super-node）”**。
- **社区内部的边**：转化为超级节点的自环（Self-loops）权重。
- **社区之间的边**：合并为超级节点之间的加权边（权重为原两社区间所有边的权重之和）。

---

### 第三层：分层社区树的构建（Hierarchy Level Generation）

通过上述的“移动 $\to$ 细化 $\to$ 聚合”，GraphRAG 完成了一次向上抽象，得到了一个全新的、规模更小的超级节点图 $G_1$。

接下来，GraphRAG 对 $G_1$ 再次重复运行 Leiden 算法，得到 $G_2$……以此类推，直到无法进一步聚合或达到设定的最大层级。

最终形成一个自底向上的**分层树状结构（Community Hierarchy）**：

| 层级 (Level) | 社区粒度 | 节点性质 | 现实语义对应示例 |
| :--- | :--- | :--- | :--- |
| **Level 0**（最底层） | 微观/细粒度 | 原始实体节点 | 具体的算法、特定工程师、独立事件 |
| **Level 1** | 中观/小社区 | 局部小图聚合 | 某个具体的项目团队、特定产品线 |
| **Level 2** | 宏观/大社区 | 模块聚合 | 公司部门、技术领域 |
| **Level 3**（顶层） | 全局/超大社区 | 全图核心干线 | 整个行业、跨国企业集团 |

---

### 第四层（最顶层）：社区报告（Community Reports）生成与检索

社区检测算法完成拓扑结构划分后，GraphRAG 在图结构之上引入 LLM 进行知识归纳：

1. **自底向上生成社区报告 (Community Report)**：
   - 对每个层级（Level 0 到 Level N）中的**每个社区**，收集该社区包含的所有节点、边以及对应的文本源切片。
   - 调用 LLM 生成一份结构化的 Markdown 格式报告，包含：
     - **社区标题 & 概述**
     - **核心实体与关系列表**
     - **主要发现/推论 (Key Findings)**
     - **影响与风险评估**

2. **全局查询检索（Global Search）时的应用**：
   - 当用户提出宏观/全局性问题（如“文档中提到的主要风险有哪些？”）时：
   - GraphRAG **不再扫描散乱的实体**，而是根据用户指定的层级（例如 Level 1 或 Level 2），**并行检索对应层级的所有社区报告**。
   - 使用 Map-Reduce 模式：Map 阶段在各个社区报告中寻找答案，Reduce 阶段归纳汇总，得到全局的高质量回答。

---

### 总结

GraphRAG 社区检测的自底向上实现逻辑可概括为：

1. **底图构建**：文本 $\to$ 实体/关系 $\to$ 原始加权图。
2. **Leiden 迭代**：局部移动 $\to$ 随机细化 $\to$ 聚合为超级节点（循环至收敛）。
3. **建立层级**：生成从微观到宏观的分层社区树（Hierarchy Tree）。
4. **语义升维**：利用 LLM 为各层社区生成结构化摘要报告，供全局检索使用。
