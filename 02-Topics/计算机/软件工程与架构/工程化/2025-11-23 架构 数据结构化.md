好，我们来把这件事“系统化”一下，而不是零碎地随手加 dataclass。

你这套系统里，其实已经非常清晰地浮现出几类“东西”：

- 订单记录（数据库查出来的那条）
- 券规则（配置里的那条）
- 预览行（前端表格里的那一行）
- 发券结果（对某个 trade_no 发券的结果）
    

这些如果全用 `dict`，短期 OK，规模一大就变成“键名地狱”。  
所以我们下一步要做的就是：

> **先给这些“核心领域概念”安上名字，用 dataclass 固定住它们的结构。**

我先给你一个“建议的 dataclass 清单”，然后按优先级讲怎么搞。

---

## 一、我们先约定一个地方：`core/models.py`

结构大概这样就行：

```text
core/
  __init__.py
  services.py
  coupon_rule.py
  models.py   ← 这里专门放领域模型 dataclass
```

所有“业务概念”（订单、券规则、预览项、发券结果），都往这里收敛。

---

## 二、优先级 1：PreviewItem（你已经有了雏形）

这个是**最容易、收益最高**的一个。

```python
# core/models.py
from dataclasses import dataclass
from datetime import date
from typing import Optional


@dataclass
class PreviewItem:
    trade_no: str
    old_code: str
    vip_phone: str
    recharge_amount: float
    sub_brand_name: str

    coupon_id: int
    coupon_name: str
    coupon_value: float
    coupon_brand: str

    beg_date: date
    end_date: date
```

然后你在 `core.services` 里，把原来返回 dict 的 `_build_preview_item` 改成：

```python
from core.models import PreviewItem

def _build_preview_item(record: dict, coupon: dict, date_range: dict) -> PreviewItem:
    return PreviewItem(
        trade_no=record["trade_no"],
        old_code=record["old_code"],
        vip_phone=record["vip_phone"],
        recharge_amount=record["recharge_amount"],
        sub_brand_name=record["sub_brand_name"],
        coupon_id=coupon["grpId"],
        coupon_name=coupon["name"],
        coupon_value=coupon["value"],
        coupon_brand=coupon["brand"],
        beg_date=date_range["beg_date"],
        end_date=date_range["end_date"],
    )
```

service 内部提到“预览项”就都是 `PreviewItem` 了，语义立刻清晰很多。

API 层 `/preview` 再用：

```python
from dataclasses import asdict

items = preview_unissued_orders()  # List[PreviewItem]
data = [asdict(item) for item in items]
```

这样对外还是 dict，对内已经是强类型。

## 三、优先级 2：CouponRule（你现在是 dict + config）

你现在的券规则应该大概长这样（来自 config.yaml）：

```yaml
- brand: 品牌A
  name: 品牌A充10000送200元
  grpId: 1002
  value: 200
  min_amount: 10000
  max_amount: null
  type: 1
```

在代码里现在是 `dict`，我们可以抽成：

```python
# core/models.py
from dataclasses import dataclass
from typing import Optional


@dataclass
class CouponRule:
    brand: str
    name: str
    grp_id: int
    value: float
    min_amount: float
    max_amount: Optional[float]
    type: int = 1
```

注意这里我用的是 `grp_id` 而不是 `grpId`，代码里可以用 Python 风格命名，  
从 config 读出来时，再做一次字段映射。

在 `coupon_rule.match_coupon_for_order` 里：

```python
from core.models import CouponRule

def match_coupon_for_order(amount: float, brand: str, rules: list[CouponRule]) -> CouponRule | None:
    # 逻辑就可以变得非常直观：
    for rule in rules:
        if rule.brand != brand:
            continue
        if amount < rule.min_amount:
            continue
        if rule.max_amount is not None and amount > rule.max_amount:
            continue
        return rule
    return None
```

从 config 读出来的 dict 列表 → 转成 `CouponRule` 列表，可以放在 services 里：

```python
cfg = load_config()
rules = [
    CouponRule(
        brand=c["brand"],
        name=c["name"],
        grp_id=c["grpId"],
        value=c["value"],
        min_amount=c["min_amount"],
        max_amount=c.get("max_amount"),
        type=c.get("type", 1),
    )
    for c in cfg["coupons"]
]
```

这样：

- 券规则逻辑完全用属性访问，避免 `coupon["xxx"]` 满天飞
- 将来配置结构轻微变化时，只要改这一处映射代码

## 四、优先级 3：SendResult（单条订单发券结果）

你现在 send 的返回结构已经有了 `ok / stage / error / trade_no / coupon_no`，这非常适合抽成 dataclass。

```python
# core/models.py
from dataclasses import dataclass
from typing import Optional, Dict, Any


@dataclass
class ErrorInfo:
    code: str
    message: str
    detail: Optional[Dict[str, Any]] = None


@dataclass
class SendResult:
    trade_no: str
    ok: bool
    stage: str           # "MATCH" / "SEND" / "ISSUE" / "DB" / "DONE"
    error: Optional[ErrorInfo] = None
    coupon_no: Optional[str] = None
    coupon_grp_id: Optional[int] = None
```

然后 `_send_single_order` 就可以改成：

```python
from core.models import SendResult, ErrorInfo

def _send_single_order(... ) -> SendResult:
    trade_no = record["trade_no"]
    ...

    if coupon is None:
        return SendResult(
            trade_no=trade_no,
            ok=False,
            stage="MATCH",
            error=ErrorInfo(
                code="RULE_NOT_MATCHED",
                message=f"未找到适合充值金额 {record['recharge_amount']} 的发券组",
            ),
        )

    # 发券失败：
    if not (response.status and response.status_code == 200 and response.msg == "成功"):
        msg = f"..."
        return SendResult(
            trade_no=trade_no,
            ok=False,
            stage="SEND",
            error=ErrorInfo(code="SEND_FAILED", message=msg),
        )

    # 全部成功：
    return SendResult(
        trade_no=trade_no,
        ok=True,
        stage="DONE",
        coupon_no=coupNo,
        coupon_grp_id=coupon["grpId"],
    )
```

API 层在 `/send` 里用：

```python
from dataclasses import asdict

results = send_coupon_for_order(trade_nos)  # List[SendResult]
data = [asdict(r) for r in results]
return make_response(True, {"results": data, ...})
```

这样你的 mock 测试也会更好写，IDE 也知道 `result.error.code` 而不是去猜 dict 结构。

## 五、优先级 4（看精力）：OrderRecord

这个是数据库查出来的充值记录，现在也是 dict：

```python
record["trade_no"]
record["recharge_amount"]
record["sub_brand_name"]
record["vip_phone"]
record["old_code"]
```

可以抽一个轻量的：

```python
@dataclass
class OrderRecord:
    trade_no: str
    old_code: str
    vip_phone: str
    recharge_amount: float
    sub_brand_name: str
```

然后你可以在 `db.get_unissued_vipmoney` 那边返回 `List[OrderRecord]` 而不是 `List[Dict]`。  
这一步改起来会稍微多一点地方动，所以我建议放在预览、发券这几个 dataclass 稳定之后再做。

---

## 六、建议的顺序（不一下子全推翻）

你刚说“先把需要搞定的 dataclass 都搞定”，但一次性全动会容易乱。  
更稳的顺序是：

1. **先上 `PreviewItem`**
    
    - 涉及面最小
    - 你已经在用 `_build_preview_item`，改起来只是“返回类型 + API asdict”
        
2. **再上 `CouponRule`**
    
    - 逻辑集中在 `coupon_rule` 和 services 加载 config 那一块
    - 能让规则那部分代码变清爽不少
        
3. **再上 `SendResult` + `ErrorInfo`**
    
    - 对 `_send_single_order` / `/send` 的返回契约重构一遍
    - 你的前端和测试就会开始真正依赖“明确的领域模型”
        
4. 最后看情况要不要把 DB 的 `record` 也抽成 `OrderRecord`。
