# ⭐ **下一步：为 service 层写“模拟对象 + 单元测试”（Mock Test）**

你已经拥有：

- 干净的 core（规则层，可测试 ✔）
- 干净的 service（壳与核拆开 ✔）
- 干净的 API 层（/preview /send 可访问 ✔）
- 页面能点、能发券 ✔

现在需要补上的最后一个“专业工程能力”是：

> **service 层的测试**
> 函数不应依赖真实数据库、不应依赖真实外部接口（ApiClient），
> 而应该“用假的（mock）db 和假的 ApiClient 来测试流程逻辑”。

这是后端开发迈向“高级”的标志性能力。

因为：

- **真实接口会变慢 → 测试会很慢**
- **真实接口会失败 → 测试不稳定**
- **真实接口无法模拟各种异常情况**
- **真实接口越多，你越不敢改代码（害怕测试打到真实系统）**

**Mock 测试就是“安全地模拟系统世界”，从而只测试你的逻辑。**

# 🎯 为什么现在非常适合做这一步？

因为你已经把 service 拆成：

- `_send_single_order(...)` （处理单条，逻辑独立）

这两个函数：

- **几乎所有 IO 都在参数里传进来了**
- **你可以完全脱离数据库 / ApiClient 来测试它们**
- **它们的逻辑足够清晰，可以用伪 DB、伪接口替代真实系统**

你现在已经具备写 service 层测试的前提条件了。

给下面这个函数写测试：

```
_send_single_order(conn, client, record, coupons_map, begDate, endDate)
```

我们要测试四类情况：

2. **券匹配失败**
3. **发券接口失败**
4. **推送接口失败**
5. **数据库更新失败**

注意：
这些错误不可能用真实接口触发，只能用 mock 触发。

这就是你现在必须掌握 mock 的原因。

```python
import pytest
from core.services import _send_single_order

class FakeDB:
    def __init__(self):
        self.updated = []

    def update(self, trade_no):
        self.updated.append(trade_no)


class FakeClientOK:
    """发券成功 + 推送成功"""
    def send_coupon(self, **kwargs):
        return type("Resp", (), {
            "status": True,
            "status_code": 200,
            "msg": "成功",
            "result": [{"CouponNo": "CN123"}]
        })()

    def issue_coupon(self, **kwargs):
        return type("Resp2", (), {"status": True})()


class FakeClientSendFail:
    """发券失败"""
    def send_coupon(self, **kwargs):
        return type("Resp", (), {
            "status": False,
            "status_code": 500,
            "msg": "失败"
        })()

    def issue_coupon(self, **kwargs):
        # 不会走到这里
        return None


class FakeClientPushFail(FakeClientOK):
    """推送失败"""
    def issue_coupon(self, **kwargs):
        return type("Resp2", (), {"status": False})()


def test_single_order_success():
    record = {"trade_no": "T01", "old_code": "OC", "vip_phone": "123"}
    coupons_map = [{"grpId": 1, "name": "券", "value": 10, "brand": "A", "min_amount": 0, "max_amount": 99999}]
    fake_db = FakeDB()
    client = FakeClientOK()

    result = _send_single_order(
        conn=fake_db,
        client=client,
        record=record,
        coupons_map=coupons_map,
        begDate="2025-01-01",
        endDate="2025-06-01",
    )

    assert result["ok"] is True
    assert result["trade_no"] == "T01"


def test_single_order_send_fail():
    record = {"trade_no": "T02", "old_code": "OC", "vip_phone": "123"}
    coupons_map = [{"grpId": 1, "name": "券", "value": 10, "brand": "A", "min_amount": 0, "max_amount": 99999}]
    client = FakeClientSendFail()

    result = _send_single_order(
        conn=None,
        client=client,
        record=record,
        coupons_map=coupons_map,
        begDate="2025-01-01",
        endDate="2025-06-01",
    )

    assert result["ok"] is False
    assert result["stage"] == "SEND"
```

# ⭐ 你刚刚习得的是：“Mock Service 测试”的关键能力

测试不是真的调用外部系统，而是自己设计一个粗糙的“伪对象”：

- `FakeClientOK` → 模拟成功返回
- `FakeClientSendFail` → 模拟发券失败
- `FakeClientPushFail` → 模拟推送失败
- `FakeDB` → 模拟数据库更新

用这些假对象，你可以：

- 不依赖真实接口
- 不依赖真实数据库
- 想制造什么错误就制造什么错误
- 准确测试你的逻辑对各种异常的处理
