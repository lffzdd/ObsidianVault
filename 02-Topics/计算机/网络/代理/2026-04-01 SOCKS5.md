# 约定的协议

你能这么快把底层路由的逻辑理顺，说明你的网络思维已经建立起来了。既然你已经理解了底层的“网卡”和“路由表”，也知道 Socket 就是两端通信的“水管接口”，那我们现在就把视角重新拉回到**最高层（应用层 Layer 7）**。

当你关闭 TUN 模式，决定只用 `127.0.0.1:7897` 这种应用层代理时，面临一个非常现实的问题：

你的浏览器（通过本地 Socket）连上了代理内核的 7897 端口。水管接通了，然后呢？浏览器直接把数据灌进去吗？

如果直接灌数据，代理内核会一脸懵：“你给我发了一堆字节，但我怎么知道你是想让我帮你访问 Google，还是访问 YouTube？”

**所以，浏览器和代理内核之间，必须有一种“约定的语言”来交代目标地址。** 这个“交代任务的语言”，就是 SOCKS5 和 HTTP 代理协议。

我们自底向上，结合它们的发展历史来看看这两种协议到底是什么。

---

### 一、 HTTP 代理 (HTTP Proxy)：为 Web 而生的“代购”

你已经熟悉了 HTTP 协议，那是浏览器和网站服务器之间请求网页的语言（比如 `GET /index.html`）。

**1. 历史背景：为了省网费的缓存服务器**

在 1990 年代初期，互联网带宽极其昂贵且缓慢。跨国访问一个带图片的网页简直是折磨。于是，人们发明了 HTTP 代理服务器（比如著名的 Squid）。

它的初衷根本不是为了“翻墙”，而是为了**缓存**。全公司的人都把浏览器的代理设置为公司的局域网服务器。张三访问了雅虎，代理服务器把雅虎的图片下载下来存进硬盘；李四再访问雅虎时，代理服务器直接把硬盘里的图片丢给李四，从而节省了公司宝贵的出口带宽。

**2. 它是怎么交代任务的？**

如果是普通的 HTTP 流量，浏览器连上代理后，不会发送正常的 `GET /`，而是会发送完整的绝对路径：

`GET http://www.google.com/ HTTP/1.1`

代理服务器一看，就懂了：“哦，你要我帮你去拿 Google 的首页”。

**3. 遇到 HTTPS 怎么办？（核心机制：CONNECT）**

后来，HTTPS 普及了，数据全是加密的。浏览器不可能把加密的明文交给代理服务器去缓存了。

为了让 HTTP 代理还能继续工作，设计者发明了一个极其关键的 HTTP 动词：**`CONNECT`**。

当浏览器想访问加密的 HTTPS 网站时，它会向代理内核（7897 端口）发送这样一句话：

`CONNECT www.google.com:443 HTTP/1.1`

代理内核收到这句话后，立刻明白：“老大要我建立一条通往 Google 443 端口的盲道”。于是代理内核去连 Google，连通后回复浏览器：“搞定了，管道通了”。

接下来，浏览器就把加密的乱码（TLS 流量）直接灌进这个管道，代理内核**什么都不管，只负责原封不动地转发这些盲数据**。

---

### 二、 SOCKS5 代理：万能的“底层盲管”

HTTP 代理虽然好用，但它有一个致命缺陷：它带有太重的“Web 时代”烙印。它最初是为网页设计的。如果你想代理一局《魔兽世界》的游戏流量，或者代理一个 FTP 文件传输、一个邮件客户端的 POP3 流量，用 HTTP 代理就显得非常别扭。

**1. 历史背景：真正的通用网络防火墙穿透**

1992 年，MIPS 计算机系统公司的工程师 David Koblas 发明了 **SOCKS**（得名于 SOCKet Secure）。他的目标很纯粹：设计一种协议，**它不关心你传输的是网页、邮件还是游戏，它只负责最底层的 TCP 连接转发**。

由于它太好用了，后来经过迭代，在 1996 年发布了第五版，也就是今天统治代理界的 **SOCKS5**。

**2. 它是怎么交代任务的？**

SOCKS5 工作在会话层（处于应用层和传输层之间）。它就像一个极其高效的快递中转站，交互过程非常干脆：

1. **浏览器/游戏** 连上代理内核的 7897 端口，发个招呼：“我支持 SOCKS5，我不需要密码（或者附带密码）”。
2. **代理内核** 回复：“验证通过，请吩咐”。
3. **浏览器/游戏** 发送目标指令：“请帮我连接 IP 142.250.190.46，端口 443”。（注意，这里全是极其精简的二进制代码，不像 HTTP 那样全是可读的英文字符串）。
4. **代理内核** 连接成功后，回复：“连接已建立”。
5. 接下来，无论是网页加密数据、游戏操作指令，还是数据库查询语句，**SOCKS5 统统当作无差别的字节流进行盲转**。

**3. SOCKS5 的杀手锏：UDP 支持**

SOCKS5 比前代和 HTTP 代理强大的一点是，它支持 **UDP 协议**的转发。很多现代的多人在线游戏、视频会议（如 Zoom），以及最基础的 DNS（域名解析）查询，使用的都是 UDP。能完美代理 UDP，确立了 SOCKS5 作为通用应用层代理的老大地位。

---

### 三、 总结：你的截图中为什么写着 `SOCKS5/HTTP Port: 7897`

现在的代理内核（比如你使用的 0dcloud 底层的核心程序）都非常智能。它在 `127.0.0.1` 的 `7897` 端口上，同时运行着一个**协议嗅探器**。

当你把某个软件的代理设置为 `127.0.0.1:7897` 时：

- 如果这个软件说的是：“`CONNECT google.com...`”，内核就知道：“哦，这是个传统的 HTTP 代理请求”，于是切换到 HTTP 代理模式处理。
- 如果这个软件发来的是 SOCKS5 的二进制握手包，内核就知道：“哦，这是个 SOCKS5 请求”，于是切换到 SOCKS5 模式处理。

**一句话概括：**

Socket 是一根没有思想的物理水管；

而 **HTTP 代理** 和 **SOCKS5**，是你（浏览器）在往水管里倒水之前，对水管另一头（代理内核）喊的那句口令——**“请把接下来的水，导向 Google 的服务器！”**。只不过，HTTP 的口令带着网页的方言，而 SOCKS5 的口令是适用于所有软件的通用普通话。
