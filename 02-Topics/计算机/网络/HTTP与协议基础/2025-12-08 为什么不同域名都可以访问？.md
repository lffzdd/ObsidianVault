这是一个非常直觉但也是新手（甚至老手）最容易陷入的误区。

看着你的代码截图，确实写得很干净，逻辑看起来是：“我声明了 `server_name williamlao.me`，那 Nginx 就应该只接待这个域名，其他的应该拒之门外，对吧？”

**很遗憾，Nginx 的底层逻辑不是这样的。**

### 核心真相：Nginx 的“独生子”原则

在 Nginx 的世界里，`server_name` **不是防火墙白名单，它只是一个“分拣标签”。**

针对你截图中的 **90 端口**，逻辑流程是这样的：

1. **请求到达**：用户请求 `headscale.williamlao.me:90`。
2. **查找端口**：Nginx 发现你有一个 `server` 块监听了 `listen 90;`（截图最下面那个）。
3. **查找域名匹配**：Nginx 拿着 `headscale...` 去跟你的配置比对。
    
    - 它问：“有没有谁专门声明了 `server_name headscale.williamlao.me` 且监听 90 端口？”
    - **答案：没有。**
        
4. **兜底机制（关键点）**：
    
    - 当找不到精确匹配的域名时，Nginx 必须把请求交给一个 **“默认服务器” (Default Server)** 处理。
    - 如果你没有显式地在某行 `listen` 后面写 `default_server`，**Nginx 会默认把“第一个”加载的，或者“唯一”监听该端口的 server 当作默认服务器。**

结论：

因为你的 Nginx 里只有这一个 server 块在监听 90 端口（它是 90 端口的“独生子”），所以无论谁来访问 90 端口，哪怕是 google.com:90（如果解析到你的 IP），Nginx 别无选择，只能把请求全部塞给下面这个 williamlao.me 的配置块。

它不是因为匹配才进去的，是因为**没地方去**才进去的。

---

### 如何解决？（再填“黑洞”）

要在逻辑上实现你想要的“白名单”效果（即：只允许 `williamlao.me`，其他全滚蛋），你必须手动给 90 端口造一个“垃圾桶”。

你需要修改这个文件，在你的正常配置**上面**，加这么一段：

```Nginx
# === 新增的黑洞块 ===
server {
    listen 90 default_server;  # 1. 抢占“默认服务器”的身份
    server_name _;             # 2. 匹配所有瞎填的域名
    return 444;                # 3. 直接挂断，不给任何反应
}
# ===================

# 下面是你截图里的原有配置，不用动
server {
    listen 90; 
    server_name williamlao.me;
    # ... 你的业务代码 ...
}
```

### 加上这段代码后会发生什么？

1. 用户访问 `headscale.williamlao.me:90`。
2. Nginx 发现不匹配 `williamlao.me`。
3. Nginx 寻找默认服务器，发现上面那个标了 `default_server` 的黑洞。
4. **请求掉进黑洞，连接直接中断。**
5. 只有精准访问 `williamlao.me:90` 的人，才能绕过黑洞，进入下面的正常配置。
