你问到 **Raw Gadget**，刚好能戏剧性地回答你今天问的第一句话——**“为什么没有 main 函数？”**！

---

### 1. 什么是 Raw Gadget？

> **Raw** 的英文意思是：**“生的、原始的、未经加工的”**。

在传统的 Gadget 里（也就是你刚才看的 [`my_usb_mouse.c`](file:///Users/williamlao/Project/4Learning/driver/my_usb_mouse.c)）：
* 你必须写在**内核态**里；
* 没有 `main` 函数，必须编译成 `.ko`；
* 一旦指针写错，整个板子直接死机崩溃。

为了让开发者更爽，Linux 内核官方在 2020 年（Linux 5.7 内核）推出了 **Raw Gadget**：
👉 **它在内核和用户态之间开了一个“绿色通道”（`/dev/raw-gadget`），允许你写一个带 `main()` 函数的普通程序（甚至用 Python），直接在应用层模拟 USB 鼠标！**

### 3. 用 Raw Gadget 写代码是什么感觉？

如果你用 Raw Gadget，你写的就**不再是内核驱动**了，而是一个**完全正常、带 `main` 的 C 程序**：

```c
/* 运行在用户态的普通程序，完全有 main 函数！ */
int main(int argc, char *argv[])
{
    // 1. 打开 Raw Gadget 通道
    int fd = open("/dev/raw-gadget", O_RDWR);

    // 2. 发送指令：“我想要模拟一个鼠标”
    ioctl(fd, USB_RAW_IOCTL_INIT, ...);

    // 3. 在普通循环里直接发鼠标坐标！
    while (1) {
        struct mouse_report report = { .x = 10, .y = 0 };
        ioctl(fd, USB_RAW_IOCTL_EP_WRITE, &report);
        sleep(1); // 随便 sleep，程序崩了也不会导致整个系统死机！
    }

    return 0;
}
```

### 4. 为什么大家喜欢用 Raw Gadget？

1. **写起来极其安全**：
   在应用层写代码，写错了最多你的程序闪退退出，**绝对不会导致 Linux 操作系统死机**。
2. **可以用 Python / Go / Rust 写**：
   内核驱动只能用 C 语言写，而 Raw Gadget 允许你直接用 Python 脚本去模拟 USB 设备。
3. **黑客和安全专家的最爱（挖掘 USB 漏洞）**：
   传统驱动会强行检查数据格式是否规范；而 Raw（原始）Gadget 允许你**故意构造乱码、畸形、破坏性的 USB 恶意数据包**，发给电脑去测试电脑会不会蓝屏（这种技术叫 USB Fuzzing）。

---

### 总结
* **传统 Gadget**：在**内核里**写驱动（没有 `main`，速度极快，适合量产产品）。
* **Raw Gadget**：内核开了一个口子，允许你在**应用层**写普通程序（有 `main`，甚至可以用 Python，开发调试极其方便安全）！

### 看看 Raw Gadget 内部真实的调用链路：

```
【你在应用层写的普通程序 (带有 main 函数)】
  │
  │ 1. 你调用 ioctl(fd, USB_RAW_IOCTL_EP_WRITE, 数据)：“帮我把这几个字节发给硬件！”
  ▼
┌───────────────────────────────────────────────────────────┐
│ Linux 内核里的 Raw Gadget 驱动 (代理人)                     │
│                                                           │
│  • 拿到你的数据                                            │
│  • 它在内核内部，其实就是去调用：                           │
│    usb_ep_queue(ep, req)  ←【没错！它调用的也是这个接口！】 │
└─────────────────────────────┬─────────────────────────────┘
                              │ 
                              ▼
┌───────────────────────────────────────────────────────────┐
│ 底层 UDC 芯片驱动 (比如树莓派/高通驱动)                     │
│                                                           │
│  • 真正去操作芯片的寄存器、DMA 和引脚电平                    │
└───────────────────────────────────────────────────────────┘
```

### 核心本质：

* **传统 Gadget（比如我们写的 [`my_usb_mouse.c`](file:///Users/williamlao/Project/4Learning/driver/my_usb_mouse.c)）**：
  是你**亲自坐在内核里**，直接调用 `usb_ep_queue()`。
* **Raw Gadget**：
  是你**坐在普通用户态（有 `main` 函数）**，通过 `ioctl` 隔空喊话，让内核里的 Raw Gadget 替你去调用 `usb_ep_queue()`！

底层识别芯片、找寄存器地址、驱动 UDC 的脏活累活，**仍然全是由 Linux 内核和底层 UDC 驱动统一搞定**。你的理解完全精准！
