这是一段跨越 60 年的技术演化史，每一代存储方式都是在上一代的痛点上诞生的。

---

## 第一代：文件系统（1960s）

最早计算机里没有"数据库"概念，数据就是磁带上的**文本文件**，程序员自己写代码来读写。 问题很明显：[[codefinity](https://codefinity.com/blog/The-History-and-Development-of-Databases)]

- 数据格式由程序决定，换个程序就读不了
    
- 没有统一查询方式，找数据全靠遍历
    
- 多个程序同时读写同一个文件会冲突
    

---

## 第二代：层级 & 网状数据库（1960s 末）

IBM 推出 **IMS（信息管理系统）**，把数据组织成**树状层级结构**，就像文件夹套文件夹。 比如：公司 → 部门 → 员工。[[codefinity](https://codefinity.com/blog/The-History-and-Development-of-Databases)]

但树状结构有致命缺陷：一个员工只能属于一个部门，现实里"员工跨部门"这种关系就很难表达。网状数据库（CODASYL 标准）允许节点之间多对多连接，但实现复杂，改动数据结构代价极高。[[codefinity](https://codefinity.com/blog/The-History-and-Development-of-Databases)]

---

## 第三代：关系型数据库（1970s–1990s）

1970 年，IBM 科学家 **Edgar Codd** 发表论文，提出"关系模型"：把所有数据拆成**二维表格**（行 × 列），表与表之间通过 ID 关联，用 **SQL** 统一查询。 这是真正的革命：[[cockroachlabs](https://www.cockroachlabs.com/blog/history-of-databases-distributed-sql/)]

- Oracle（1979）、DB2、SQL Server 相继诞生
    
- 任意复杂的查询都能用 SQL 表达
    
- ACID 事务保证数据不出错（转账时不会钱凭空消失）
    

关系型数据库统治了整个 80–90 年代，今天仍是企业数据的核心。[[cockroachlabs](https://www.cockroachlabs.com/blog/history-of-databases-distributed-sql/)]

---

## 第四代：NoSQL（2000s）

互联网爆炸，Facebook、Google、Amazon 面临的问题是：**数据量太大，单台服务器装不下**。关系型数据库扩容极难，而且强一致性带来性能瓶颈。[[cockroachlabs](https://www.cockroachlabs.com/blog/history-of-databases-distributed-sql/)]

Google 在 2004 年发表 **Bigtable** 论文，Facebook 用了类似思路做了 Cassandra，核心思想是：**放弃部分 SQL 能力（比如 JOIN），换取水平无限扩展**。于是出现了：

|类型|代表产品|组织形式|
|---|---|---|
|键值对|Redis、DynamoDB|Key → Value，极简极快|
|文档型|MongoDB|存 JSON 文档，灵活 Schema|
|宽列型|Cassandra、HBase|类 Excel 但可无限加列|
|图数据库|Neo4j|节点 + 边，适合关系网络|

---

## 第五代：对象存储 & 数据湖（2006 至今）

上面所有数据库都解决的是**结构化数据**（能用表格表达的数据）。但互联网上大量数据是**非结构化的**：图片、视频、日志文件、模型权重……这些塞进数据库既贵又低效。

2006 年，Amazon 推出 **S3（Simple Storage Service）**，发明了 Bucket + Object 这套模型。 核心设计哲学是：[[aws.amazon](https://aws.amazon.com/what-is/object-storage/)]

- **不关心数据内容**：什么格式都能存
    
- **扁平寻址**：靠唯一 Key 取文件，不用目录树
    
- **无限水平扩展**：理论上可以存 EB 级别数据
    
- **按用量计费**：不用提前买服务器
    

Cloudflare R2 就是在 S3 之后出现的竞品，完全兼容 S3 API，但**取消了出站流量费**（S3 的流量费是业界痛点）。[[developers.cloudflare](https://developers.cloudflare.com/r2/)]

---

## 最新一层：数据湖仓（2020s）

光有对象存储还不够——数据存进去了，怎么**高效分析**？于是出现了 **Apache Iceberg、Delta Lake** 这类"表格格式"，给 R2 里的 Parquet 文件加上 Schema 和版本管理，让你能直接用 SQL 查询 R2 里的海量数据。这就是你在 Cloudflare 看到的 **R2 Data Catalog** 的由来。[[infoq](https://www.infoq.com/news/2025/11/cloudflare-data-platform/)]

---

整个演化脉络可以总结为一条主线：**数据量越来越大、结构越来越多样，每一代新技术都是在"我上一代处理不了这个规模/这种数据"的痛点上诞生的。** 关系型数据库没有被取代，而是和 NoSQL、对象存储共存，各自解决自己最擅长的问题。[[cockroachlabs](https://www.cockroachlabs.com/blog/history-of-databases-distributed-sql/)]
