### **`ax`、`di` 这类寄存器是 x86 的通用寄存器，名字里藏着它们最初的"分工"，虽然现代编译器早就不严格遵守了。**

---

### **先理解命名规律**

x86-64 有 16 个通用寄存器，同一个寄存器在不同位宽下有不同的名字，以 `a` 寄存器为例：

```
rax   → 64 位完整寄存器
eax   → rax 的低 32 位
ax    → rax 的低 16 位
ah    → ax 的高 8 位
al    → ax 的低 8 位
```

`r` 前缀是 x86-64 扩展时加的，`e` 前缀是 80386 扩展到 32 位时加的，最原始的 `ax`、`bx` 这些是 8086 时代 16 位寄存器的名字。所以你看到 `edi` 就是 `di` 的 32 位版本，`rdi` 是 64 位版本，三者是同一个物理寄存器的不同"窗口"。

---

### **各寄存器的原始含义**

#### `ax` — Accumulator，累加器
最常用的运算寄存器。乘法、除法结果默认放这里，函数**返回值**也约定放 `rax`/`eax`。名字来自"accumulate"，早期做加法循环时结果一直在这里累积。

#### `bx` — Base，基址寄存器
最初用于内存寻址的基址，比如 `[bx + offset]` 这种寻址方式。现代用途已经很通用，没有特殊约束。

#### `cx` — Counter，计数器
专门为循环计数设计。`loop` 指令每次执行会自动把 `cx` 减 1，为零时跳出。`shl`/`shr` 移位指令的移位次数也默认从 `cl`（`cx` 的低 8 位）读取——上面代码里 `shl eax, 1` 直接写了立即数 1，但如果移位次数是变量，就得先放进 `cl`。

#### `dx` — Data，数据寄存器
配合 `ax` 使用。32 位除法时被除数是 `edx:eax`（64 位拼接），结果商在 `eax`，余数在 `edx`。I/O 端口操作也用 `dx` 存端口号。

#### `si` — Source Index，源索引
字符串操作指令（`movs`、`cmps` 等）的**源地址**默认放这里，`si` 里的地址每次操作后自动递增或递减。

#### `di` — Destination Index，目标索引
字符串操作的**目标地址**，和 `si` 配对使用。这也是为什么函数调用约定把第一个参数放 `rdi`——历史上 `di` 就是"目的地"的意思，传参就是"把值送到目的地"，语义上说得通。

#### `sp` — Stack Pointer
上一条消息刚讲过，栈顶指针，不赘述。

#### `bp` — Base Pointer
栈帧基址指针，同上。

---

### **x86-64 新增的寄存器**

8086 只有 8 个寄存器（ax/bx/cx/dx/si/di/sp/bp）。x86-64 扩展时新增了 `r8` 到 `r15`，命名直接用数字，没有历史包袱，也没有特殊语义，纯粹是通用寄存器。它们的各位宽写法是：

```
r8    → 64 位
r8d   → 低 32 位（d = double word）
r8w   → 低 16 位（w = word）
r8b   → 低 8 位（b = byte）
```

---

### **现代调用约定里的实际分工**

虽然原始语义已经淡化，但 System V AMD64 ABI（Linux/macOS 用的约定）重新规定了寄存器的用途：

| 寄存器 | 用途 |
|--------|------|
| `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` | 依次传递第 1\~6 个整型参数 |
| `rax`, `rdx` | 返回值（`rdx:rax` 可返回 128 位） |
| `rbx`, `rbp`, `r12`\~`r15` | 被调用者保存（callee-saved），函数用完必须还原 |
| `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`\~`r11` | 调用者保存（caller-saved），函数可以随便改 |

这就是为什么上面那段汇编里参数 `x` 是从 `edi` 读取的——它是第一个参数，约定放在 `rdi`，而函数只需要 32 位所以用 `edi`。
