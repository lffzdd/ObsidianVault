这其实是每个程序员在成长过程中都会思考的经典问题！

答案是：**“七分靠预判，三分靠实验”**。

简单来说：**有经验的开发者在写代码时，对绝大多数可能出现的 Error 是心知肚明的；但面对陌生领域时，也是通过“故意让它报错”来摸索的。**

我们可以把写代码时对 Error 的掌控分为三个阶段：

---

### 1. 七分靠预判：我们为什么能知道会报什么错？

当我们对语言和业务熟悉后，写下某些代码时，脑子里会自动拉起“红色警报”，预判到可能发生的异常：

* **根据“物理规律”和“常识”预判**：
  * 只要写**读写文件**（`open("file.txt")`），脑子里第一反应就是：“万一文件不存在呢？万一权限不够呢？” ➡️ 预判会报 `FileNotFoundError` / `PermissionError`。
  * 只要写**网络请求**，第一反应就是：“万一断网了呢？万一服务器超时呢？” ➡️ 预判会报 `ConnectionError` / `Timeout`。
  * 只要写**除法**，第一反应就是：“分母会不会是 0？” ➡️ 预判会报 `ZeroDivisionError`。
* **根据 API 文档预判**：
  好的第三方库和标准库，文档里都会明确写着：“如果失败，本函数会抛出 XXX 异常”。我们直接照着文档写 `except XXX` 即可。

---

### 2. 三分靠实验：不知道会报什么错时，我们怎么办？

当你使用一个全新的库，或者代码逻辑非常复杂，**连写代码的人自己都不知道会报什么错时**，程序员们通常会用以下三种招数：

#### 招数一：故意使坏，查看报错（最常用）
就像我们刚才在终端里运行 `Character('2')` 一样。程序员在写正式代码前，会先在测试环境或终端里**故意输入垃圾数据**，看看控制台打印出什么 Error，然后把那个 Error 复制到 `except` 后面。

#### 招数二：先“大网捕鱼”，再“精准打击”
在开发调试阶段，先写一个最宽泛的捕获，把错误类型打印出来：
```python
try:
    # 某些不确定的复杂操作
    result = some_mysterious_function()
except Exception as e:
    # Exception 是几乎所有错误的老大，它能抓住所有错
    # 打印出具体的错误类型，比如：发现打印出来的是 <class 'json.decoder.JSONDecodeError'>
    print(f"原来你报的是这个错: {type(e)}") 
```
知道具体是 `JSONDecodeError` 后，再把代码改成精准的 `except JSONDecodeError:`。

---

### 3. 防御性编程的“黄金法则” ⚠️

在处理 Error 时，有一个非常重要的行业共识：

> **绝对不要无脑地用 `except Exception:` 吞掉所有错误！**

**反面教材：**
```python
try:
    value = Character(ch)
    pirnt(value)  # ⚠️ 注意：这里 print 拼写错了！本该报 NameError
except Exception:
    return False  # 拼写错误被吞掉了，代码永远返回 False，你找几天都找不到 Bug 在哪！
```

**正确做法：**
只捕获你**有把握处理**的、**预料之中**的错误（比如 `ValueError`）。如果发生了预料之外的错误（比如代码拼写错的 `NameError`），让程序直接崩溃报出来，这才是最安全的做法。

### 总结
写代码是一个**“从不知道到知道”**的过程。
刚开始写代码时，我们经常不知道会报什么错，这非常正常；随着踩坑变多、看报错信息的次数变多，你的大脑里就会自动建立起一张“异常转移表”，那时候你就能像写 `try-except ValueError` 一样，优雅又自然地预判一切了！
