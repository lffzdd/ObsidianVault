# 🎯 先说你的核心疑惑：什么叫 IO？

在架构、测试和函数式编程里，**IO 的定义不是“输入/输出”这种教材式的概念**。
真正的含义可以一句话说清：

> **IO = 需要跟外部世界打交道的操作（数据不来自函数参数，而来自“系统外部”）**
>
> 函数每次执行的结果不由你代码的参数100%决定，而是取决于“外面的世界”。

我们用你熟悉的例子来理解：

---

## ✦ 为什么“查库”是 IO？

因为数据库是外部世界：

- 数据可能随时间变化
- 网络可能变
- 用户可能在其他系统里改了记录

只要你一运行代码，结果可能不同。
这就是“外部世界”。

---

## ✦ 为什么“加载配置”是 IO？

因为：

- 你读的是磁盘文件（文件可能被编辑、移动、缺失）
- 配置值由外部世界定义，而不是函数内部决定

返回的内容**不由参数决定**，而由磁盘状态决定。

---

## ✦ 那打印呢？为什么打印也算 IO？

因为打印是一种 **side effect（副作用）**，它改了“世界的状态”。
比如：

- 控制台里多了一行文字
- 日志文件被写入
- 运行结果已经无法“纯粹复现”

更重要的：
**打印让一个函数变成不可预测（不可复现、不可测试）**。

---

# 🎯 那什么叫“纯计算”？

你可以把纯计算理解成：

> **不依赖外部世界，只依赖函数参数；
> 输入一样，输出永远一样；
> 不会修改任何外部状态。**

比如：

- 根据金额判断发什么券（core 层的匹配逻辑）
- 根据今天日期生成有效期（这其实也算“外部依赖”，但暂时可接受；严格来说依赖时间也是 IO）
- 把数据库记录拼成 dict（只要输入记录一样，输出永远一样）

# 🔧 我们来一起把你的代码分层拆干净（一步一步来）

你现在的 `preview_unissued_orders` 里，混合了三种事情：

### ① 获取数据（外部世界 IO）

```python
conn = get_db_connection()
records = get_unissued_vipmoney(conn)
coupons_map = load_config()["coupons"]
```

### ② 业务逻辑计算（纯处理）

```python
coupon = match_coupon_for_order(...)
date_range = _generate_date()
orders.append({...})
```

### ③ 错误输出（副作用）

```python
print("无法建立数据库连接")
```

# 🌱 下一步我们要做的事：**把 IO 和“纯逻辑”分开**

但不会一次性搞得很复杂，我们做一个小小的演化：

---

## ✔ 第一步：把 coupons_map 提出来一次性读

你现在每个循环都：

```python
coupon = match_coupon_for_order(..., load_config()["coupons"])
```

这等于是：

- 每条订单都去读一次硬盘
- 重复 IO
- 把业务逻辑污染了

我们先把它统一读出来：

```python
config = load_config()
coupons_map = config["coupons"]
```

把它放在循环前，这样循环内部只有“纯计算”。

---

## ✔ 第二步：把“数据加工”抽成一个纯函数（service 的核心技能）

比如我们做一个小函数：

```python
def build_preview_item(record, coupon, date_range):
    return {
        "trade_no": record["trade_no"],
        "old_code": record["old_code"],
        "vip_phone": record["vip_phone"],
        ...
    }
```

注意：
这个函数 **没有任何 IO，只有参数 → 返回值**，是“纯逻辑”。

未来测试它就非常容易。

---

## ✔ 第三步：服务函数就变成这样（逻辑清晰、边界明确）

示意如下——你不用直接写，我只是给你提前看看“目标形态”：

```python
def preview_unissued_orders():
    conn = get_db_connection()
    if not conn:
        return []

    records = get_unissued_vipmoney(conn)

    config = load_config()
    coupons_map = config["coupons"]

    orders = []
    for record in records:
        coupon = match_coupon_for_order(
            record["recharge_amount"],
            record["sub_brand_name"],
            coupons_map,
        )
        if not coupon:
            continue

        date_range = generate_date()
        orders.append(build_preview_item(record, coupon, date_range))

    return orders
```

看到了吗？

你的 service 层现在就像这样：

- IO 都放在外面
- 纯逻辑（匹配 + 拼装 dict）是函数
- service 是 orchestrator（协调者），负责把流程串起来

这就是架构成熟度提升的标志。
