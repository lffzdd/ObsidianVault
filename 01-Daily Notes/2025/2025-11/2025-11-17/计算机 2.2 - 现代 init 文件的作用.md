# `__init__.py`的作用

你这种感觉特别典型：

当你第一次知道 `python -m`、`pip install -e .`、虚拟环境这些“现代手段”之后，会产生一种错觉：

> “既然我已经能把项目根目录塞进 sys.path，那 **init**.py 好像没啥用了？”

其实 **这是一种“时代被技术赶上了”的错觉**。

要理解它，你得从 `__init__.py` 的历史演化说起，这样才能理解它“今天到底还值不值钱”。

下面我按时间线讲，让你彻底明白：

---

# 一、最早的世界（Python 1.x ~ Python 2.6）：

## **没有 `__init__.py` 就不是包 → 不能 import**

在最初的 Python 世界里，文件夹不等于包。

必须有：

```
mypkg/
    __init__.py
```

Python 才会认为你有一个包 `mypkg`，才允许：

```python
import mypkg.module
```

为什么？

因为 **Python 根本不知道“目录只是目录”还是“目录是一个可导入的包”**。

`__init__.py` 就是那个“显式声明”。

这叫 **Old-style package**。

在那个时代，`__init__.py` 是必须的。

没它：import 直接失败。

---

# 二、现代世界（Python 3.3 之后）：

## **引入 Namespace Package → “没有 **init**.py 的目录也能当包”**

当项目变大，生态变复杂，一个目录对应一个包变得太局限。

于是 PEP 420 引入了：

- **Implicit Namespace Package**：没有 `__init__.py` 的目录也能当包
- 同一个包可以分散在多个目录里
	（例如多个子项目扩展同一个包）

例如：

```
mypkg/        # no __init__.py
    moduleA.py

other_dir/
    mypkg/
        moduleB.py
```

两个目录共同组成一个包 **mypkg**。

这在大型框架（如 Google 的 internal monorepo）里超常用。

---

# 三、那么现在 `__init__.py` 为什么还存在？

它仍然有作用，而且作用非常关键，只不过它从“必需品”变成了“可选但重要的控制器”。

下面是它现在残存的真正价值（你会发现它不可能消失）：

---

# 3.1 区分 “普通目录” 和 “包目录”

现代 Python 没有强制要求必须有 `__init__.py` 才是包，

但是 **如果你有它，Python 就会明确把这个目录当成一个包，不会和其他目录合并。**

举例：

```
src/
    mypkg/
        __init__.py   # 有它，这个目录独立成为一个包
```

如果你想严格管理包边界（正常项目必须这样），就需要它。

否则：

- 有些工具（mypy、PyCharm）可能识别错
- 包扫描行为可能不一样
- “多个目录合成一个包”会以你意想不到的方式发生

---

# 3.2 它提供“包初始化代码”

例如：

```python
# mypkg/__init__.py
print("mypkg loaded")
from .utils import helper
VERSION = "1.2.3"
```

这能做：

- 导出公共 API
- 设置包级常量
- 执行初始化逻辑
- 让 `import mypkg` 有内容可用

如果没有它：

```python
import mypkg
mypkg.VERSION   # 会失败
```

因为 namespace package 不能包含模块代码。

---

# 3.3 它决定包是否是 namespace package

简单说：

```
没有 __init__.py → namespace package
有 __init__.py   → 传统包（普通包）
```

绝大多数工程都不希望自己变成 namespace package。

namespace package 的行为很“放飞自我”：

- 可以来自多个目录
- 顺序不可控
- 内部可能混入其他 team 的代码

因此：

> **稳定工程都必须使用 **init**.py 来锁定包结构。**

---

# 四、工程实战里的现代结论

## 在一般项目中：

****init**.py 仍然是必须的**
否则会出现各种导入问题、工具无法识别、IDE 补全缺失。

例如：

```
src/
    myproject/
        __init__.py   ← 必须有
        moduleA.py
        moduleB.py
```

因为：

- 你希望这个目录是一个独立的包
- 你不希望它和其他目录合并
- 你希望 IDE 正确识别
- 你希望可以写包级 API

---

## 哪些项目可以不要 `__init__.py`？

两类：

### 1. 极小型脚本，不是工程

随便写点工具脚本的文件夹，不需要。

### 2. 大型企业/框架使用“namespace package”

如：

- Google 的内部 monorepo
- parts of `google.*`
- 庞大插件系统（如 setuptools plugins）

这是高阶用法，对普通项目来说没必要。

---

# 五、总结一句“本质解释”（彻底讲透）

你之所以觉得 “有了 -m、PYTHONPATH、pip install -e 好像不需要 **init**.py”，

是因为：

> 这些机制是在“让根目录进入 sys.path”，
> 而不是在决定“目录是不是包”。

这两个概念完全不同。

**sys.path 决定“能不能找到包”**
****init**.py 决定“这个目录是不是一个独立的包，以及包的行为方式”**

你需要两者，同时存在。
