USB gadget 是 Linux 内核里让一台设备**反过来扮演 USB 外设(peripheral)**的子系统——平时你的电脑是 USB host,插上 U 盘/键盘是外设;而跑在树莓派 Zero、BeagleBone 这类板子上的 Linux,可以通过 gadget 框架让自己变成"U 盘""网卡""键盘"插到别的电脑上。自底向上看是这样一套结构:

**第一层:UDC 硬件(灰色)** UDC 全称 USB Device Controller,是 SoC 里专门用来"扮演外设"的物理控制器——和让 Linux 当 host 用的 EHCI/XHCI/OHCI 控制器是两块完全不同的硬件。手机、树莓派 Zero、各种嵌入式芯片里通常都集成了一个 UDC,常见型号有 Synopsys DesignWare(dwc2/dwc3)、Marvell 的 mv_udc 等。没有 UDC 的板子(比如普通台式机主板)是没法当 USB 外设的。

**第二层:UDC 驱动** 代码在 `drivers/usb/gadget/udc/` 下,是针对具体那块 UDC 芯片写的底层驱动,负责操作寄存器、管理端点(endpoint)、收发数据包,并通过 `usb_add_gadget_udc()` 把自己注册到上一层的核心框架里。

**第三层:Gadget 核心(`udc-core.c`)** 这是承上启下的抽象层,定义了 `struct usb_gadget`(代表这块控制器)、`struct usb_ep`(端点)、`struct usb_request`(一次传输请求)。它的作用是把具体硬件差异屏蔽掉,让上层的功能驱动不用关心自己跑在哪块芯片上。

**第四层:Function 驱动** 代码在 `drivers/usb/gadget/function/` 下,每个文件实现一种具体的 USB 设备类型(class):

- `f_mass_storage` → U 盘
- `f_ecm` / `f_rndis` → 网卡
- `f_acm` → 虚拟串口(很多开发板的调试口就是这个)
- `f_hid` → 键盘/鼠标模拟
- `f_fs`(FunctionFS)→ 把功能实现完全交给用户空间程序

**第五层:Composite 框架(`composite.c`)** 负责把一个或多个 function 拼装成一个完整的 USB 设备,处理标准 USB 请求(如 `GET_DESCRIPTOR`、`SET_CONFIGURATION`),生成设备描述符。这就是为什么一块板子可以同时表现成"U 盘 + 网卡 + 串口"的多功能复合设备。

**第六层:用户空间** 两种配置方式:

- **legacy 方式**(渐渐被淘汰):内核模块参数硬编码好组合,比如 `g_ether`、`g_mass_storage`、`g_serial`
- **configfs 方式**(现在的主流):在 `/sys/kernel/config/usb_gadget/` 下用 `mkdir` + 写文件的方式,动态、灵活地组合各种 function,可以用 `libusbgx` 这类库来操作
- **FunctionFS**:更进一步,让用户空间程序直接实现自定义的 USB 功能逻辑,相当于 device 端的 libusb

一个直观的应用场景:把树莓派 Zero 的 USB 口接到电脑上,电脑会识别出一个"U盘"或"网卡",这背后就是 gadget 框架在跑——UDC 硬件收发信号 → UDC 驱动翻译成通用请求 → gadget 核心分发 → f_mass_storage 按 U 盘协议应答 → composite 框架把它包装成一个完整的 USB 设备描述符 → 用户空间通过 configfs 提前配置好这一切。

另外补充一点:很多 SoC 的 USB 口是 **OTG(On-The-Go)** 口,既能当 host 也能当 device,具体走哪条路径由 ID pin 或 role switch 驱动在运行时决定,这时候 gadget 栈和 host 栈(EHCI/XHCI)是并存、按需切换的。

**先搞清楚一个最根本的规则:USB 通信里,谁能"先说话"**

USB 这套协议从设计上就规定死了:两边永远不对等,一方只能主动发起,另一方只能被动应答,不能反过来,也不能同时说。

打个比方:就像打电话,一方是"打电话的人"(可以主动拨号),另一方是"接电话的人"(只能等铃响了才能接)。你平时用的电脑,永远是"打电话的人"——这个角色在 USB 里叫 **host(主机)**。你插的 U 盘、键盘、鼠标,永远是"接电话的人"——这个角色叫 **device(设备)**。这不是谁软件写得好不好的问题,是硬件和协议层面就焊死的分工。

**那 gadget 到底是什么**

平时 Linux 也可以当"打电话的人"(比如你的电脑插 U 盘)。但有些 Linux 设备(树莓派 Zero、各种开发板)身上还装了一块特殊的硬件,能让它反过来变成"接电话的人"——插到别的电脑上时,自己伪装成一个 U 盘、一张网卡,或者一个键盘。**gadget 就是让 Linux 完成这个"角色反转"的整套本事(软件功能)。**

**再顺手解释两个高频词,后面会一直用到:**

- **驱动(driver)**:每种硬件长得都不一样,需要一个专门"认识"它的小程序去操作细节(发什么信号、读哪个寄存器)。这个小程序就叫驱动,可以理解成"说明书"或"翻译"。
- **内核(kernel)**:Linux 系统的核心部分,相当于总协调员,管理所有硬件、给各种程序分配资源。前面说的 gadget,整个都是活在内核里的东西。

**现在重新过一遍那六层,这次先说"这是干嘛的",再提名字:**

1. **最底层——硬件本身。** 芯片里专门有一小块电路,物理上能"假装成外设"去收发信号,这块电路就是前面提到的 UDC。注意它跟你插 U 盘时电脑里工作的那个"USB 主机控制器"完全是两块不同的硬件——一个只会当"打电话的人",一个只会当"接电话的人",谁也替代不了谁。
    
2. **第二层——驱动。** 有了这块专门的硬件,就需要软件去操作它,告诉它"现在开始收数据""把这段数据发出去"。这段软件就是 UDC 驱动,一个芯片型号对应一个驱动。
    
3. **第三层——内核里统一的"接待层"。** 市面上 UDC 芯片型号五花八门,如果上面每一层都要单独适配每种芯片,太麻烦。所以内核在驱动之上又搭了一层通用接口,不管底下是哪家的芯片,往上看都长一个样。这层就是所谓的 gadget 核心。
    
4. **第四层——决定"伪装成什么"。** 到这一层才轮到具体身份:我要伪装成 U 盘,还是网卡,还是键盘。每种身份对应一段代码,可以理解成"角色剧本",这些就叫 function 驱动。
    
5. **第五层——把多个身份拼在一起。** 如果想让设备插上去同时既是 U 盘又是网卡,就需要把几个"剧本"打包成一个对外统一呈现的完整 USB 设备,这个打包机制叫 composite 框架。
    
6. **最顶层——用户来配置。** 作为用户,你要决定到底启用哪几个身份,这一步发生在"用户空间"(也就是普通程序跑的地方,跟内核相对)。现在主流做法是用一套叫 configfs 的接口,像搭积木一样,写几条命令告诉系统"用这几个 function 拼成一个设备"。
    

串起来看,gadget 子系统干的事其实很简单:让一台本来只会当"打电话的人"的 Linux 设备,信号在硬件层被收发、在驱动层被翻译、在核心层被规范化、在 function 层被赋予身份、在 composite 层被打包成完整设备、最后由你在用户空间决定具体怎么配。
