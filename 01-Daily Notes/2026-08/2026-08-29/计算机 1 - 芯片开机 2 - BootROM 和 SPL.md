

简单来说，**BootROM（Boot Read-Only Memory，引导只读存储）就是芯片里的“通电第一道本能”**。

如果把香橙派的开机比作一场**接力赛**，BootROM 就是**第 0 棒**——负责点燃第一把火的发令枪。

---

### 一、 什么是 BootROM？

BootROM 是在芯片制造（光刻、封测）时，**直接固化在 SoC 芯片硅片内部的一小段微型程序（通常只有 16KB ~ 64KB）**。

它有两个最根本的物理特性：
1. **刻死在芯片里（只读，ROM）**：用户无法修改它，刷机刷不坏它，任何软件 Bug 也无法篡改或擦除它（俗称“物理防变砖”）。
2. **CPU 复位后的第一站**：板子通电或者按复位键瞬间，CPU 的程序指针（PC 寄存器）会被硬件强制指向 BootROM 的起始地址（例如 `0xFFFF0000` 或 `0x00000000`）。

---

### 二、 为什么必须要有 BootROM？（“先有鸡还是先有蛋”的死结）

在板子刚通电的瞬间，硬件处于一个极其原始的状态：
* **大内存（DDR4/LPDDR4 等）是死的**：内存控制器没配置时钟、电压和时序，几 GB 的外部大内存根本无法读写。
* **没有代码能跑**：CPU 只能在内存中执行代码，但内存又还没启动，代码从哪里来？

**芯片设计者的破局办法：**
在芯片内部塞进两个微型组件：
1. **片上 BootROM**（写好的固定引导程序，不可变）。
2. **片上 SRAM**（极小但通电即用的内部临时高速缓存，通常仅几十 KB）。

CPU 刚醒来时，不需要外部大内存，**直接在芯片内部运行 BootROM 代码**。

---

### 三、 BootROM 具体干了哪几件事？

BootROM 的逻辑非常简单、直接且严苛，主要按顺序执行以下任务：

```
                    [ 芯片通电 / 复位 ]
                            │
                            ▼
            【 1. 基础硬件配置 (开内部时钟/SRAM) 】
                            │
                            ▼
            【 2. 检查启动模式引脚 / 熔丝 (eFuse) 】
                            │
                            ▼
            【 3. 依次探测外设存储介质 】
               SPI Flash ──> eMMC ──> TF/SD卡
                            │
                    找到合法的引导签名？
                     ├── 是 ──> 【 4. 搬运 SPL 到片上 SRAM 并跳转运行 】 (成功启动)
                     └── 否 ──> 【 5. 进入 USB 救砖模式 (FEL/Maskrom) 】 (等待PC刷机)
```

#### 1. 基础硬件初始化
开启芯片内部最基础的时钟晶振，给片上 SRAM 通电。

#### 2. 读取启动顺序（Boot Sequence）
根据芯片引脚状态（或内部电子熔丝 eFuse），决定先去哪里找启动代码。
* 比如典型顺序：`SPI Nor Flash -> eMMC -> SD/TF 卡`。

#### 3. 扫描存储介质的固定物理偏移
BootROM 会用最原始、保守的标准时序去读存储设备。
芯片原厂（全志 Allwinner、瑞芯微 Rockchip 等）在设计芯片时，就**硬编码规定了读取位置**：
* **全志芯片（如 H6/H616）**：BootROM 会固定去 SD 卡的 **8KB 偏移处**（即第 16 个扇区）寻找带 `eGON` 签名的代码。
* **瑞芯微芯片（如 RK3588/RK3566）**：BootROM 会固定去 SD 卡的 **32KB 偏移处**（即第 64 个扇区）寻找特定的头部标记（`idbloader.img`）。

#### 4. 加载第 1 棒（SPL）到片上 SRAM
一旦找到合法的签名头，BootROM 会把紧随其后的一小段代码（即 **SPL，次级引导程序**，约 30KB~50KB）搬运到芯片内部的 **SRAM** 中。

#### 5. 交出控制权
校验通过后，CPU 跳转到 SRAM 中的 SPL 入口地址开始执行，**BootROM 光荣退休**，退出舞台。

---

### 四、 如果 SD 卡是空的，或者卡坏了，BootROM 会怎样？

这就是 BootROM 最神奇的地方——**USB 救砖 / 烧录模式**：

如果 BootROM 找遍了 SPI、eMMC、SD 卡，发现都没有合法的启动代码，它**不会死机**，而是执行最后的兜底逻辑：
* **把板子的 USB 接口模拟成一个从机（USB Device）**。
* **全志芯片** 会进入著名的 **FEL 模式**。
* **瑞芯微芯片** 会进入 **Maskrom 模式**。

此时你用一根 USB 线把香橙派插到电脑上，电脑端工具（如 `rkdeveloptool` 或 `sunxi-fel`）就可以**直接通过 USB 把代码推到芯片内部 SRAM 运行**，实现空板烧录系统或死机救砖。

---

### 五、 为什么 BootROM 不直接把 Linux 内核或者 U-Boot 启动起来？

你可能会问：既然 BootROM 能读卡，为什么不一步到位直接把整个系统拉起来？

主要有三点原因：
1. **硅片成本与面积限制**：ROM 占用宝贵的芯片硅片面积，不可能做得太大。
2. **无法修复 Bug**：ROM 刻死在硅片上，逻辑越复杂越容易出 Bug。一旦有 Bug，全球卖出的几千万颗芯片就全报废了，所以它必须保持**极简、绝对稳定**。
3. **不知道外部内存参数**：每一款板子用的 DDR 颗粒不同（有的板子配 4GB 三星 LPDDR4，有的配 8GB 海力士，时序电压完全不同）。芯片厂造芯片时不可能预知这颗芯片未来会被焊在哪块板子上，所以**点亮内存的重任必须留给下一棒（可由板厂自定义编写的 SPL）**。

---

### 总结

* **BootROM** 是：**出厂刻死在芯片里的“发电机钥匙”**。
* **它的核心使命**：利用仅有的几十 KB 内部 SRAM，把存储卡固定位置的 **SPL（初始化内存的程序）** 读进芯片并运行起来。
