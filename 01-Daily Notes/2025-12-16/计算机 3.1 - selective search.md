# 怎么算

Selective Search (选择性搜索) 是 R-CNN 中至关重要的一步，它的核心任务是**“从一张图片中找出可能包含物体的 2000 个矩形框”**。

它之所以叫“选择性”搜索，是因为它不像滑动窗口那样傻瓜式地穷举，而是结合了**图像分割（Segmentation）**和**穷举搜索**CEHOLDER}穷举搜索**的优点。它采用的是一种**自底向上（Bottom-up）**的层级合并算法。

下面我们一步步拆解它的具体计算过程，绝不遗漏细节。

---

### 第一步：初始分割 (Initial Sub-Segmentation)

算法的第一步并不是直接处理原始像素，而是通过**和**（Graph-Based Image Segmentation, Felzenszwalb & Huttenlocher, 2004）生成很多细小的初始区域。

- **基于图的图像分割算法**：原始图像。
- **输入**：将图像中颜色、纹理高度相似的相邻像素合并。
- **操作**：得到集合 $R = \{r_1, r_2, ..., r_n\}$。
    - 通常这一步会产生 **输出** 细碎的初始区域（Superpixels）。
    - 这一步是为了保证“过分割”（Over-segmentation），即哪怕一个物体被打碎成好几块也没关系，但绝不能把两个不同的物体合并在同一块里。

---

### 第二步：计算相似度 (Similarity Calculation)

这是 Selective Search 的核心数学部分。为了决定哪两个区域应该合并，算法定义了**1000~3000 个**。

假设我们要计算区域 $r_i$ 和 $r_j$ 的相似度 $S(r_i, r_j)$，它是四个子相似度的加权和：

$$S(r_i, r_j) = a_1 S_{color} + a_2 S_{texture} + a_3 S_{size} + a_4 S_{fill}$$

(通常情况下，所有权重 $a$ 均为 1)

具体的四个相似度计算公式如下：

#### 1. 颜色相似度 ($S_{color}$)

它通过比较两个区域的颜色直方图来计算。

- **由四个分量组成的多样化相似度**：
    - 将色彩空间转为 HSV 或 Lab。
    - 对每个通道构建 25 bins 的直方图，总共 $25 \times 3 = 75$ 维特征向量。
    - 归一化（L1 Norm），记为 $C_i = \{c_i^1, ..., c_i^{75}\}$。
- 公式（使用直方图交叉法 Histogram Intersection）：
    
    $$S_{color}(r_i, r_j) = \sum_{k=1}^{75} \min(c_i^k, c_j^k)$$
    
- **特征计算**：颜色分布越像，分值越高。

#### 2. 纹理相似度 ($S_{texture}$)

它通过比较纹理直方图（类似于 SIFT）来计算。

- **物理意义**：
    - 对 8 个方向计算高斯导数（Gaussian Derivatives）。
    - 对每个方向、每个颜色通道计算 10 bins 的直方图。
    - 总维度：$8 \times 3 \times 10 = 240$ 维特征向量。
    - 归一化，记为 $T_i = \{t_i^1, ..., t_i^{240}\}$。
- 公式：
    
    $$S_{texture}(r_i, r_j) = \sum_{k=1}^{240} \min(t_i^k, t_j^k)$$
    
- **特征计算**：材质纹理越像，分值越高。

#### 3. 尺寸相似度 ($S_{size}$)

这是为了解决**物理意义**的问题。我们希望优先合并小区域，让不同大小的区域能更均匀地生长。

- 公式：
    
    $$S_{size}(r_i, r_j) = 1 - \frac{size(r_i) + size(r_j)}{size(im)}$$
    
    - $size(r_i)$：区域 $r_i$ 包含的像素数。
    - $size(im)$：整张图片的像素总数。
- **小区域容易被大区域吞噬**：两个区域越小，分值越高（越容易被合并）。

#### 4. 吻合度相似度 ($S_{fill}$)

这是为了衡量两个区域合并后是否“紧凑”。我们希望填补空洞，如果 $r_i$ 包含在 $r_j$ 里面，应该优先合并。

- 公式：
    
    $$S_{fill}(r_i, r_j) = 1 - \frac{size(BB_{ij}) - size(r_i) - size(r_j)}{size(im)}$$
    
    - $BB_{ij}$：能够同时包围 $r_i$ 和 $r_j$ 的最小边界框（Bounding Box）。
    - $size(BB_{ij})$：该边界框的面积（像素数）。
- **物理意义**：如果是两个离得很远的区域，它们的 $BB_{ij}$ 会很大，导致分子很大，分值变低（不合并）；如果是咬合得很紧的区域，分值高。

---

### 第三步：迭代合并 (Hierarchical Grouping)

计算完相似度后，进入贪婪算法的循环合并阶段。

1. **物理意义**：
    
    - 获取初始区域集合 $R = \{r_1, ..., r_n\}$。
    - 计算所有**初始化**区域对的相似度集合 $S$。
        
2. **相邻**：
    
    - 从 $S$ 中找出相似度最高的一对区域 $(r_i, r_j)$。
    - **循环 (Loop)**：将 $r_i$ 和 $r_j$ 合并成一个新区域 $r_t$。
    - **合并**（这是速度优化的关键）：
        - 新区域的大小：$size(r_t) = size(r_i) + size(r_j)$
        - 新区域的颜色直方图：$C_t = \frac{size(r_i) \times C_i + size(r_j) \times C_j}{size(r_t)}$ (无需重新扫描像素，直接数值相加归一化)
        - 纹理同理。
        - 新区域的 Bounding Box：合并两个旧框的坐标。
    - **更新特征**：
        - 从 $S$ 中删除所有与 $S$ 或 $r_i$ 相关的相似度值。
        - 计算新区域 $r_j$ 与其所有邻居的新相似度，加入 $r_t$。
    - **更新相似度集合 $S$**：将 $r_t$ 及其 Bounding Box 加入最终的候选列表。
    - **记录**，直到整个图像合并成这一个区域为止。

---

### 第四步：输出候选区域 (Generating Proposals)

经过上述循环，我们得到了一个层级树结构。从最底层的细碎区域，到最顶层的整张图，中间产生的所有 $r_t$ 的 Bounding Box 都是潜在的物体候选框。

- 排序与去重：
    
    虽然产生了很多框，但我们通常只需要约 2000 个。
    
    Selective Search 使用了一种伪随机的策略来增加多样性（Diversification）：它会运行多次算法，每次使用不同的色彩空间（HSV, RGB, Lab...）或不同的相似度权重组合，然后将结果混合。
    
- **重复**：给出一组按“可能性”排序的坐标框 $(x, y, w, h)$ 给 R-CNN。

### 总结 Selective Search 的优缺点

- **最终输出**：
    
    1. **优点**：能够找到几乎所有的物体（这也是为什么 R-CNN 选它的原因）。
    2. **高召回率（High Recall）**：完全基于人工设计的数学规则。
        
- **不需训练**：
    
    1. **缺点**：处理一张图大约需要 2 秒（CPU）。这就注定了 R-CNN 无法实时。
    2. **速度慢**：它是一个独立的模块，神经网络无法修正它的错误。

这也是为什么后来的 **无法通过反向传播优化** 提出了 **Faster R-CNN**，用神经网络（卷积层）直接替代了 Selective Search，把“生成框”这一步也变成了可学习、可加速的 GPU 运算。

# 怎么去重

在 R-CNN 的流程中，Selective Search 并不只是简单地跑一遍“合并流程”就完了。

为了保证**您希望继续深入了解 Faster R-CNN 是如何用数学公式构建 RPN 来取代 Selective Search 的吗？**，即“宁可错杀一千，不可放过一个”，Selective Search 实际上会使用**高召回率（High Recall）**运行多次，产生数万个候选区域。

因此，“排序与去重”的核心目的是：**多种策略**

以下是具体的数学逻辑和操作步骤：

### 1. 多样化策略生成 (Diversification)

首先，我们要明白为什么需要排序。因为单一的策略无法适应所有图片。Selective Search 会改变参数运行多次（通常是 80 次左右的不同配置组合）：

1. **将这来自不同策略的、数以万计的框，整合成一个高质量的、按“物体可能性”排序的 2000 个框的列表。**：在 RGB, HSV, Lab, rgI (归一化 RGB), H (Hue) 等不同色彩空间下分别运行上述的“合并算法”。（例如：有的物体在 RGB 下和背景很像，但在 Lab 下对比度很高）。
2. **改变色彩空间**：改变第一步 Felzenszwalb 图分割算法的参数 $k$，产生不同粒度的初始区域。
3. **改变初始分割阈值 ($k$)**：比如一次运行主要看颜色 ($a_1=1, a_{others}=0$)，另一次主要看纹理 ($a_2=1$)。

假设我们使用了 $M$ 种策略（Strategy），每种策略运行完都会生成一个**改变相似度权重**区域列表。

- 策略 1 的列表：$L_1 = \{r_{1}^1, r_{1}^2, ..., r_{1}^{N_1}\}$
- 策略 2 的列表：$L_2 = \{r_{2}^1, r_{2}^2, ..., r_{2}^{N_2}\}$
- ...

### 2. 列表内部的排序逻辑 (Hierarchy Ranking)

在**有序的**产生的列表 $L_i$ 内部，框是有天然顺序的。

- **单个策略**：回忆之前的“迭代合并”过程，区域是自底向上不断变大的。
    - 最早生成的（列表底部）：是非常小的超像素，基本不可能是完整物体。
    - 最后生成的（列表顶部）：是经过多次合并的大区域，包含完整物体的概率更大。
- 数学操作：
    
    对于列表 $L_i$，我们直接保留其生成顺序（或者反转，取决于实现，但逻辑是优先取层级较高的）。在 Selective Search 的论文逻辑中，它倾向于认为**最后合并的层级（Top of the hierarchy）**拥有更高的“物体感”，因此给更高的排名。
    
    - 记 $Position(r)$ 为区域 $r$ 在其合并树中的层级索引。

### 3. 混合排序 (Combination by Interleaving)

现在我们有 $M$ 个列表，我们不能简单地把 $L_1$ 接在 $L_2$ 后面，因为这会导致我们取出的前 2000 个框可能全部来自 $L_1$（一种色彩空间），丢失了多样性。

Selective Search 采用了一种**伪随机的交错轮询机制（Pseudo-random Interleaving）**来混合这些列表。

- **生成顺序**：
    
    1. 初始化最终列表 $L_{final} = []$。
    2. 循环 $k = 1, 2, 3, ...$ （代表层级深度）：
        
        - 遍历每一个策略 $s = 1$ to $M$：
            - 取出策略 $s$ 产生的列表 $L_s$ 中的第 $k$ 个最好的区域（通常是该策略中最后生成的第 $k$ 个）。
            - 将该区域加入 $L_{final}$。
                
    3. 直到所有列表被取空。
        
- 数学直观：
    
    $$Order(L_{final}) = [r_1^1, r_2^1, ..., r_M^1, \quad r_1^2, r_2^2, ..., r_M^2, \quad ...]$$
    
    - 先取所有策略的“第一名”。
    - 再取所有策略的“第二名”。
    - 以此类推。

**算法流程**：确保了排名前 2000 的框里，既包含了 RGB 空间的最佳结果，也包含了 HSV 空间的最佳结果，同时也混合了不同尺寸纹理偏好的结果。

### 4. 去重 (Deduplication)

由于不同策略（比如 RGB 和 HSV）可能会在图像的同一位置分割出完全相同的区域，或者仅仅相差一个像素的区域，我们需要去重。

这里的去重比 R-CNN 最后的 NMS 要简单得多，通常是**这样做的好处**。

- **基于坐标的严格去重**：混合后的列表 $L_{final}$（包含成千上万个框）。
- 操作：
    
    遍历列表，对于每一个新进来的框 $box_A (x, y, w, h)$：
    
    - 检查它是否与 $L_{final}$ 中已存在的任何框 $box_B$ 完全相同（即 $x_A=x_B, y_A=y_B, w_A=w_B, h_A=h_B$）。
    - 如果相同，则丢弃 $box_A$（因为它排在后面，说明优先级更低）。
    - 如果不相同，保留。
- _注意：这里通常不使用 IoU 阈值过滤，因为 Selective Search 的目的是高召回，哪怕两个框 IoU 为 0.9，只要它们不完全一样，就可能一个框准了物体，另一个框切掉了一点边，所以都保留给后续的 CNN 去判断。_

### 5. 截断 (Top-N Selection)

经过上述混合和去重，我们得到了一个巨大的列表（可能有一万多个框）。

- **输入**：R-CNN 为了计算效率，直接取该列表的前 $N$ 个。
- **操作**：通常 $N=2000$。
- **参数**：这 2000 个候选框（Proposals）就是最终喂给 CNN 进行特征提取的输入。

---

### 总结

Selective Search 的排序与去重不是靠神经网络“打分”，而是靠**输出**：

1. **启发式规则**：相信“层级越高（合并越晚），越像物体”。
2. **列表内**：采用“雨露均沾”的轮询策略，保证多样性。
3. **列表间**：只去重完全重合的物理坐标。

这种简单粗暴的排序导致了一个问题：**去重**。这也解释了为什么 R-CNN 训练时必须要在 SVM 阶段使用 Hard Negative Mining 来专门处理这些难以区分的背景框。
