## 一、先把问题缩到“最小计算单元”

目标检测最开始并不是在“整张图”上算，而是把问题拆成：

**给定一个固定大小的小窗口，判断：这个窗口里是不是目标？**

所以我们只看一个窗口，比如：

64×128 像素的一块图像（这是经典的行人检测尺寸）。

## 二、第一步：从像素到“特征”（这是最关键的计算）

### 1️⃣ 为什么不能直接用像素？

早期研究者很早就意识到一件事：

- 像素值本身对“是不是人 / 脸 / 车”几乎没有稳定意义。
- 光照一变，像素全变；颜色一变，像素全变。
- **但形状结构往往不变。**

所以必须把 **像素 $\rightarrow$ 更稳定的中间表示**。

### 2️⃣ 以 HOG 为例，具体怎么算？

我们一步一步来，不跳。

#### Step 1：计算梯度（本质是边缘）

对窗口中每个像素，计算水平和垂直方向的差分：

$$G_x = I(x+1, y) - I(x-1, y)$$

$$G_y = I(x, y+1) - I(x, y-1)$$

得到两个关键数值：

- **梯度方向（边缘朝向）：**
    
    $$\theta = \arctan\left(\frac{G_y}{G_x}\right)$$
    
- **梯度强度（边缘有多“明显”）：**
    
    $$|G| = \sqrt{G_x^2 + G_y^2}$$

#### Step 2：把窗口切成很多小 cell

比如：

- 每个 cell 是 **8×8** 像素。
- 一个 64×128 的窗口 $\rightarrow$ $8 \times 16 = 128$ 个 cell。

#### Step 3：在每个 cell 里做“方向统计”

在一个 cell 内：

- 把 **0°–180°** 分成 9 个方向桶（bins）。
- 每个像素根据它的梯度方向 $\theta$ 投票到对应方向，权重是梯度强度 $|G|$。
- 于是你得到一个 9 维向量：
    
    $$h = (h_1, h_2, \dots, h_9)$$

这一步非常重要，它做了一件事：**彻底丢掉了“精确位置”，只保留“局部形状结构”。**

#### Step 4：Block 归一化（对抗光照）

为了避免“整体变亮/变暗”影响结果：

- 把相邻几个 cell 拼成一个 block。
- 对 block 内的向量做 L2 归一化：
    
    $$h' = \frac{h}{\sqrt{\|h\|_2^2 + \epsilon}}$$

📌 **到这里，一个窗口被变成了一个长向量 $x$（通常是几千维）。**

## 三、第二步：真正的“判断”是怎么算的？

现在我们终于进入你关心的核心：**模型是怎么给出“是 / 不是”的？**

### 1️⃣ 用最简单、最可控的模型：线性分类器

以 线性 SVM 为例（这是早期最常见的方案）：

你有：

- 特征向量 $x \in \mathbb{R}^d$
- 学到的权重 $w \in \mathbb{R}^d$
- 偏置 $b$

计算只有一句话：

$$s = w^\top x + b$$

- 如果 $s > 0$：认为是目标。
- 如果 $s \le 0$：不是目标。

📌 **没有概率，没有 fancy 结构，就是一个点积。**

### 2️⃣ 这个点积在“语义上”是什么意思？

这是很多人忽略、但极其重要的一点。

$$w^\top x = \sum_{i} w_i x_i$$

你可以把它理解成：

- 某个方向的边缘 $\rightarrow$ 对应权重 $w_i$ 大 $\rightarrow$ **加分**
- 某个方向的边缘 $\rightarrow$ 对应权重 $w_i$ 为负 $\rightarrow$ **扣分**

本质是：**“这个窗口里的边缘分布，像不像我见过的目标的平均形状？”**

### 3️⃣ 所以“检测”就是在算什么？

现在可以一句话说清楚了：

对每一个窗口，算一次 “模板和当前窗口的相似度”。

线性 SVM 在这里几乎等价于：**一个可学习的形状模板，在整张图上做滑动匹配。**

## 四、第三步：整张图是怎么算的？

现在我们把窗口放回整张图。对一张图，实际做的是：

Python

```
for scale in image_pyramid:            # 解决物体大小不同
    for (x, y) in sliding_window_positions:
        crop window
        compute HOG features           # 算特征 x
        score = w^T * x + b            # 算分数 s
        if score > threshold:
            record detection
```

📌 **是的，就是这么“笨”且暴力。**

## 五、那多个窗口重叠怎么办？

这一步也是实打实的计算。即 **非极大值抑制（NMS）**：

1. 按 score 从高到低排序。
2. 取最高的窗口。
3. 删除与它 IoU 大于阈值的其他窗口。
4. 重复。

IoU 的计算本身就是：

$$\text{IoU} = \frac{\text{Area of Intersection}}{\text{Area of Union}}$$

## 六、现在你应该真正“懂”的核心算式

如果我把早期目标检测压缩成三行数学，就是：

1. **特征提取（结构统计）：**
    
    $$x = \text{HOG}(\text{window})$$
    
2. **线性打分（模板匹配）：**
    
    $$s = w^\top x + b$$
    
3. **空间去重（几何规则）：**
    
    $$\text{NMS}(s, \text{boxes})$$

## 七、为什么这种方法在历史上“必然出现”？

因为在那个时代：

- 深度网络不可行（算力不够，梯度消失）。
- 非线性模型太慢。
- 全局搜索太贵。

而这个方案：

- 每一步都可解释。
- 每一步都可拆分优化。
- 每一步都能在 CPU 上跑。
