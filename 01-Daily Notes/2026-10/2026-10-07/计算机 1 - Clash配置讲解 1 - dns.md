# `enable`

Clash 的 DNS 配置虽然看起来很复杂，但它的核心任务只有两个：

1. 快：访问国内网站时，秒开网页。
2. 准：访问国外网站时，拿到正确的 IP，不被污染，也不泄露隐私。

## 第一步：最基础的开关 `enable`

在 Clash 的 DNS 模块里，最开始的一行通常是：

```yaml
dns:
  enable: true
```

- 它是干嘛的：这是 Clash 内置 DNS 服务器的总开关。
- 为什么要设为 `true`：如果把它设为 `false`（或者不写），Clash 就不会接管你电脑的域名解析请求，而是直接让你的电脑系统（或者路由器）去向运营商（如电信、联机、移动）申请解析。这样一来，Clash 的很多高级分流功能和防泄露功能就无法生效了。所以，必须开启。

# `enhanced-mode`

那我们这就来聊聊这个最神奇的参数：`enhanced-mode`（增强模式）。

在 Clash 里，这个参数主要有两个选择：`fake-ip` 和 `redir-host`。现在主流的配置基本都在用 `fake-ip`。

我们先用一句话总结它：`fake-ip` 就是管家给你发的一张“假传票”（虚拟 IP）。

## 🧠 传统的流程（没有 fake-ip 时）

平时上网时，你的浏览器必须先知道网站的真实 IP 地址，才能发送网页请求。

1. 浏览器问：“`google.com` 的 IP 是多少？”
2. Clash 去问国外的 DNS 服务器。
3. 国外 DNS 慢吞吞地返回真实 IP。
4. Clash 把真实 IP 给浏览器。
5. 浏览器拿到 IP，再通过 Clash 发起连接。

- 缺点：中间等 DNS 结果的时间很长，网页打开就慢。

---

## ⚡ 开启 `fake-ip` 后的“神仙操作”

当设置了 `enhanced-mode: fake-ip` 之后，整个过程变成了极速闪送：

1. 浏览器问：“`google.com` 的 IP 是多少？”
2. Clash 连看都不看，一秒钟都不耽误，直接随手分配一个假的 IP（比如 `198.18.0.5`）扔给浏览器，并自己在小本本上记下：“`198.18.0.5` 代表 `google.com`”。
3. 浏览器拿到这个假 IP 很高兴，立刻对 `198.18.0.5` 发起了网页请求。
4. 这个请求再次经过 Clash 时，Clash 翻开小本本一看：“哦，你是想找 `google.com` 啊！”然后 Clash 直接把 `google.com` 这个域名打包，丢给远端的代理服务器去处理。

## 🎁 这样做有什么好处？

1. 超级快：浏览器不用等 DNS 解析结果了，直接本地秒回应。
2. 防泄露（最重要）：你的电脑根本没有在本地网络查询国外域名的真 IP，所有的查询都是代理服务器在国外帮你做的。国内的运营商完全不知道你访问了什么，彻底杜绝了本地 DNS 泄露！

---

## 先回答你最核心的问题

**不用 fake-ip 时，DNS 查询不一定就是“本机直接去找”，也不一定就是“代理服务器去找”。这取决于 Clash 的 DNS 配置和规则。**

也就是说：

- 可能是本机向本地运营商 DNS 查
- 可能是 Clash 自己去向某个 DNS 服务器查
- 可能是 Clash 把 DNS 查询也走代理，让代理服务器去查
- 也可能是浏览器自己先查了，Clash 根本没参与

所以不能简单说“不用 fake-ip 就是本机去找”。

## 关键区别：谁在什么时候做 DNS 解析

### fake-ip 模式

浏览器问 Clash：`google.com` 的 IP 是多少？

Clash 直接回：`198.18.0.5`，不查真实 IP。

等浏览器真的向 `198.18.0.5` 发请求时，Clash 才根据记录知道你要访问 `google.com`，然后把**域名**交给代理服务器。

代理服务器在国外，由它去真正解析 `google.com`。

**DNS 解析发生在代理服务器那边。**

### 非 fake-ip 模式，比如 redir-host

浏览器问 Clash：`google.com` 的 IP 是多少？

这时候 Clash 不能随便给假 IP，它必须给出一个**真实可用的 IP**。那这个真实 IP 从哪来？

就看 Clash 的 DNS 配置：

- 如果 Clash 配置了 `nameserver: 223.5.5.5`，那 Clash 会向阿里 DNS 查。
- 如果配置了 `nameserver: https://dns.google/dns-query`，那 Clash 会向 Google DNS 查。
- 如果配置了 `proxy-server-nameserver` 或让 DNS 走代理，那查询可能通过代理出去。
- 如果 Clash 没接管 DNS，浏览器直接用系统 DNS，那就是本机向运营商 DNS 查。

所以**非 fake-ip 时，DNS 查询路径取决于配置，不是固定的。**

## 你问的“本机去找，是通过 Clash 去找，还是不需要”

分三种情况：

### 情况 1：浏览器/系统直接用系统 DNS

Clash 没接管 DNS，或者你访问的域名没进 Clash。

流程：

1. 浏览器问系统：`google.com` 的 IP 是多少？
2. 系统向本地运营商 DNS 查。
3. 运营商 DNS 返回结果。

这时 Clash 完全没参与 DNS。

**问题：** 本地运营商能看到你查了 `google.com`，可能被污染，也可能泄露。

### 情况 2：Clash 接管 DNS，但 Clash 自己去查

浏览器问 Clash，Clash 向配置的 DNS 服务器查。

比如 Clash 配置：

```yaml
dns:
  enable: true
  nameserver:
    - 223.5.5.5
    - 119.29.29.29
```

那 Clash 会向这些国内 DNS 查。

**问题：** 如果查的是国外域名，国内 DNS 可能返回污染结果，而且运营商仍然能看到查询。

### 情况 3：Clash 接管 DNS，并且 DNS 查询走代理

Clash 配置让 DNS 查询通过代理出去，或者用 `fake-ip` 配合代理。

那真正查 `google.com` 的是国外代理服务器。

**优点：** 本地运营商看不到你查了什么，结果也不容易被污染。

### 所以你的理解哪里对，哪里需要修正

你说：

> 如果不用 fake ip，找 dns 服务器这个过程就不是代理服务器去找，而是本机去找

**不完全对。** 不用 fake-ip 时，DNS 查询可能由本机、Clash、或代理服务器发起，取决于配置。

你说：

> 本机去找到的可能有问题？

**对。** 如果本机直接向国内运营商 DNS 查国外域名，可能被污染、被记录、被劫持。

你说：

> 本机去找，是通过 clash 去找，还是不需要

**都有可能：**

- 不需要 Clash：浏览器直接用系统 DNS。
- 通过 Clash：Clash 接管 DNS，向配置的 DNS 服务器查。
- 通过 Clash 再走代理：Clash 把 DNS 查询也交给代理服务器。

### 为什么 fake-ip 能“防泄露”

因为 fake-ip 模式下，浏览器拿到的是假 IP，它根本不会去查 `google.com` 的真实 IP。

真正的域名解析发生在代理服务器那边。

所以本地运营商看不到：

- 你查了 `google.com`
- `google.com` 的真实 IP 是多少

它只能看到：

- 你的浏览器在跟 `198.18.0.5` 通信
- 但这个地址是假的，没有意义

### 一张表总结

| 模式 | 谁回答浏览器 | 谁真正解析域名 | 本地运营商能看到吗 |
|---|---|---|---|
| 系统 DNS，Clash 不接管 | 系统 DNS | 本地/运营商 DNS | 能看到你查了什么 |
| Clash 接管，redir-host | Clash | Clash 向配置的 DNS 查 | 取决于 DNS 服务器位置 |
| Clash 接管，DNS 走代理 | Clash | 代理服务器 | 看不到真实查询 |
| fake-ip | Clash 给假 IP | 代理服务器 | 看不到真实查询 |

### 一句话总结

**不用 fake-ip 时，DNS 查询不一定由本机直接做，也不一定由代理做，而是取决于 Clash 的 DNS 配置。只有配置成 DNS 也走代理，才能真正防泄露；否则本机或国内 DNS 仍然可能暴露你访问的域名。fake-ip 的优势是它从流程上就让浏览器不去查真实 IP，把真实解析交给代理服务器。**


# `nameserver`

你的理解方向非常对，但细节上有一点点小偏差。我们把 `Rule`（规则模式）和 `Global`（全局模式）拆开，用最通俗的话来理清 `fake-ip` 在这里的角色。

最核心的一句话：在 `fake-ip` 模式下，无论走直连还是代理，浏览器都只拿到了假 IP。真正去联系 DNS 服务器的，只有 Clash 自己。

以下是它在不同模式和规则下的真实运作流程：

## 1. 如果你在 Clash 里开了 `Global`（全局代理）

此时你的分流规则完全失效，所有流量无条件走代理。

- 过程： 浏览器向 Clash 要 IP $\rightarrow$ Clash 直接给假 IP $\rightarrow$ 浏览器发包 $\rightarrow$ Clash 把包直接丢给远端代理服务器。
- 结果： 整个过程，Clash 完全不需要动用本地的 `nameserver`。域名百分之百由国外的代理服务器去解析。

---

## 2. 如果你在 Clash 里开了 `Rule`（规则分流模式）

这是我们最常用的模式，也是最容易让人晕的地方。这时候会分两种情况：

## 情况 A：域名命中了“域名规则”（比如 `DOMAIN, google.com`）

如果 Clash 看到规则写着 `google.com` 应该走代理（PROXY）：

- 过程： Clash 塞给浏览器一个假 IP $\rightarrow$ 浏览器发包给 Clash $\rightarrow$ Clash 看到规则说这个域名走代理，于是直接把域名和包一起打包发给国外代理服务器。
- 结果： 在这种情况下，Clash 依然不需要动用本地的 `nameserver`，域名由远端代理服务器解析。

## 情况 B：域名没有命中域名规则，触发了“IP 规则”（比如 `GEOIP, CN`）

如果一个域名（比如 `baidu.com` 或者某些没被规则收录的国外冷门域名）没有被前面的域名规则拦截，撞到了底部的 IP 分流规则：

- 过程： Clash 必须知道这个域名的真实 IP 到底是不是中国的。
- 动作： 这时候，Clash 就会在后台偷偷动用本地的 `nameserver` 去查这个域名的真实 IP。
- 判断：
    
    - 如果 `nameserver` 返回的是国内 IP（比如百度）：Clash 判定走直连（DIRECT），在本地用这个真实 IP 帮你连上百度。
    - 如果 `nameserver` 返回的是国外 IP：Clash 判定走代理（PROXY），把包发给国外代理服务器，由代理服务器重新在国外解析并连接。
    

---

## 🎯 完美的总结

你的疑问是：“配置的本地域名去走本地 DNS 服务器解析而不用走代理服务器？”

- 正确的表述是：
    
    - 只有当规则需要判断 IP 归属地，或者最终决定走直连（DIRECT）时，Clash 才会去调用你配置的本地 `nameserver`。
    - 如果规则直接能断定这个域名要走代理，Clash 就会把解析工作完全交给远端代理服务器，本地 DNS 连看戏的机会都没有。
    

这就是为什么如果本地 `nameserver` 只有国内 DNS，碰到情况 B 里的“国外冷门域名”时，国内 DNS 就会返回一个假的大陆 IP（污染），导致 Clash 误以为它是国内网站而选择“直连”，最终让你打不开网页。

现在这个逻辑闭环是不是彻底清晰了？如果搞懂了，接下来我们就可以直接看如何配置 `nameserver`，才能在情况 B 发生时，既不让国内网站减速，又不让国外网站被污染。

#

把这最后四个参数搞定，你的 Clash DNS 知识树就彻底圆满了！这四个参数属于**“保障类”和“微调类”配置**，用来规定假 IP 的范围以及 Clash 该去哪里抄近路。

我们依然一个一个来拆解：

---

## 1. `fake-ip-range: 198.18.0.1/16`

- 它是干嘛的：规定“假 IP”的水池范围。
- 通俗解释：前面我们说 Clash 会随手发假 IP 忽悠浏览器，但它也不能瞎发。这个参数就是告诉 Clash：“你发假 IP 的时候，只能在 `198.18.0.1` 到 `198.18.255.254` 之间挑地址发 [2]。”
- 为什么要用这个范围：因为在国际网络标准中，`198.18.x.x` 这段 IP 被专门规定用于“网络基准测试和虚拟设备”。它在公网上是不存在的。这样就能确保 Clash 发的假 IP，绝对不会和互联网上任何一个真实的网站 IP 撞车。

---

## 2. `prefer-h3: false`

- 它是干嘛的：是否优先使用 HTTP/3 协议去查询 DNS。
- 通俗解释：现在的加密 DNS（DoH）很多都升级支持了更新、更快的 HTTP/3（基于 UDP 的 QUIC 技术）。如果设为 `true`，Clash 就会优先尝试用这种最新技术去查 DNS。
- 为什么通常设为 `false`：因为很多国内运营商对 UDP 流量有严格的限制或恶意的限制，导致最新的 HTTP/3 反而经常握手失败、断连，甚至速度变得极慢。所以为了绝对的稳定性，普遍推荐设为 `false`，老老实实用成熟、稳定的 HTTP/2 即可。

---

## 3. `use-hosts: true`

- 它是干嘛的：是否允许使用 Clash 配置文件里自己写的 `hosts` 规则。
- 通俗解释：在 Clash 配置文件的其他地方，可以自定义一个叫 `hosts:` 的小本本。比如你可以写死：`baidu.com: 127.0.0.1`。
- 为什么要开启：开启后，如果浏览器访问百度，Clash 会优先去翻你自己在配置文件里写的 hosts 小本本。如果翻到了，就直接按你写的 IP 返回，不再去走任何 DNS 查询。这属于高效的“开小兵通道”。

---

## 4. `use-system-hosts: true`

- 它是干嘛的：是否允许 Clash 去读取你“电脑系统自带的 hosts 文件”。
- 通俗解释：你的 Windows 或 Mac 电脑系统本身就自带一个叫 `hosts` 的文件（比如开发人员经常去修改它来做本地测试）。
- 为什么要开启：设为 `true` 后，Clash 也会去尊重你电脑系统本来的 host 设置。如果你在电脑系统里手动屏蔽了某个广告网站，或者指定了某个本地服务器的 IP，Clash 就会直接沿用，不会和你的系统设置打架。

---

## 🏁 终极大总结

恭喜你！到这里，你已经把 Clash 整个 DNS 树状图里面的所有核心和零碎参数全部吃透了。我们把它们放在一起，就是一整套天衣无缝的防御与加速体系：

1. `enable` / `fake-ip` / `range`：建立一个安全隔离的虚拟 IP 水池，秒回浏览器，断绝外界污染。
2. `default-nameserver`：保障 Clash 能够顺利找到国外代理节点。
3. `nameserver` / `fallback`：让国内和国外的域名在大后方进行安全的赛跑分流。
4. `filter` / `hosts` / `system-hosts`：大后方的白名单与近路，确保局域网、游戏和本地系统完美兼容。
