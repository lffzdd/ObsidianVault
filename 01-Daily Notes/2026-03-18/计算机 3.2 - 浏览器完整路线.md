# 🧠 总览（先给你一眼全图）

```text
用户输入 URL
   ↓
浏览器进程（UI + 调度）
   ↓
创建/选择 渲染进程
   ↓
浏览器进程发起网络请求
   ↓
收到 HTML 数据（流式）
   ↓ IPC
渲染进程（loader）
   ↓
HTML 解析（parser）
   ↓
构建 DOM
   ↓
遇到 <script> → 执行 JS
   ↓
样式计算（CSS）
   ↓
布局（layout）
   ↓
绘制（paint）
   ↓
提交给 GPU
   ↓
屏幕显示（首屏）
```

接下来我们一段一段拆。

# 一、用户输入 URL（入口点）

你在地址栏输入：

```text
https://example.com
```

## 实际发生：

### 1️⃣ 操作系统 → 浏览器进程

```text
OS → Browser(UI thread):
    keydown / input / enter
```

### 2️⃣ 浏览器 UI 处理

```cpp
void onAddressBarEnter(string url) {
    browserMessageLoop.post({
        type: OPEN_URL,
        url: url
    });
}
```

👉 **第一个关键点：任务来源不是 renderer，是 UI**

# 二、浏览器进程处理导航

```cpp
case OPEN_URL:
    renderer = getOrCreateRenderer(tabId);
    network.startRequest(url, renderer);
```

## 这里做了三件事：

### 1️⃣ 选择或创建渲染进程

```text
如果这个 tab 没 renderer → 创建一个新进程
```

### 2️⃣ 建立 IPC 通道

```text
browser <-> renderer
```

### 3️⃣ 发起网络请求（重要）

👉 注意：

> **renderer 不直接发 HTTP 请求**

# 三、网络请求（浏览器进程 / network service）

```cpp
networkThread.start(url);
```

## 网络线程在干嘛？

```cpp
send TCP
send HTTP
wait response
receive bytes...
```

## 关键：是“流式”的

```text
不是等整个 HTML 下载完才开始
而是一边收，一边往 renderer 发
```

# 四、HTML 数据进入渲染进程

浏览器进程：

```cpp
sendIPC(renderer, {
    type: HTML_CHUNK,
    bytes: "<html>..."
});
```

# 五、渲染进程：loader 接管

```cpp
void onHTMLChunk(bytes) {
    buffer.append(bytes);

    postTask(PARSE_HTML);
}
```

👉 **这里就是你问的：谁塞任务？**

👉 答案：**DocumentLoader**

# 六、HTML 解析（parser）

```cpp
void parse() {
    while (buffer.hasToken()) {
        token = nextToken();

        if (token == <div>) {
            DOM.addNode(div);
        }

        if (token == <script>) {
            pauseParsing();

            postTask(EXECUTE_SCRIPT);

            return;
        }
    }
}
```

## 🔥 关键点

👉 HTML 解析不是一口气完成的  
👉 是：

```text
解析一点 → 停 → 执行 JS → 再继续
```

# 七、执行 JS（主线程）

```cpp
executeTask(EXECUTE_SCRIPT)
```

进入 JS 引擎：

```cpp
jsEngine.execute(script)
```

## 如果 JS 里有：

```js
setTimeout(...)
fetch(...)
```

就会：

```text
renderer → IPC → browser process
```

（你前面已经搞懂这块了）

# 八、继续解析 HTML

JS 执行完：

```cpp
parser.resume();
```

继续：

```text
HTML → DOM
```

# 九、CSS 解析 + 样式计算

当遇到：

```html
<link rel="stylesheet">
```

## 流程：

```text
renderer → browser → network → renderer
```

CSS 下载回来后：

```cpp
styleEngine.computeStyle(DOM)
```

## 结果：

```text
DOM + CSS → Render Tree
```

# 十、布局（Layout）

```cpp
layoutEngine.compute(RenderTree);
```

👉 计算：

```text
每个元素的位置、大小
```

# 十一、绘制（Paint）

```cpp
paintEngine.draw(RenderTree);
```

生成：

```text
绘制指令（不是像素）
```

# 十二、提交给 GPU

```cpp
sendToGPU(paintCommands);
```

# 十三、屏幕显示（首屏）

GPU：

```text
合成图层 → 输出像素 → 显示
```

# 🧠 你刚才的两个疑问现在可以彻底闭环

## ❓1：输入是谁处理的？

👉 **浏览器进程 UI 模块（不是 renderer）**

## ❓2：HTML 解析任务是谁丢进队列的？

👉 **renderer 内的 DocumentLoader / Parser**

# 🔥 最关键的认知升级（你现在必须掌握）

你现在可以这样总结整个系统：

## 🧵 主线程不是唯一循环

而是：

```text
Browser 进程：一个大循环（UI + IPC + network）
Renderer 进程：一个大循环（IPC + loader + parser + scheduler）
JS：只是 renderer 里的一个子循环
```

## 🧠 谁产生任务？

|阶段|生产者|
|---|-|
|输入|浏览器 UI|
|网络|network 线程|
|HTML 解析|loader|
|script|parser|
|Promise|JS 引擎|
|定时器|browser timer|

# 🔥 最后一锤（你现在的水平该记住这句）

> **浏览器不是“一个 event loop”，而是“多进程 + 多线程 + 多消息循环 + 多任务生产者协作的系统”。**
