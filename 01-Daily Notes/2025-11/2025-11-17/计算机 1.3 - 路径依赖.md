好，那我们进入下一关 👣：
**从“想好了结构” → “代码里真的长出三层来”。**

这一步的目标非常具体：

> 让你的项目在物理结构上也变成：`app`（入口） → `core`（业务） → `base`（底层），
> 并且还能正常跑起来。

我会拆成三个小任务，你一步一步来做。

---

## 第一步：真的把文件挪进三层目录

按你刚才定的结构，把文件“物理位置”先整理出来（名字可以先用你提的那套）：

```text
project/
  app/
    __init__.py
    app.py          # 先空着，后面再写网页
  core/
    __init__.py
    services.py
    coupon_rule.py  # 只有一份，放这
  base/
    __init__.py
    db.py
    api.py
    config.py

  config.yaml
  main.py
```

注意两点：

- `__init__.py` 可以先是空文件，只是让 Python 把它当包
- `coupon_rule.py` 只放在 `core/` 下面，`base/` 不放

这一步做完，项目肯定会**暂时跑不动**，因为 import 路径变了——没关系，这正是我们要练的。

---

## 第二步：按“依赖方向”改 import（真正练架构的地方）

目标依赖关系要长成这样：

- `app` 只依赖 `core`
- `core` 依赖 `base` + 自己内部模块
- `base` 不依赖 `core`（这一条很关键）

你可以按这个思路改几处核心 import（我给你一个**示例方向**，不是要你原封不动照抄）：

### 1）在 `core/services.py` 里

以前可能是：

```python
from db import get_unissued_vipmoney
from api import ApiClient
from coupon_rule import match_coupon_for_order
from config import load_config
```

现在应该类似：

```python
from base.db import get_unissued_vipmoney
from base.api import ApiClient
from base.config import load_config
from core.coupon_rule import match_coupon_for_order
```

逻辑就是一句话：**service 调用 base 和 core 内部，而不是反过来。**

### 2）在 `core/coupon_rule.py` 里（可以暂时先不完美）

如果你暂时还在里面读配置，可以先写成：

```python
from base.config import load_config
```

将来你想让它更“纯业务”，再把 `load_config` 挪出到 service 里，这一步先不急。

### 3）在 `base/db.py` / `base/api.py` / `base/config.py` 里

这几个文件应该只依赖标准库、三方库，不依赖 `core` 或 `app`。
比如：

```python
# base/db.py
import cx_Oracle
from base.config import load_config
```

而不是从 `core` 引什么。

---

## 第三步：写一个最简单的 “app 层” 入口（先用命令行）

网页先别急，我们可以先做一个**超级薄的 CLI 入口**，让你感受三层是怎么协作的。

在项目根目录写一个 `main.py`，作用就一件事：调用 service：

```python
# main.py
from core.services import preview_unissued_orders

def main():
    orders = preview_unissued_orders()
    # 先简单打印几条看看效果
    for o in orders[:5]:
        print(
            o["trade_no"],
            o["recharge_amount"],
            o["coupon_name"],
            o["coupon_value"],
            o["beg_date"],
            o["end_date"],
        )

if __name__ == "__main__":
    main()
```

这其实就是一个最简单的 **app 层**：

- 不知道数据库怎么连
- 不知道规则怎么算
- 只知道：“我要预览未发券订单”，于是去找 `core.services` 要结果。

以后你上网页框架（Flask/FastAPI）的时候，也会是同一个套路，只不过换成 HTTP 请求 → 调 `preview_unissued_orders()` → 返回 JSON。

---

## ✅ 这轮你的任务小结

你现在可以按这个顺序实操：

1. 把文件按 `app/core/base` 目录整理好，加上空的 `__init__.py`
2. 按“app → core → base”的依赖方向调整 `import`
3. 写一个最简单的 `main.py`，调用 `preview_unissued_orders()`，能跑起来并打印几条记录

做到第 3 步，这个项目在“架构”层面就已经从**单文件脚本**升级到**有基本分层的工程**了。
