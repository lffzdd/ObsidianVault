好，我们直接掀开 Python 模块系统的盖子，看清里面那几个关键字段到底在干嘛，尤其是你问的主角：`__package__`。

你现在卡的点本质是：

> “我知道相对导入需要‘知道自己属于哪个包’，但这个信息到底是**怎么存的、谁给的、什么时候给的**？”

答案核心就几个东西：

- `__name__`
- `__package__`
- `__file__`
- 再加上 `sys.modules` 和 `__spec__`（可以轻一点带过）

我按故事线讲：**先讲它们各自是什么，再讲谁来给它们赋值，最后跑一遍你关心的 main/core 的完整流程。**

---

## 一、module 在 Python 里到底是什么？

Python 中的“模块”不是一个“文件名”，而是一个 **对象**，存放在 `sys.modules` 这个 dict 里。

比如你：

```python
import pkg.sub.core
```

做的其实是：

1. Python 去找并加载这个模块对应的 `.py` 文件
2. 创建一个 `module` 对象（类型是 `types.ModuleType`）
3. 给它塞上一堆属性：
	
	- `__name__`
	- `__package__`
	- `__file__`
	- `__spec__`
		
4. 把这个对象丢进 `sys.modules['pkg.sub.core']`

所以：

```python
import pkg.sub.core
import sys
m = sys.modules['pkg.sub.core']

m.__name__      # 'pkg.sub.core'
m.__package__   # 'pkg.sub'
m.__file__      # '/xxx/.../pkg/sub/core.py'
```

**关键：相对导入就是依赖 `__package__` 来判断 “`.` 和 `..` 到底从哪里算起”的。**

---

## 二、`__name__` 和 `__package__` 分工是什么？

你可以这样理解：

- `__name__`：这个模块在“整个 Python 世界”的全名（带包层级）
- `__package__`：相对导入用的“参考坐标系”

典型规则：

对于一个普通模块，比如 `pkg.sub.core`：

```python
core.__name__    == 'pkg.sub.core'
core.__package__ == 'pkg.sub'
```

对于一个“包本身”（`pkg` 这个目录的 `__init__.py` 对应的模块）：

```python
pkg.__name__     == 'pkg'
pkg.__package__  == 'pkg'
```

对于脚本方式运行的 `main.py`：

```bash
python main.py
```

对应模块：

```python
__name__    == '__main__'
__package__ == None
```

这就解释了：**脚本没有包坐标系，所以 `from .xxx` 没法算。**

---

## 三、相对导入到底是怎么用 `__package__` 的？

当你写：

```python
from . import x
from ..utils import y
```

解释器干的事逻辑上大概是：

1. 看当前模块对象的 `__package__` 字段
2. 把 `.` / `..` 翻译成“基于这个包名的偏移”
	
	- `.` = 当前包
	- `..` = 当前包的父包
		
3. 得到一个“绝对包名”，再去执行普通 import

举个例子：当前模块是：

```python
__package__ == 'pkg.sub'
```

那么：

- `from . import x` → 等价于导入 `pkg.sub.x`
- `from .. import z` → 等价于导入 `pkg.z`

**只要 `__package__` 有值，相对导入就有“坐标系”，就能算。**

---

## 四、那 `__package__` 是谁设置的？

这里是你之前推理容易拧巴的点。

### 情况 1：模块是通过 `import` 加载的

比如：

```python
from pkg.sub import core
```

加载 `core.py` 时，解释器已经知道完整模块名是 `pkg.sub.core`，于是会设置：

```python
core.__name__    = 'pkg.sub.core'
core.__package__ = 'pkg.sub'   # 去掉最后一段
```

这是绝大部分模块的来源。

### 情况 2：模块是作为脚本运行的（`python xxx.py`）

比如：

```bash
python pkg/main.py
```

对于 `main.py` 来说：

- 它不是通过 `import` 加载的
- 它是“程序入口”，特殊对待

于是解释器给它：

```python
__name__    = '__main__'
__package__ = None
```

不管它在不在 `pkg` 目录里，解释器 **不会** 自动去问：

> “诶你是不是某个包下面的模块啊？”

它完全不管，直接当孤儿处理。

### 情况 3：`python -m pkg.main`

这个是“模块方式运行”。

命令行告诉解释器：

> “请把 `pkg.main` 当作模块加载，并且执行它。”

于是解释器会按 **正常 import 模块的流程** 来处理它：

```python
__name__    = 'pkg.main'
__package__ = 'pkg'
```

所以此时 `main.py` 就有了包上下文，可以写：

```python
from . import something  # OK
from ..utils import x    # OK
```

## 五、回到你的核心困惑场景，完整跑一遍

假设结构：

```text
proj/
    pkg/
        __init__.py
        main.py
        sub/
            __init__.py
            core.py
```

### 运行方式 A：`python pkg/main.py`

加载 main.py 时：

```python
__name__    = '__main__'
__package__ = None
```

之后在 main.py 中：

```python
from pkg.sub import core
```

这一步只是把 **core.py** 作为 `pkg.sub.core` 模块加载，给 **core** 设置：

```python
core.__name__    = 'pkg.sub.core'
core.__package__ = 'pkg.sub'
```

注意：**这一步不会回头来修改 main 的 `__package__`**。

所以：

- 在 core.py 里：`from .. import something` ✅ 可以
- 在 main.py 里：`from . import something` ❌ 不行（还是没有包上下文）

也就是说：

> **“导入了包”并不会改变“当前文件是不是属于包”的事实。入口脚本始终是脚本。**

这一步就是你之前推理里“感觉 maybe 会改 main 的包名”的地方——实际不会。

---

### 运行方式 B：`python -m pkg.main`

现在加载 main.py 的方式变了：
命令行已经明确告诉解释器：**这是一个模块，不是裸脚本**。

所以 main 得到的是：

```python
__name__    = 'pkg.main'
__package__ = 'pkg'
```

这时在 main.py 中可以写：

```python
from .sub import core     # → pkg.sub.core
from .. import something  # 父包（如果有更上层）
```

而 core.py 还是像之前一样：

```python
core.__name__    = 'pkg.sub.core'
core.__package__ = 'pkg.sub'
```

此时：

- main 有包上下文（因为用了 `-m`）
- core 有包上下文（因为是被 import 的）

**所以两者都可以正常用相对导入。**

---

## 六、那 `__spec__` 又是干嘛的？（简单点说）

`__spec__` 是 Python import 系统后来引入的一个更正式的“模块描述对象”，里面记录了：

- 模块的完整名
- 是包还是普通模块
- loader 是谁
- origin（源码文件在哪里）

`__package__` 在现代实现里，基本上是由 `__spec__` 决定的。
但对你理解相对导入来说，记住这点就够：

> **相对导入只看 `__package__`，而 `__package__` 是“你是谁（包内模块还是脚本）”在加载时就已经决定好的。**

---

## 七、把这一切压缩成一条“底层规则”

你完全可以用这一条判断所有奇怪行为：

> **相对导入依赖当前模块的 `__package__`；
> 模块是通过 `import` 或 `-m` 加载的才会有合理的 `__package__`；
> 通过 `python xxx.py` 直接运行的文件永远是脚本（`__package__ = None`），
> 所以不可能通过相对导入理解 `.` / `..`。**

或者更短一点版本：

> **“被 import 才有包名，当脚本就没包名。
> 有包名就能算相对导入，没有就不行。
> `-m` 的作用就是让入口也‘像被 import 一样’。”**
