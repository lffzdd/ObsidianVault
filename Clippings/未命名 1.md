# 尚霖盈和数字化建设方案

> **以商品运营为核心 · 分阶段构建数据驱动的零售运营能力**

> 瞄准滞销 · 激活会员 · 沉淀统一数据基座

适用主体：尚霖盈和（长株潭中高端/设计师女装独家代理）

文档版本：V1.0（讨论稿）

编制日期：2026 年 6 月

密级：公司内部 · 仅限管理层及项目组传阅

# 一、方案概要

## 1.1 背景与症结

尚霖盈和是长株潭区域中高端/设计师女装的独家代理商，年销售额约 5 亿元、门店约 60 家、员工约 300 人，代理 DAZZLE、dzzit、JNBY、播 Broadcast、ARIOSE YEARS、REVAN 等品牌并运营自主品牌 AMIA。公司采用买断经销模式，所有库存风险由我方承担——这意味着每一次选品失误、每一次季中处理不及时，最终都直接体现为公司的真实亏损。这是理解本方案一切优先级的根本前提。

**当前最大的症结是滞销。**按吊牌价计，沉淀滞销已超过 2000 万元，对应成本约 700–800 万元。其根因有二：前端在订货会上选品主要靠经验（由商品经理、品牌经理与高销共同拍板，缺乏结构化的历史战绩支撑），后端在商品生命周期内的打折、调店、调拨、补货又不够及时。与此同时，商品运营缺乏实时可视的系统支撑、十万会员有分层标签却尚未接入自动化触达、关键决策普遍依赖手工 Excel 与个人经验。

## 1.2 数字化目标

本方案不追求“为建而建”的大平台，而是围绕业务价值、用好现有的伯俊 ERP + 驿氪 CRM + 企业微信资产，分阶段、小步快跑地构建数据驱动的运营能力。按照已对齐的优先级，聚焦三大核心工程：

| **核心工程**                      | **针对的核心痛点**              | **关键产出**                                                                                         | **优先级** |
|-----------------------------------|---------------------------------|------------------------------------------------------------------------------------------------------|------------|
| **工程一 商品运营效率底座**       | 2000 万滞销；商品运营无系统支撑 | 实时商品健康度看板 + 季中行动清单（折扣/调店/调拨/补货触发规则）；结构化历史战绩库支撑订货会选品复盘 | **P0**     |
| **工程二 会员精准营销**           | 会员未激活；过季库存需温和消化  | 驿氪自动化触达旅程 + 导购私域赋能（任务派发/素材库/利益绑定）；过季库存私域定向消化机制              | **P1**     |
| **工程三 统一数据基座与口径治理** | 无统一数据/分析层；口径不一     | 统一指标字典（含 SKC/SKU 口径）+ 轻量数据分析层，替代手工 Excel；随业务目标生长                      | **P2**     |

三大工程相互咬合：工程三为工程一、工程二提供可信的统一数据底座；工程一识别“该清的货”，工程二识别“接得住的人”，二者协同实现过季库存的私域定向消化——既回笼现金，又不以无差别打折损伤中高端价格形象。

## 1.3 预期价值

价值集中在四个方向，且以滞销改善为最大杠杆：

- 存量回收：通过私域定向 + 渠道组合温和消化已沉淀的 700–800 万成本库存，回笼现金、释放资金与门店陈列空间。

- 增量拦截（最大价值）：以历史战绩支撑选品、以季中行动清单及时止损，从源头降低每年新增滞销的生成率。在 5 亿体量上，滞销率哪怕小幅下降，年化减亏即达数百万元量级。

- 会员激活：十万会员接入自动化触达、近 3 万高频私域由导购精细运营，带动复购与连带提升。

- 人效与决策：以统一口径的实时看板替代手工 Excel 拼表，让商品、会员、财务从“做报表”转向“做决策”，决策更快、口径更稳。

## 1.4 关键成功要素

三大工程均横跨商品、会员、IT 三个领域，而公司当前数据按部门分管、IT 能力有限、缺乏跨域数据角色。因此本方案能否落地，最关键的前提是组织保障：

- 一把手授权的跨域负责人或核心小组，拥有统一口径的最终裁定权与跨部门协调权，直接向一把手汇报。

- 口径先行：先把 SKC/SKU、售罄率、动销率、折扣率等核心口径统一并文档化，再谈看板与模型。

- 业务驱动、小步快跑：先看板后模型、先核心品类后全量，每个阶段都交付可见的业务价值（快赢），用成果换取一线的信任与采纳。

整体节奏建议以下一季订货会为时间锚点倒排：用 6–12 个月完成奠基与前两大工程的核心能力，确保“数据支撑的订货会”如期落地。

# 二、现状诊断

## 2.1 公司与业务模式

尚霖盈和定位中高端/设计师女装零售代理，为长株潭区域（省级区域）独家代理，以购物中心店为主、少量奥莱店，单品牌单店、不混店；大店约 10 名导购、小店约 5 名，导购提成约 6 个点。代理品牌包括 DAZZLE、dzzit、JNBY、播 Broadcast、ARIOSE YEARS、REVAN，并运营体量较小的自主品牌 AMIA。

**核心约束——买断经销，库存风险在我方。**公司向品牌方买断进货，滞销即我方亏损。因此与“轻代理/联营”模式不同，尚霖盈和的数字化价值首先要回答一个问题：如何让买进来的每一件货，更可能卖得掉、卖得早、卖得不亏。这决定了本方案把商品运营、尤其是选品与季中处理放在第一优先级。

## 2.2 系统现状盘点

公司已具备相当扎实的系统底子，交易、商品、库存、会员等核心数据齐全，且关键系统之间已打通。真正缺失的不是“某个系统”，而是把分散数据汇聚起来、统一口径、转化为决策的分析层与机制。

| **系统 / 资产** | **覆盖范围与数据资产**                                                        | **现状与缺口**                                                                     |
|-----------------|-------------------------------------------------------------------------------|------------------------------------------------------------------------------------|
| **伯俊 ERP**    | POS、采购、销售、库存、调拨、盘点、出入库、分拣等；交易、商品、库存数据完整。 | 交易与库存数据齐全，是商品域分析的主数据源；缺面向运营决策的实时可视层。           |
| **驿氪 CRM**    | 会员 10 万+，已有会员分层与标签。                                             | 分层标签已具备，但尚无自动化营销/触达，会员资产基本处于“沉睡”状态。                |
| **企业微信**    | 已与驿氪打通，导购私域有效会员近 3 万。                                       | 最高频可触达资产，但集中在导购个人手中，缺统一的任务派发、素材与运营管理。         |
| **系统打通**    | 伯俊 ↔ 驿氪 已打通（会员身份与交易可对应）；企微 ↔ 驿氪 已打通。              | 底层链路已通，具备建设统一分析层与会员自动化的良好基础，无需推倒重来。             |
| **数据与分析**  | 无统一数据/分析层；报表靠手工 Excel 拼。                                      | 口径不统一、按部门分管（财务/会员/商品/IT）；IT 有专职但能力有限，无跨域数据角色。 |

## 2.3 核心痛点与根因（按金额排序）

痛点一：滞销严重（金额最大）

沉淀滞销按吊牌价超过 2000 万元，成本约 700–800 万元。在买断模式下，这是直接的真实亏损与资金占用。根因可拆为前后两端：

- **前端·源头：**订货会选品靠经验。由商品经理 + 品牌经理 + 高销共同决定，缺乏结构化的历史战绩支撑——“哪类版型/价格带/品类历史上卖得好、卖得早、不打折就能售罄”没有数据可查，只能凭印象与直觉，命中率难以稳定。

- **后端·生命周期：**商品上市后的打折、调店、调拨、补货不够及时。卖得好的店缺货却没及时补/调，卖不动的店压货却没及时处理，断码的款没及时归集，过季的款没及时清理——错过最佳处理窗口，滞销由此累积。

痛点二：商品运营效率无系统支撑

折扣、售罄、库存周转等关键指标缺乏实时可视与统一口径，商品经理难以及时发现问题、缺乏行动依据。决策依赖事后拼出的 Excel，往往“看到时已经晚了”。

痛点三：会员营销未激活

驿氪已有 10 万+ 会员及分层标签，却没有自动化触达，营销靠零散人工动作；真正可高频触达的私域约 3 万，且集中在导购手中，缺乏统一调度与赋能。庞大的会员资产与最值钱的私域资产都未被系统性激活，过季库存也缺少温和、定向的消化出口。

痛点四：决策方式以经验为主

关键决策（尤其是选品）主要靠报表 + 经验、甚至“拍脑袋”。经验本身是宝贵资产，但缺乏数据校准时，难以复制、难以纠偏，也难以沉淀传承。

## 2.4 根因归一：三个“缺”

四大痛点表象不同，根因可归结为三个“缺”，而本方案正是针对这三点同步发力：

- 缺统一、可信的数据与口径——同一指标各部门口径不一、靠手工拼表，数据难以支撑决策。（→ 工程三）

- 缺把数据变成行动的机制——即便有数据，也没有“看板 → 触发规则 → 行动清单 → 例会复盘”的闭环把它落到具体动作。（→ 工程一、工程二）

- 缺跨域统筹的人与权——商品/会员/IT 各管一摊，没有一把手授权、握有统一口径的跨域角色来牵头。（→ 组织保障）

# 三、总体思路与蓝图

## 3.1 设计原则

- **业务驱动，不为建而建。**一切建设都服务于明确的业务价值（首要是减滞销、激活会员），数据基座随业务目标生长，不追求一步到位的大平台。

- **用好存量，不推倒重来。**在已打通的伯俊 + 驿氪 + 企微之上叠加分析与应用层，最大化复用既有投资与数据资产。

- **小步快跑，先看板后模型。**先把实时看板与行动清单做出来产生价值，再逐步引入选品打分、销售预测等模型；先核心品类/品牌试点，再扩展全量。

- **保护品牌调性。**中高端定位忌无差别打折损伤价格形象，清货倾向私域定向；所有营销动作以维护价格体系与会员体验为前提。

- **口径统一，单一事实来源。**先统一术语与指标口径（SKC/SKU、售罄率、动销率、折扣率等），所有看板与决策基于同一套定义。

## 3.2 总体蓝图

总体架构在现有系统之上，自下而上分为四层，并以“组织与数据治理”贯穿全局。建设顺序自下而上：先打通数据与口径，再做能力与应用，最终支撑业务决策与执行。

|                                  |                                                                                                    |
|----------------------------------|----------------------------------------------------------------------------------------------------|
| **决策与执行层**                 | 商品经理季中决策 · 订货会选品复盘 · 会员运营 · 导购一线执行                                        |
| **能力与应用层（三大工程产出）** | 商品健康度看板与行动清单 · 历史战绩库与选品支撑 · 会员自动化触达 · 导购私域赋能 · 过季库存定向消化 |
| **数据整合与口径层**             | 轻量数据/分析层（抽取整合伯俊与驿氪数据）+ 统一指标字典（口径治理）                                |
| **数据源层（现有系统）**         | 伯俊 ERP（交易/商品/库存/调拨/盘点）· 驿氪 CRM（会员/分层/标签）· 企业微信（私域/导购）            |
| **贯穿全局**                     | 组织与数据治理：一把手授权的跨域负责人/核心小组 · 统一口径 · 数据质量与责任机制                    |

## 3.3 三大工程与优先级逻辑

优先级排序紧扣“金额最大、最急迫、价值最确定”的原则：工程一直指 2000 万滞销，是减亏的最大杠杆，置于 P0；工程二激活沉睡的会员与私域资产、并为过季库存提供温和出口，置于 P1，可与工程一部分并行；工程三作为底座跟随前两者按需生长，置于 P2，但其中成本最低的“口径治理”需先行启动。后续待基座成熟，再拓展销售预测、自动补货/调拨建议等远期能力。

# 四、工程一：商品运营效率底座（对着 2000 万滞销）

## 4.1 目标与价值

本工程是整个数字化的重中之重，目标是把商品运营从“事后拼 Excel、凭经验拍板”转为“实时可视 + 规则驱动 + 有据可依”，从前后两端同时压降滞销：

- 后端·季中决策：让折扣、调店、调拨、补货等动作有实时依据、有触发规则、有行动清单，及时止损、及时补单——降低存量滞销、拦截正在生成的滞销。

- 前端·订货会复盘：沉淀结构化历史战绩库，为下一季选品提供数据支撑，从源头提升选品命中率——这是减少滞销“增量”的最高杠杆。

## 4.2 商品核心指标体系（SKC 与 SKU 双视角）

先统一一套商品核心指标，并严格区分层级：选品看 SKC（款，如 DAZZLE 春夏 383 款即 SKC 层），断码/售罄看 SKU（含尺码）。同一指标在不同层级用途不同，口径必须一致。

| **指标**          | **层级**  | **定义 / 口径要点**                                                           | **主要用途**                                 |
|-------------------|-----------|-------------------------------------------------------------------------------|----------------------------------------------|
| 售罄率            | SKC/SKU   | 累计销量 ÷ 入库总量；需固定时间窗口（如上市第 N 周）与口径（按件/按吊牌额）。 | 衡量动销与去化进度，是季中处理与复盘的核心。 |
| 正价售罄率        | SKC       | 未打折（或折扣高于阈值）情况下的售罄占比。                                    | 中高端尤为关键，反映真实需求与价格承受力。   |
| 动销率            | SKC/SKU   | 周期内有销售的 SKC（或 SKU）数 ÷ 在售总数。                                   | 识别“铺了货却没动”的款，评估宽度健康。       |
| 首周/首 N 周表现  | SKC       | 上市初期售罄率与动销速度。                                                    | 最早的“爆款/滞销”信号，决定追单或早处理。    |
| 库存周转天数      | 品类/品牌 | 平均库存 ÷ 日均销售（成本口径）。                                             | 衡量资金占用与运营效率。                     |
| 库销比            | 门店/品类 | 期末库存 ÷ 周期销售。                                                         | 判断备货是否过量、是否需调拨/补货。          |
| 折扣率 / 折扣深度 | SKC       | 实际成交价 ÷ 吊牌价；跟踪折扣分布与趋势。                                     | 监控价格形象、衡量去化代价。                 |
| 断码率 / 齐码率   | SKU       | 缺断尺码占比 / 齐全尺码占比（按 SKC 下 SKU）。                                | 断码会拖累 SKC 售罄，触发集中调拨归集。      |
| 过季库存占比      | SKC/品类  | 过季 SKC 库存额 ÷ 总库存额。                                                  | 清货优先级排序，对接私域定向消化。           |

## 4.3 季中商品决策体系：从看板到行动清单

仅有看板还不够——很多滞销是“看到了也没及时动”。本工程的关键，是把指标按商品生命周期分级、用触发规则自动生成“本周该做什么”的行动清单，并配套决策例会落地。

### 4.3.1 商品生命周期健康度分级

为每个 SKC 标注其所处生命周期阶段，不同阶段关注不同信号、对应不同动作：

| **生命周期阶段** | **关注信号与指标**                             | **建议动作**                                                                            |
|------------------|------------------------------------------------|-----------------------------------------------------------------------------------------|
| **新品期**       | 首周/首 N 周售罄率、动销速度、各店表现差异。   | 强表现 → 追单/翻单、向高动销店调拨补充；弱表现 → 调店至更匹配门店、营销助推，尽早判断。 |
| **成长期**       | 售罄率爬升斜率、库存深度（可售周数）、断码率。 | 畅销款及时补货/调拨保供，避免断码断货错失销售。                                         |
| **成熟期**       | 售罄率是否停滞、库销比、折扣率。               | 动销放缓且库存偏高 → 评估温和促销或调拨归集；保持价格形象。                             |
| **衰退期**       | 动销停滞、断码加剧、可售周数过长。             | 断码款集中调拨归集成齐码店；启动定向去化，避免越压越深。                                |
| **过季**         | 过季库存额与占比、剩余可售。                   | 优先走私域定向消化（VIP 专享/导购一对一），慎用门店无差别打折。                         |

### 4.3.2 触发规则与行动清单（示例）

系统按统一口径自动巡检全量 SKC/SKU，命中规则即生成带责任人的行动清单，推送到对应角色，替代被动的事后发现。以下为示例规则，具体阈值需结合各品牌历史基准校准：

| **触发场景** | **判断口径（示例）**           | **建议动作**                             | **主责**    |
|--------------|--------------------------------|------------------------------------------|-------------|
| 新品动销疲软 | 上市 3 周售罄率低于同品类基准  | 调店至高潜门店 / 营销助推 / 早做处理预案 | 商品 + 门店 |
| 畅销断货风险 | 可售周数 \< 2 周且仍处成长期   | 向滞销门店调拨 / 向品牌翻单              | 商品        |
| 断码拖累售罄 | SKC 断码率超阈值、整体仍有库存 | 跨店集中调拨，归集为齐码可售             | 商品 + 调拨 |
| 库存深度过高 | 可售周数 \> 设定上限且动销放缓 | 温和促销 / 调拨平衡 / 纳入去化池         | 商品        |
| 过季待清     | 进入过季且仍有较高库存额       | 进入私域定向消化（对接工程二）           | 商品 + 会员 |
| 折扣异常     | 折扣深度超过品牌价格形象阈值   | 复核促销策略，防止价格体系受损           | 商品 + 品牌 |

### 4.3.3 看板形态与决策例会

看板以实时/准实时刷新，支持按品牌、品类、波段、门店、SKC、SKU 多维下钻，并直接呈现行动清单。配套建立周或双周商品决策例会，以看板与行动清单为唯一议事依据，逐条跟进打折/调店/调拨/补货的执行与结果，彻底替代手工 Excel 拼表。决策从“拼数据”转向“做决策与盯执行”。

## 4.4 订货会复盘与选品支撑体系

这是从源头减少滞销“增量”的关键。把每一季的实际战绩结构化沉淀下来，反哺下一季的选品判断，让商品经理 + 品牌经理 + 高销的经验有数据校准。

### 4.4.1 结构化历史战绩库

为历史每个 SKC 同时打上“属性标签”和“结果标签”，形成可检索、可分析的战绩库。建议先回溯近 2–3 年、聚焦核心品牌与品类，再逐步补全。

| **维度类别**      | **具体标签 / 字段（示例）**                                                                               |
|-------------------|-----------------------------------------------------------------------------------------------------------|
| **商品属性维度**  | 品牌、季节/年份、波段、品类（如连衣裙/外套/针织）、版型廓形、面料、颜色色系、图案、风格标签、吊牌价格带。 |
| **采购/结构维度** | 首单量、铺货门店数、尺码配比、订货占比（占该季/该品类比重）。                                             |
| **销售结果维度**  | 售罄率、正价售罄率、动销速度（首 N 周）、最终折扣深度、毛利贡献、退换率、是否判定为滞销。                 |

### 4.4.2 选品参考与打分框架

在订货会现场，对每一个候选 SKC，系统调取“属性相似”的历史款表现，给出参考评分与风险提示，把模糊的“我觉得这款会卖”变为“同类版型在此价格带历史正价售罄率约 X%”。具体支撑包括：

- 相似款战绩回溯：按版型、品类、价格带、风格匹配历史款，呈现其售罄、折扣、毛利与滞销情况。

- 价格带与品类结构分析：识别历史上易超量、易压货的价格带/品类，优化本季订货的结构配比。

- 订货量与尺码配比建议：基于相似款历史售罄与门店容量，提示订货量区间与尺码配比，从源头降低断码。

### 4.4.3 定位：辅助决策，而非取代经验

选品支撑工具的定位是为商品经理、品牌经理与高销提供共识基础——数据负责把历史规律摆上桌面、提示风险，最终判断仍由人结合品牌调性、流行趋势与现场买手手感做出。数据 + 经验，优于任何单一一方。

## 4.5 与买断模式的契合

因为库存风险全在我方，选品命中率的微小提升就能带来可观的减亏：在 5 亿体量上，把每年新增滞销（按成本计）压降一两成，对应即是数百万元的真实利润改善。相比清理已沉淀的存量，从源头“少买错、早处理”才是更可持续、更高回报的方向——这也是本工程把“季中决策”与“订货会复盘”双轮并重的根本原因。

## 4.6 落地路径

- 奠基（P0）：统一商品核心指标口径，搭建第一版实时商品健康度看板（接伯俊+驿氪），替代核心手工报表。

- 季中决策（P1）：上线触发规则与行动清单、建立商品决策例会；同步启动历史战绩库回溯与打标。

- 选品支撑（P1–P2）：历史战绩库就绪后，形成选品参考与打分框架，赶在下一季订货会投入使用。

# 五、工程二：会员精准营销（3 万私域 + 导购 + 驿氪分层）

## 5.1 目标与价值

把已有但沉睡的会员资产真正激活：让 10 万+ 会员接入自动化触达、让近 3 万高频私域被导购精细运营，带动复购与连带，并为过季库存提供温和、定向的消化出口，全程维护中高端价格形象。

## 5.2 会员资产盘点与触达分层

不同会员资产的可触达性与运营方式差异很大，应分层运营、各用其长：

| **会员层级**   | **规模 / 来源**            | **主要触达渠道**           | **运营重点**                             |
|----------------|----------------------------|----------------------------|------------------------------------------|
| **全量会员**   | 10 万+（驿氪，已分层打标） | 短信 / 公众号 / 小程序     | 自动化旅程批量培育与唤醒，盘活长尾。     |
| **高频私域**   | 近 3 万（企微，导购持有）  | 企微一对一 / 朋友圈 / 社群 | 导购精细化运营，最高转化，承接定向去化。 |
| **高价值/VIP** | 驿氪高层级标签人群         | 导购一对一 + 专属权益      | 专属服务与新品优先，维护与复购为先。     |
| **流失/沉睡**  | 长期未复购人群             | 自动化挽回 + 导购触达      | 预警挽回，唤醒沉睡，止损流失。           |

## 5.3 驿氪自动化触达体系

基于驿氪已有的分层与标签，搭建自动化营销旅程，把零散人工动作变为“事件触发、自动执行、可衡量”的常态化运营。核心场景示例：

| **营销场景** | **触发条件 / 人群** | **动作与内容**                     | **主渠道**  |
|--------------|---------------------|------------------------------------|-------------|
| 新会员培育   | 首次入会/首购后     | 欢迎礼遇 + 品牌介绍 + 二次到店引导 | 企微/短信   |
| 生日关怀     | 会员生日临近        | 专属生日权益与问候                 | 短信/企微   |
| 复购与连带   | 购买后特定周期      | 搭配推荐、连带券、上新提醒         | 公众号/企微 |
| 流失预警挽回 | 超过复购周期未到店  | 唤醒权益 + 导购跟进                | 短信+企微   |
| 消费升级     | 接近更高层级门槛    | 升级激励与权益预告                 | 企微/小程序 |
| 上新/节令    | 新品上市、关键节点  | 分层差异化推送（非无差别群发）     | 公众号/企微 |

所有触达需做节奏与频控管理，避免过度打扰；内容以价值感与品牌调性为先，而非单纯促销，保护中高端形象。

## 5.4 导购私域赋能

近 3 万私域是最值钱、最高频的资产，但目前分散在导购个人手中、缺统一调度。本节通过企业微信把“该联系谁、说什么、给什么”系统化地武装给导购，并与提成激励绑定。

- 任务派发：系统识别需触达的会员（如 VIP 久未到店、生日临近、可关联推荐、定向去化目标），自动生成任务派给对应导购，让一线“知道今天该联系谁”。

- 素材与话术库：提供标准话术、新品素材、朋友圈内容、一键发券与群发工具，降低导购运营门槛、统一品牌表达。

- 利益绑定：将私域运营与定向去化任务与 6 个点提成或专项激励挂钩，让导购有动力主动经营私域。

- 私域健康度管理：以导购运营看板跟踪好友数、活跃度、触达与转化，纳入日常管理与复盘。

## 5.5 过季库存定向消化机制（工程一 × 工程二 协同 · 关键亮点）

这是两大工程协同产生的、最契合尚霖盈和约束的能力：用私域定向消化过季/滞销库存，既回笼现金，又避免门店无差别打折损伤价格形象。逻辑闭环为——工程一识别“该清的货”，会员数据识别“接得住的人”，私域渠道完成低调而精准的触达。

| **步骤** | **关键动作**                                               | **数据 / 系统支撑**        | **主责**    |
|----------|------------------------------------------------------------|----------------------------|-------------|
| **①**    | 圈定去化目标：过季/滞销 SKC（含断码归集后）                | 工程一健康度看板与去化池   | 商品        |
| **②**    | 匹配目标人群：买过相似风格/价位/尺码、高复购、私域可触达者 | 驿氪标签 + 交易历史 + 企微 | 会员        |
| **③**    | 定向触达：VIP 专享 / 导购一对一 / 小程序专区               | 企微任务派发 + 素材/券     | 会员 + 导购 |
| **④**    | 复盘迭代：跟踪去化率与价格形象影响，控制节奏               | 去化效果看板               | 项目组      |

注意把握节奏与价值感，避免频繁定向折扣透支会员、形成“等打折”预期；定向去化应包装为“会员专属/限量”的权益体验，而非常态化清仓。

## 5.6 落地路径

- 先导购、后全量：优先用企微赋能 3 万私域并跑通过季库存定向消化（可与工程一季中决策同步试点，快速见效）。

- 再上自动化旅程：在驿氪逐步上线生日、复购、流失挽回等核心旅程，盘活 10 万全量会员。

- 持续优化：基于效果数据迭代人群、内容、节奏与激励。

# 六、工程三：统一数据基座与口径治理（跟随业务生长）

## 6.1 目标与原则

本工程为工程一、工程二提供可信的统一数据底座，但坚持“跟随业务目标生长、非为建而建”：不追求一次性的大数据中台，而是按业务需要分步搭建，先服务商品域，再服务会员域，再逐步扩展。

## 6.2 口径治理与指标字典（先行、低成本、高价值）

这是整个数字化最便宜也最关键的一步：它主要是组织共识 + 文档化，几乎不依赖采购。统一术语（SKC/SKU/款/波段等）与核心指标口径（售罄率、动销率、折扣率、周转、断码率等的定义、计算公式、时间窗口、数据来源、责任部门），形成《指标字典》并落地到所有看板，确保各部门“同一个词说的是同一件事”。详见附录 B 示例。

## 6.3 轻量数据 / 分析层

在已打通的伯俊与驿氪之上，把交易、商品、库存、会员数据抽取整合到统一分析层，以 BI/可视化工具产出看板，替代手工 Excel 拼表。建设要点：

- 选型方向：优先选择与伯俊等系统集成成熟、在零售行业落地广泛、对 IT 能力要求适中的 BI/分析方案；自建与采购各有取舍，需结合预算与人力评估，并以厂商正式报价为准。

- 渐进交付：先交付商品域核心看板（服务工程一），再扩展会员域看板（服务工程二），按需逐步增加主题，避免一次性大而全。

- 数据质量保障：明确主数据来源（如商品/库存以伯俊为准、会员以驿氪为准），建立校验与对账机制。

## 6.4 数据治理机制

- 单一事实来源：每个核心指标只有一个权威口径与一个数据出口，杜绝多版本报表。

- 责任到人：每个主题/指标明确归口责任部门与维护人，由跨域负责人统一裁定口径争议。

- 更新与对账：明确刷新频率、对账周期与异常处理流程，保证数据可信。

## 6.5 远期能力

在数据基座与历史战绩库成熟后，可进一步发展销售预测、自动补货/调拨建议、更精细的会员生命周期模型等。这些能力建立在前述底座之上，属于水到渠成的延伸，不在初期范围内强行铺开。

# 七、组织与机制保障

## 7.1 现状问题

三大工程均横跨商品、会员、IT，而当前数据按部门分管（财务/会员/商品/IT），IT 虽有专职但能力有限，且没有跨域数据角色。若没有一个握有统一口径、能跨部门协调的牵头者，方案极易陷入“各管一摊、口径打架、推进无力”。这是落地的最大组织风险，必须前置解决。

## 7.2 跨域负责人 / 数字化核心小组（一把手授权）

建议由一把手授权，设立数字化负责人或小核心团队，作为统一口径的拥有者与项目的总抓手，直接向一把手汇报。

| **角色**         | **来源 / 构成**                    | **核心职责**                                                       |
|------------------|------------------------------------|--------------------------------------------------------------------|
| **数字化负责人** | 内部选拔或外部引入，懂业务也懂数据 | 统筹三大工程、裁定口径、协调跨部门、对结果负责，直接向一把手汇报。 |
| **业务代表**     | 商品 / 会员 部门骨干（兼职）       | 提出业务需求、校准口径、推动本部门采纳与执行。                     |
| **数据/IT 角色** | IT 专职 + 视情外部伙伴             | 负责数据集成、看板与战绩库实现、系统对接与运维。                   |
| **财务代表**     | 财务部（兼职）                     | 校准成本/毛利等财务口径，参与 ROI 跟踪。                           |

授权要点：核心小组对核心指标口径拥有最终裁定权（具约束力）；拥有跨部门数据调用与协调权；其决议由一把手背书。

## 7.3 能力建设

- 补齐跨域数据角色：这是当前最关键的能力缺口，可通过内部培养 + 外部引入/顾问补强。

- IT 能力补强：以外部实施伙伴弥补初期建设能力，同时在过程中培养内部团队，逐步具备自维护能力。

- 一线赋能培训：对商品经理（看板与选品工具）、导购（私域工具与话术）开展培训，确保工具被真正用起来。

## 7.4 跨部门协作与例会机制

- 商品决策例会（周/双周）：以商品健康度看板与行动清单为唯一依据，跟进季中处理。

- 会员运营例会（双周/月）：复盘自动化旅程与私域去化效果，迭代策略。

- 项目推进例会（周）：核心小组同步进度、风险与口径决议。

## 7.5 变革管理

数字化的真正阻力往往不在技术，而在“人愿不愿意改变”。应对之道：

- 一把手持续背书：明确数字化是公司战略而非某部门的活，为跨部门协调撑腰。

- 利益绑定：把工具使用与去化、运营成效与导购提成/部门考核挂钩，让“用起来”对每个人有好处。

- 以快赢换信任：先在小范围跑出看得见的成果（如一次成功的私域去化、一份让商品经理省事又准的看板），再逐步推广。

# 八、实施路线图与里程碑

## 8.1 分阶段总览

整体分为四个阶段，业务驱动、小步快跑、各阶段都交付可见价值。时长为建议区间，需结合资源与厂商确认细化（阶段之间可部分并行）。

| **阶段 / 时间**                     | **阶段目标**                 | **关键举措**                                                                     | **交付物与里程碑**                                 |
|-------------------------------------|------------------------------|----------------------------------------------------------------------------------|----------------------------------------------------|
| **Phase 0 · 奠基 约 1–2 个月**      | 立组织、定口径、出第一版看板 | 成立核心小组、任命跨域负责人；制定核心指标字典（含 SKC/SKU）；搭轻量分析层       | ★ 统一口径的实时商品看板上线，替代核心手工报表     |
| **Phase 1 · 商品底座 约 2–4 个月**  | 季中决策成闭环、开始拦截滞销 | 上线触发规则与行动清单、建商品决策例会；启动历史战绩库回溯打标；试点私域定向去化 | ★ 季中行动清单运行；首批存量滞销私域去化见效       |
| **Phase 2 · 会员+选品 约 3–5 个月** | 激活会员、选品有数据支撑     | 驿氪核心旅程上线、导购私域赋能全面铺开；战绩库支撑选品打分框架                   | ★ 第一次“数据支撑的订货会”；会员自动化旅程常态运行 |
| **Phase 3 · 深化与远期 持续**       | 能力深化、底座按需扩展       | 销售预测、自动补货/调拨建议；更精细会员运营                                      | ★ 远期能力按需上线，基座持续生长                   |

## 8.2 以订货会节奏对齐时间锚点

女装订货会通常在销售季前数月召开。建议把“选品支撑就绪”这一里程碑，明确倒排锚定到下一季（如下一季春夏或秋冬）订货会的时间点，据此反推历史战绩库回溯与打标的启动时间，确保 Phase 2 的选品框架能赶上那一次订货会真正用上，而非滞后一季。

## 8.3 快赢清单（早期可见成果）

- 一份口径统一、实时可下钻的商品健康度看板——商品/会员/财务不再各拼各的 Excel。

- 一套自动生成的季中行动清单——商品经理每周清楚“哪些款该打折/调店/调拨/补货”。

- 一次成功的私域定向去化试点——用既有滞销验证“清货又不伤品牌”的打法并量化回收。

# 九、投入与收益（ROI）

## 9.1 投入估算

预算尚未确定，以下按类别给出量级与说明，供编制预算参考；最终金额需结合自建/采购方案与厂商正式报价确定。

| **投入类别**      | **内容说明**                                       | **量级与说明**                                               |
|-------------------|----------------------------------------------------|--------------------------------------------------------------|
| **数据/BI 平台**  | BI/可视化与数据整合工具的许可与集成                | 软件年费 + 实施，量级随用户数与自建/采购方案而定；需厂商报价 |
| **会员/私域工具** | 驿氪自动化营销模块、企微私域运营工具               | 多为模块/年费，量级中等；部分能力或可在现有基础上扩展        |
| **实施与定制**    | 看板开发、历史战绩库建设、规则/模型搭建、系统对接  | 一次性投入为主，自建或外部伙伴各有取舍                       |
| **人力**          | 跨域负责人 + 数据分析角色（可内部调配 + 外部补充） | 年化人力成本，是持续投入的关键一项                           |
| **持续运营**      | 维护、迭代、培训                                   | 年度小额预算                                                 |

总体而言，对一家 5 亿体量、60 家门店的零售企业，本方案属于务实的中等投入，且可分阶段投放、按成效追加，避免一次性重资产投入。

## 9.2 收益测算（示例 · 需以公司实际数据校准）

收益以滞销改善为最大来源。下表为测算逻辑与量级示例，所有假设均需用公司真实数据替换，仅供决策参考、非收益承诺。

| **收益杠杆**             | **测算逻辑（含假设）**                                                                                      | **量级（测算）**                            |
|--------------------------|-------------------------------------------------------------------------------------------------------------|---------------------------------------------|
| **存量滞销回收**         | 对 700–800 万成本的沉淀库存，通过私域定向 + 渠道组合在 12–18 个月温和去化，回笼部分现金并释放资金与陈列空间 | 数百万元现金回收（取决于折扣与动销）        |
| **增量滞销拦截（最大）** | 以历史战绩支撑选品、季中行动清单及时止损，降低每年新增滞销生成率；在 5 亿体量上，按成本计每降一两成         | 每年数百万元减亏（可持续）                  |
| **会员复购提升**         | 自动化旅程 + 私域精细运营带动复购与连带；会员贡献销售提升一两个百分点                                       | 每年数百万元增量销售（量级）                |
| **人效与决策**           | 报表自动化释放财务/会员/商品的拼表工时，决策更快更准                                                        | 人力释放 + 决策提速（难直接量化，价值显著） |

## 9.3 ROI 与回收逻辑

把投入与收益放在一起看：本方案的核心投入量级，与“滞销改善”单项每年带来的减亏/回收（数百万元量级）相比，回报具吸引力——即便仅实现较保守的滞销改善与会员提升，也有较大机会在较短周期内覆盖整体投入，更不必说人效与决策质量的长期价值。建议在 Phase 0–1 设定可量化的基线指标（如核心品类滞销率、私域去化率、会员复购率），用真实成效持续校准投入节奏。

*说明：以上 ROI 为面向规划的测算示例，依赖一系列假设，并非财务承诺或投资建议；公司应结合自身财务数据独立评估后再做预算与立项决策。*

# 十、风险与应对

提前识别关键风险并配套应对，是方案稳健落地的保障：

| **风险**                    | **潜在影响**                 | **应对措施**                                                   |
|-----------------------------|------------------------------|----------------------------------------------------------------|
| 口径不统一、数据不可信      | 看板无人信、决策仍回到拍脑袋 | 口径治理先行，建立指标字典与单一事实来源，由跨域负责人统一裁定 |
| 业务不买账（商品/导购不用） | 工具空转、价值落空           | 一把手背书 + 利益绑定 + 快赢示范 + 一线培训                    |
| 为建而建 / 范围蔓延         | 投入失控、迟迟不见效         | 业务驱动、分阶段、先看板后模型、每阶段交付可见价值             |
| IT 能力不足                 | 建设与运维受阻               | 引入外部实施伙伴，同步培养内部团队，关键岗位补强               |
| 历史数据打标工作量大        | 战绩库迟迟难成形             | 渐进推进，先核心品牌/品类、近 2–3 年，再逐步补全               |
| 品牌方对折扣/清货有约束     | 去化受限或触发合规问题       | 清货走私域定向、控制折扣深度，并与品牌方充分沟通               |
| 私域过度营销透支会员        | 会员反感、形成等折扣预期     | 节奏与频控管理，定向去化包装为专属权益而非常态清仓             |

# 附录

## 附录 A · 术语表

| **术语**            | **含义**                                                                            |
|---------------------|-------------------------------------------------------------------------------------|
| **SKC（款）**       | Stock Keeping Color，颜色级商品（如 DAZZLE 春夏 383 款即 SKC 层）；选品在此层判断。 |
| **SKU**             | 在 SKC 基础上含具体尺码的最小库存单位；断码/售罄在此层判断。                        |
| **波段**            | 同一季内分批上市的商品批次/节奏。                                                   |
| **售罄率**          | 累计销量占入库总量的比例，需固定时间窗口与口径。                                    |
| **正价售罄率**      | 未打折（或折扣高于阈值）情况下的售罄占比。                                          |
| **动销率**          | 周期内有销售的 SKC/SKU 占在售总数的比例。                                           |
| **断码率 / 齐码率** | SKC 下尺码缺断 / 齐全的程度，影响 SKC 整体去化。                                    |
| **库销比**          | 期末库存与周期销售之比，衡量备货是否合理。                                          |
| **库存周转天数**    | 平均库存与日均销售（成本口径）之比，衡量资金占用效率。                              |
| **调拨 / 调店**     | 门店间库存转移 / 将商品调至更匹配门店，用于保供与去化。                             |
| **翻单 / 返单**     | 对畅销款向品牌方追加订货。                                                          |
| **私域**            | 经企业微信等沉淀、可主动高频触达的会员（近 3 万，多在导购手中）。                   |
