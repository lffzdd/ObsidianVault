## 0. 一句话逻辑（这条链是整份设计的脊柱）

**早看见（指标） → 早诊断（信号分诊） → 早动作（调拨 / 补货 / 折扣 / 清货） → 攒战绩（订货会复盘修源头）**

两条分工贯穿全篇：

- **SKC 看「款的命运」**——这款是不是一笔好的买断赌注。选品、折扣、清货都看 SKC。
- **SKU 看「码段与操作」**——某店某码缺不缺、能不能拼、要不要搬。断码、售罄、调拨落到 SKU。

一个核心判断（第 1.4 节展开）：**同一个「售罄低于基准」的 SKC，可能是「款的问题 / 码的问题 / 店的问题」三种完全不同的病，对应三种完全不同的动作。误诊 = 把好款打折杀掉，还把错误经验喂给订货会。**

## 1. 监控指标体系

### 1.1 设计原则

1. **对着时间轴看，不看绝对值。** 一个款卖了 40% 是好是坏，取决于它上市了 2 周还是 10 周。所有售罄指标必须挂「上市周数」，跟「该周数的健康基准线」比（基准线设法见 1.5）。
2. **对着钱排序。** 痛点是钱（吊牌 2000 万 / 成本 700–800 万）。每个被点名的 SKC 都带一个「在险吊牌额 / 在险成本额」，分诊清单按在险金额倒序——先处理压钱最多的，ROI 才打得出来。
3. **分品牌设基准。** DAZZLE 的健康售罄曲线 ≠ JNBY ≠ 播。基准必须按「品牌 × 品类 × 上市周」分别定，不能全公司一条线。
4. **只用伯俊现成数据。** 下面每个指标都标了来源；唯一的结构性缺口是「商品结构化属性（廓形 / 风格 / 价位段）」，这是订货会复盘的前提，单列在第 3.4 节。

### 1.2 SKC 层指标（看款的命运 → 喂选品、折扣、清货决策）

|指标|定义口径|伯俊数据来源|看什么|
|---|---|---|---|
|**上市周数**|当前日期 − 首销日期（按全网首笔销售或商品档案上市日）|销售明细 / 商品档案|所有售罄判断的时间锚|
|**累计售罄率**|累计销量 ÷ 累计实收量（含翻单）|销售 + 入库|款的总体健康；必须配上市周数读|
|**N 周售罄率（4/8/12 周）**|上市第 N 周末的累计售罄率|销售 + 入库|**最早的领先信号**，首 4 周尤其关键|
|**正价售罄占比**|正价成交件数 ÷ 总成交件数|POS 成交价 vs 吊牌价|**中高端价格形象 KPI**：只能靠打折走 = 款力不足，即使最终售罄不差也是隐患|
|**平均成交折扣**|加权平均（成交价 ÷ 吊牌价）|POS|这款是「靠几折在走」|
|**库存周数（WOC）**|当前在库 ÷ 近 4 周平均周销|库存 + 销售|还能卖几周；季末高 WOC = 清货信号，早期高 WOC + 低售罄 = 早预警|
|**动销店数 / 有货店数**|近 N 周售出≥1 件的店数 / 在库≥1 件的店数|销售 + 分店库存|款的「铺得开不开 / 是不是只在个别店活」|
|**在险吊牌额 / 在险成本额**|当前在库件数 × 吊牌价 / × 成本价|库存 + 商品档案|这款现在压着多少钱——排序用|
|**调拨依赖度**|生命周期内该 SKC 被调拨件数 / 实收|调拨记录|复盘用：靠搬货才卖动的款 ≠ 真畅销|

### 1.3 SKU 层指标（看码段与操作 → 喂调拨、补货、断码处置）

|指标|定义口径|伯俊数据来源|看什么|
|---|---|---|---|
|**核心码定义**|每品牌指定哪几个码为核心码（如女装常见 M/L）〔待确认：各品牌核心码清单〕|需先定义|断码判断的基准|
|**断码状态（店 × SKC）**|该店该 SKC 缺核心码≥1 个（或核心码在库 = 0）|分店分 SKU 库存|顾客找不到自己的码 → 直接压住 SKC 售罄|
|**断码店数 / 占比**|有货但断码的店数 ÷ 有货店数|分店库存|一个「看似慢」的款，是不是其实全网断码|
|**码段完整度**|该店该 SKC 在库核心码数 ÷ 核心码总数|分店库存|陈列是否「能成套卖」|
|**SKU 售罄分布**|各码各自的售罄率|销售 + 入库|哪些码总先卖光、哪些码总剩 → 喂码段配比校准|
|**SKU 缺货风险**|单码 WOC 低于阈值且仍在动销|库存 + 销售|触发补缺调拨 / （在窗口内）补货|
|**常滞码识别**|跨款跨季稳定剩货的码（如 XS / XXL）|历史销售 + 库存|清货候选 + 订货会「别多订极端码」|

### 1.4 ⭐ 核心：「慢销」三分法（整套设计的智力核心）

同一个症状——**SKC 售罄低于基准**——背后是三种病。**诊断顺序很重要：先排除「码」和「店」，再下「款」的结论。**

|病因|识别信号（伯俊可算）|真相|动作|复盘要记的战绩标签|
|---|---|---|---|---|
|**店的问题**|总量不差，但分布错位：个别店爆 / 断码，多数店压货；动销店数集中|款没错，铺错了地方|**调店 / 调拨再平衡**|「需调店」——铺货策略问题|
|**码的问题**|核心码早早断、剩的全是边缘码；早期售罄其实不低，是断码后才停|**是好款，但订浅 / 订错码**|**断码归集调拨**＋（若在补货窗口）**补货**，**别打折**|「断码遗憾」——订量 / 码段问题|
|**款的问题**|全码段都不动、各店都慢、拉了折扣也起不来|真是一笔坏赌注|**折扣 → 清货**|「滞销」——选品问题|

**为什么这是核心：** 把「断码遗憾」误判成「款滞销」去打折，会同时犯三个错——杀掉本可补货赚钱的好款、白损价格形象、把「这类款不好卖」的错误结论喂回订货会，让下季继续少订好款。三分法把第 1 节的指标、第 2 节的动作、第 3 节的复盘标签串成一条线。

### 1.5 健康基准线怎么设（不要拍一个数）

基准是一条**曲线**，不是一个点：「某品牌某品类，上市 4 周应到 X%、8 周应到 Y%、12 周应到 Z%」。设法：

1. **用伯俊历史回溯。** 取过去 2–4 季同品牌同品类的 SKC，画出各上市周的售罄分布，取**中位数为基准线、下四分位为预警线**。这件事现在就能做，不依赖任何新系统。
2. **下四分位即「早预警名单」。** 上市第 4 周售罄落在同类历史后 25% 的 SKC，自动进早预警——这就是「早看见」最硬的那个信号。
3. **示例阈值（占位 · 务必按各品牌历史校准，先别当真）：** 连衣裙类 4 周售罄 <15% 预警、外套类 4 周 <10% 预警、季末 WOC >8 周进清货评审。**这些数字是给 IT 先有东西可写规则，不是定论。**

## 2. 季中决策触发机制

### 2.1 节奏（对应一期「周度售罄 review + 调拨 SOP」）

- **周度 SKC 健康扫描（快循环）：** 每周一把全网 SKC 跑一遍，自动落桶（见 2.2）。主战场是调拨 / 补货 / 早预警，**当周就能动手、零成本**。
- **节点折扣评审（慢循环）：** 对齐品牌 / 商场促销节点 + 生命周期阶段门，集中评审「折扣 / 清货候选」桶。**打折是节点决策，不是周决策**——避免无差别、随手打折伤价格形象。

### 2.2 分诊：每周把 SKC 自动落进 5 个桶

每个 SKC 每周自动归入唯一一个桶，桶内**按在险成本额倒序**排队（先处理压钱最多的）：

```
                       ┌─ 早期？售罄高于基准？还能补？ ──▶【补货机会】
                       │
 SKC 售罄 < 基准？──是─▶├─ 断码店多 / 核心码先断？ ───────▶【调拨机会·归集】
                       │
                       ├─ 分布错位（个别店爆其余压）？ ──▶【调拨机会·再平衡】
                       │
                       └─ 全码全店都慢、折扣也不起？ ─────▶【折扣 / 清货候选】
        │
        否
        ▼
 售罄正常 + 局部缺货 / 缺码 ─────────────────────────────▶【调拨机会·补缺】
 其余 ─────────────────────────────────────────────────▶【健康观察】
```

### 2.3 触发规则逐条

#### A. 补货（30–40% 的真杠杆：ARIOSE 约 4 成、其余约 3 成可补）

||内容|
|---|---|
|触发信号|上市早期 + N 周售罄显著高于基准 + 库存周数低于阈值（快缺货）|
|前置条件|**仍在补货窗口内**（lead time 允许）+ 该品牌该款可翻单|
|动作|发起翻单；按 SKU 售罄分布定补货码段（别照首单比例补，照实际卖法补）|
|责任人|商品部决策，IT 出数|
|数据依据|N 周售罄率、WOC、SKU 售罄分布|
|〔待确认·二期门槛〕|**lead time、最晚补货 cutoff、现在谁依据什么决定补**——这三个不给，补货纠偏无法定稿。底座先把「补货机会信号」算出来挂着，规则等这三个数|

#### B. 调拨（**你说调拨几乎无约束、被用得最不充分——这是全方案最便宜的杠杆，要往死里用**）

三种子型，对应三种信号：

|子型|触发信号|动作|
|---|---|---|
|**补缺调拨（拉式）**|动销店某核心码将缺货 + 别店该码在压|从滞销店搬到动销店，追动销|
|**断码归集**|全网该 SKC 断码店多，但合计余量够在少数店拼齐码段|散料集中到 2–3 家好店，重建完整码段陈列，把「码的问题」救回成可售款|
|**再平衡调拨**|同款 A 店压货、B 店动销好且快缺|按动销速度再分配库存|
|责任人|商品部定规则与触发，门店 / 物流执行||
|数据依据|分店 SKU 库存、分店动销、断码店数||

#### C. 打折（**中高端红线：忌无差别打折**）

| |内容|
|---|---|
|触发信号|上市足够周数 + 售罄持续低于基准 + **已排除码的问题和店的问题**（全码全店都不动）|
|前置条件|确认是「款的问题」；对齐品牌 / 商场促销节点|
|动作|**分级、分场**：① 战术折扣（参与品牌官方促销节点，护价格形象）；② 清货折扣（生命周期末，优先私域定向，见 D）|
|责任人|商品部 + 品牌经理（节点评审），跨域负责人把口径|
|数据依据|售罄曲线、正价售罄占比、平均成交折扣、在险金额|

#### D. 清货 / 私域定向（与二期会员线接口）

||内容|
|---|---|
|触发信号|过折扣期仍滞销 + 近季末 + 在险金额大|
|动作|渠道分流：**私域定向消化**（中高端首选，二期跑）vs 奥莱|
|〔待确认〕|**① 奥莱净回收地板线**——私域只有跑赢奥莱才值得做，**建议一期就把这个数摸出来**，否则二期私域清货 ROI 算不准；**② 私域成交形态**（导购 1:1 手聊收款？还是要小程序商城？）决定清货能不能上规模|

## 3. 订货会复盘 · 战绩数据沉淀

**目标：把「拍脑袋选品」换成「看战绩」。** 关键能力不是「记录每个款卖得怎样」，而是——**下次订货会看着一个新款时，能拉出「同类历史款的战绩」做参照。** 这要求战绩可按属性检索。

### 3.1 战绩档案（SKC 战绩卡）三段结构

#### A 段 · 选品决策端（订货会当场记 → 二期订货模块开起来才有）

|字段组|字段|
|---|---|
|身份|SKC、品牌、季节、上市波段|
|属性|品类（大/中/小类）、廓形、面料、主色/色系、价位段、风格标签|
|决策|订货数量、码段配比、计划铺货店数、首铺/翻单计划、计划吊牌价|
|责任|决策人（商品经理/品牌经理/高销）、选品理由标签、信心评级（主推/常规/试单）|

#### B 段 · 战绩结果端（伯俊全程沉淀 → **现在就能从历史回溯**）

|字段组|字段|
|---|---|
|售罄|4/8/12 周售罄率、季末售罄率、达到某售罄率用了几周|
|价格|正价售罄占比、平均成交折扣、各折扣档销量结构|
|操作|调拨依赖度、断码时点、动销店数峰值|
|财务|实际回收 vs 成本、季末结存（在险吊牌额 + 成本额）|
|终态|**畅销 / 正常 / 滞销 / 断码遗憾**（对应三分法标签）|

#### C 段 · 复盘衍生结论（A+B 链满一季后聚合 → 三期）

|结论|怎么算|喂回哪里|
|---|---|---|
|品类 × 价位段 售罄表现|按维度聚合 B 段|下季各类目订深订浅|
|廓形 / 色系 命中率|畅销占比|选品偏好校准|
|码段校准|SKU 实际售罄分布 vs 订货码段配比|修「总断 M 码 / 总剩 XS」|
|订量校准|实际售罄 vs 订货量|下季订量基准|
|选品人命中率|按决策人聚合终态|订货会话语权依据|
|相似款检索|给定候选款属性 → 拉同品牌历史相近款的售罄/正价占比/残留|**订货会现场参照**|

### 3.2 时间分层（直接对上三期路线图）

- **现在 / 一期：** B 段可**从伯俊历史回溯**——这就是 1.5 节基准线的数据，也是首批类目级回顾。**A 段还没有**（订货模块没开）。
- **二期：** 订货模块开起来，A 段开始随订货会录入；选品血缘从此能「订了什么 → 卖成什么样」回链。
- **三期：** A+B 链满**至少一个完整季**，C 段才算得出，复盘会才真能改选品。落地时点不是「第几个月」，是**二期之后的下一场订货会**。

### 3.3 ⚠️ 硬前提：商品属性必须结构化（不补这条，相似款检索做不出来）

伯俊商品档案通常有品类、颜色、吊牌价，但**廓形、风格、价位段段位往往没有结构化字段**。没有这些，「拉同类历史款」无从匹配。

**具体任务（IT + 商品部，二期起）：** 定义一份**商品属性字典**（品类层级 / 廓形 / 价位段分档 / 色系 / 风格标签），**订货会现场强制对每个 SKC 打标**。成本极低（订货时顺手打），但它是整个「修选品源头」的地基。

## 二、第一期（0–3 个月）：私域地基，会员营销就干三件事

零技术投入，全是 SOP + 激励 + 企微配置。这一期不依赖帆软，可全程并行。

### 1. 存量转化：把 7 万缺口里的暖客搬进企微

**双通道同时跑：**

- **通道 A · 驿氪自助拉**：给"近一年有交易、未加企微"的会员，用短信/公众号模板推一条加企微邀请，带钩子（加企微领专属券 / 积分翻倍 / 新品和你的尺码到货优先通知）。二维码用**企微渠道活码**，自动按门店归属分配、自动打标签。
- **通道 B · 导购主动加**：给每个店一份"你店里近一年买过、但没加企微"的名单，导购按名单用上次留的微信/电话主动触达。

**必须先定的一条规则——归属分配**：会员加进来归谁？建议**按门店归属，店内再按规则分给在职导购**，避免抢客撞单。这条不定，导购会内耗，会员部要在动作开跑前先拍。

**一期验收**：暖客转化率（新增企微 / 目标暖客），建议先定一个能交账的数（如暖客转化 40–50%）。

### 2. 增量转化：每一单结账都把企微加上（写进结账 SOP）

源头堵住，不然 7 万补完又漏新的。结账动作固化成五步：

开单 → 确认/注册驿氪会员（已有）→ **引导加企微**（话术："加企微，这单的券和积分到这发，下次新品到货和你的尺码补货第一时间通知你"）→ 客户扫**导购企微活码**（不走个人微信，这点是后面护栏的命门）→ 给即时小激励（加企微立减 / 小样 / 积分）。

**关键纪律：加好友只走企微活码，禁止走导购个人微信。** 走个人微信 = 这个客户是导购私产，导购一走就带走；走企微 = 客户是公司资产。这是整条护栏能不能立住的根。

### 3. 流失护栏：靠企微原生功能，不用开发

你们说"导购离职、会员没加链接就消失"——根因是这些客户从来没真正进过企微（只在导购个人微信/通讯录里）。所以护栏的根本动作就是上面那条"强制走企微活码"，再配两个企微原生功能：

- **离职继承**：导购离职，管理员一键把其名下客户分给接替导购，客户侧收到"服务顾问已变更"提示，关系不断。
- **在职转接**：导购转岗/休长假，客户可转给同店他人。

前提是客户得**打了门店归属标签**——所以活码进来自动打标签这步不能省。这一整块是配置 + 流程，几乎零成本，但要会员部 + IT 把企微后台的继承规则配死、把"离职交接 = 客户先继承再办离职"写进 HR 流程。

> 一期会员营销三件事的共同前提是激励——见第五节，没激励导购不会加人，这一期就空转。

### 2. 定向清货试点：会员部对那 2000 万交账的地方

这是引擎二，单独拎出来当一个完整试点来设计。

**第一步 · 选品来源**：从一期帆软看板的清货信号圈滞销款。**注意按 SKU 看而不是 SKC**——断码款只有能配上的尺码才卖得动，要把"还配得齐尺码"的 SKU 圈出来。

**第二步 · 选一个品牌试**：建议选**滞销金额大 + 会员基数大 + 调性允许内购**的品牌先跑（基数大的更容易做出人货匹配；DAZZLE 这类调性最硬的先别碰，等机制验证了再说）。

**第三步 · 人货匹配（用驿氪标签，这是私域清货跑赢奥莱的关键）**：不是群发，是精准匹配——

- 品类偏好：买过同品类
- 尺码匹配：清货 SKU 的尺码 ∈ 该会员历史尺码
- 价格带匹配：历史客单价 ≥ 清货价（别推给只买过低价的人，浪费且伤感知）
- 品牌偏好：买过该品牌

四个条件叠出来的人，才是"看到会心动、且买得起、且穿得了"的精准盘。

**第四步 · 走私域、保调性**：企微 1:1 或小范围社群，框定为"VIP 专属内购 / 老客特惠"，**私密 + 限量 + 限时**，制造稀缺而非常态降价。不在朋友圈大面积、不在公众号群发打折。

**第五步 · 不伤正价的护栏**：清货人群尽量和正价高潜客户**错开**（别把还会买正价的人拉去买清货）；试点后做一次**蚕食检查**——清货买家在之后 N 天的正价购买有没有下降，下降说明你在用清货价卖本来能正价卖的人。

**第六步 · 算账（这是 go/no-go 的硬指标）**：

```
私域定向清货 单件净回收 = 清货成交价 − 导购清货激励 − 履约/物流 − 小程序/平台分摊
奥莱地板线         = 同款走奥莱的 单件净回收
决策规则：私域净回收 > 奥莱地板线 → 私域清；否则 → 直接甩奥莱
```

**私域清货只有跑赢奥莱才值得做。** 所以一期就要把奥莱地板线那个数摸出来（你们路线图里也标了），否则二期这笔账算不了，试点做完也没法判断成不成。

**二期验收**：净回收率 vs 奥莱地板线（达标 = 私域跑赢）、清货动销件数/SKU 数、蚕食率（正价无明显下降）。

### 3. 成交形态的岔路口（二期唯一可能的大支出）

定向清货能不能上规模，卡在一个还没确认的点：**现在私域成交是导购 1:1 手工聊 + 手工收款吗？**

- 如果是手工：小规模能跑，但人一多就乱、难追踪归属、难算账，清货跑不出量。
- 要上规模，可能得上**小程序商城**——会员直接看清货专区、自助下单、自动归属到导购。这是二期唯一可能的较大支出，要不要花，取决于试点跑出来的量和这条成交形态的实情。

**建议**：二期先用手工形态跑通试点验证"私域能跑赢奥莱"，跑赢了、且量确实被手工卡住了，再决定上不上小程序——别为还没验证的规模先砸钱建商城。

## 五、贯穿全程：激励机制（成败在此，单独拎出来）

6 个点的提成是底盘。但你要导购多做三件**不在现有提成里**的事，每件都得单独给钱，否则一期就空转：

|行为|激励设计|防套利的关键|
|---|---|---|
|加企微|小额即时（每有效加 X 元）+ 季度按"名下活跃企微数"奖|**不按"加了几个"付，按"加的人 90 天内有互动/复购"付**，否则导购刷僵尸号|
|私域维护|与名下会员复购贡献挂钩|让导购把私域当资产养，而非加完就不管|
|推定向清货|清货款单独提成，**建议略高于正价提成**（清货是帮公司止损，值得多给）|货源和名单由公司控制——导购只能把"被圈定的清货款"推给"被圈定的人"，提成再高也套不了利；同时设净回收下限，防止为冲量贱卖到亏|

**清货提成那条要特别拿捏**：太低，导购宁可推正价不推清货；太高又怕导购故意压正价推清货。平衡点是**"提成略高 + 货和人都由公司圈定"**——把自由裁量权收回公司，激励就可以给得大方而不怕滥用。

## 一、基座不是一个系统，是三层；而且是"长出来的"不是"建出来的"

它由三层构成，缺一层都不成立：

- **语义层（口径字典）**——同一个指标全公司只有一个定义。这是地基里的地基，最便宜、最高杠杆。
- **数据层（分析数据）**——帆软真正去读的那份干净、对齐、留了历史的数据放哪。
- **治理层（谁拥有口径、怎么改）**——把上面两层从"项目里的临时约定"变成"公司资产"。

关键纪律：**这三层在每一期里只长到业务当期需要的大小**。一期帆软看板只读伯俊，就不需要单独的分析库；二期要跨库 join（会员）+ 要留历史（选品血缘），分析库才被业务"拉"出来；三期再收口成公司资产。基座的每一块，都是被前面业务用出来的沉淀，不是先盖好等业务来用。

**明确划出边界（写给 IT 和老板，防止预算跑偏）**：不做数据中台、不做数据湖、不做实时流、不自建 ML 平台。这套体量，分析库一个轻量实例 + 帆软 + 外包实施就够。

## 二、技术层：数据物理上放哪，怎么随三期长

你们的底子其实很好——**伯俊↔驿氪 已打通、驿氪↔企微 已打通，会员身份和交易能对应**。这意味着最难的"身份打通/数据采集"在源头基本解决了。基座不需要重新解决身份识别，只需要把这个已经对齐的 ID 一路带下去、留住、对齐口径。

数据流的走向是固定的，会变的只是"中间那层有多重"：

```
伯俊 ERP（交易/商品/库存/调拨/订货）─┐
驿氪 CRM（会员/分层/标签）──────────┼─→〔集成/同步〕→〔分析数据层〕→ 帆软 → 业务动作
企微（私域/导购关系）───────────────┘
```

中间那层随期演进：

- **一期**：帆软**直连伯俊（强烈建议走只读副本/从库，不要直连 POS 生产库）**，在帆软里建售罄/滞销数据集。**不建独立分析库。** 数据全在伯俊，这是最省、最快出活的。
- **二期**：两个需求把"独立分析库"拉出来——(1) 会员看板要 join 伯俊+驿氪+企微，在帆软里硬 join 会越来越吃力；(2) 选品血缘、生命周期状态这些**源系统会覆盖/不留历史的数据，必须有人按时间快照存下来**，靠查实时源库做不到。这时上**一个轻量分析库**（一台 MySQL/PostgreSQL 实例即可），ETL 把清洗、对齐、历史化后的表落进去，帆软改读这个库。ETL 由帆软实施伙伴建——IT 弱，这块必须外包。
- **三期**：**收口**。把分析库里被业务验证有用的那几张对齐表 + 口径字典，固化成"公司官方数据资产"，ETL 文档化、稳定化，以后所有报表都从这里出。销售预测（远期）就坐在这套已经历史化的数据上。

一句话给 IT：架构是 **直连（一期）→ 轻量分析库 + 历史化（二期）→ 收口成官方基座（三期）**，永远不碰中台。

## 三、语义层：口径字典——这一块是基座的命根子，写最厚

你最痛的"报表口径不统一、按部门分管"，根子在这层。**没有统一定义，帆软看板建不出来；建出来了部门也会为"你那个数怎么算的"吵起来，吵起来就没人按信号行动，止血就空转。** 所以一期就得起。

# 尚霖盈和 · 数字化方案（整合版）

> 给老板和商品 / 会员 / IT 各位负责人：这份方案不是「上一套系统」，而是用现有的伯俊、驿氪、企业微信加一个帆软，把公司从「报表 + 经验」改造成一条**能止住亏损、能拉动增长、还能自己长出数据资产**的链路。请先记住下面这一句话，全篇所有动作都挂在它上面。

**主线一句话：**
> **用「商品底座」把 2000 万滞销看清楚（哪些救得回、该走哪个杠杆），用「会员 / 私域」把它清掉或救回、同时拉动占公司 90% 的会员生意，在这个过程里顺手长出「统一数据资产」。**

## 一、为什么必须做：2000 万是怎么沉下来的

我们是**买断经销**——库存风险在我方，所以滞销不是「周转慢」，而是**直接亏损**。这一条是整份方案的财务锚点：所有投入都用「少亏多少 / 多赚多少」来算账，而不是「效率提升百分之几」。

2000 万（吊牌价，成本约 700–800 万）不是某一个环节坏了，而是**每一个止损杠杆都没在正确的时点、按正确的口径被正确使用**，累积出来的。根因在两个时间点上：

**源头——选品一次性下重注，且没有战绩支撑。** 期货占比高（ARIOSE 约 6 成、其余约 7 成在订货会当天就锁死），而伯俊订货模块没启用，「当初订了什么、最后卖成什么样」无法回链，下一季还是凭经验。**这是入口风险。**

**生命周期内——下错了注之后，反应太慢。** 该调没调、该补没补、该折 / 清没及时，缺实时可视、缺决策依据。**这是运营风险。**

把 2000 万按「本可被哪个杠杆救回」拆开，问题就具象了——这也是整个方案要操作的五个杠杆：

| 杠杆 | 成本 / 约束 | 现状 |
|---|---|---|
| **提前调拨** | 几乎零成本，60 店自由搬货 | 约束最小、却用得最不充分——**最便宜的止血点** |
| **季中补货纠偏** | 30–40% 期货空间，受 lead time / cutoff 约束 | 真杠杆，但能动多少取决于补货时效 |
| **私域定向清货** | 3w 私域，忌伤中高端调性 | 净回收跑得赢奥莱才值得做 |
| **返厂** | 仅 10% 额度，稀缺 | 该留给最差的款，不可滥用 |
| **奥莱兜底** | 净回收最低 | 地板，往年货都丢这里 |

所有杠杆共用一个前提：**早期、准确、按 SKC / SKU 正确口径看到信号。** 这就是为什么「商品底座」必须打头——它不直接卖货，它让所有杠杆**看得见、来得及**。

## 二、三大目标怎么咬合：为什么是这个顺序

三个目标不是先后排队的瀑布，是互相拉动的螺旋。先把角色定死：

- **目标一 · 商品运营底座 = 大脑。** 把 2000 万从「看不见」变成「看得见、分得清哪些救得回、该走哪个杠杆」。它产出的是**决策信号**。
- **目标二 · 会员精准营销 = 双重身份。** 一面是公司几乎全部生意的**增长引擎**（会员销售占比 90%+），一面是底座清货信号的**主力执行出口**（私域定向清货的能力在这里）。
- **目标三 · 统一数据基座 = 收口。** 把前两个目标在落地中验证有用的口径和数据，从「项目级」固化成「公司级资产」。

**为什么底座在前**：直接对着最大、最痛、ROI 最清晰的 2000 万；而且它定义了「要清什么、补什么、调什么」——没有它，会员侧的私域清货就是无的放矢，乱推过季款反而伤价格形象。

**为什么会员紧跟、不靠后**：90% 的会员占比决定它是最大增长杠杆，不能等；它同时是底座信号的执行末端，否则「看得见却动不了」。再叠加 **10w 驿氪 vs 不到 3w 企微的 7 万缺口**、以及导购离职带走会员链接的漏洞——这两件是不依赖底座的独立地基工程，越早动越好。

**为什么数据基座垫底 / 伴生**：先建中台再谈业务，会掉进「建了没人用、ROI 说不清、预算撑不住」的陷阱，尤其在预算轻、IT 弱的体量下。正确姿势是反过来——业务落地时各自沉淀口径、打通数据源、产出指标，基座只做「把已被业务验证有用的东西收口」。**先用、验证、再收口，绝不为建而建。**

## 三、三条工作流

下面把三条流各自的脊柱讲清楚（细节已在各自的落地设计里）。每条都标了「定位 → 核心机制 → 分期落点」。

### 3.1 商品运营底座（对着 2000 万的止血与纠偏）

**核心链路：早看见（指标）→ 早诊断（信号分诊）→ 早动作（调拨 / 补货 / 折扣 / 清货）→ 攒战绩（订货会复盘修源头）。**

两条口径分工贯穿全程：**SKC 看「款的命运」**（选品、折扣、清货），**SKU 看「码段与操作」**（断码、售罄、调拨）。

**这条流的智力核心是「慢销三分法」**——同一个「售罄低于基准」的 SKC，可能是三种完全不同的病，必须先排除码和店、再下款的结论：

- **店的问题**（总量不差、分布错位）→ 调店 / 再平衡调拨；
- **码的问题**（核心码早断、剩边缘码，其实是好款订浅了）→ 断码归集调拨 + 补货，**绝不打折**；
- **款的问题**（全码全店都不动、打折也不起）→ 折扣 → 清货。

为什么这是核心：把「断码遗憾」误判成「滞销」去打折，会同时犯三个错——杀掉本可补货赚钱的好款、白损价格形象、还把「这类款不好卖」的错误结论喂回订货会，让下季继续少订好款。

**关键设计原则**：所有售罄指标都挂「上市周数」、跟「按品牌 × 品类 × 上市周设的健康基准曲线」比（基准用伯俊历史回溯就能算，下四分位即早预警名单）；每个被点名的 SKC 都带「在险吊牌额 / 成本额」，分诊清单**按在险金额倒序**——先处理压钱最多的。

**季中节奏**：周度 SKC 健康扫描（快循环，主战场是零成本的调拨 / 补货 / 早预警，当周动手）+ 节点折扣评审（慢循环，打折是节点决策不是周决策，护价格形象）。

| 落点 | 内容 | 期 |
|---|---|---|
| SKC/SKU 口径、核心码定义、健康基准曲线 | 跨域负责人拍口径 + 伯俊历史回溯，**无需新系统** | 一期 |
| 周度分诊清单 + 调拨三型 SOP | 手工 Excel → 帆软 v1；调拨是**零技术快赢** | 一期 |
| 补货纠偏规则 | 卡在 lead time / cutoff / 现行决策依据〔待确认〕 | 二期 |
| 订货模块启用 + 选品血缘 + 商品属性字典 | 伯俊已有未用，攒数据给三期 | 二期 |
| 订货会复盘 + 相似款检索 | 依赖血缘攒满一季，落在**二期之后的下一场订货会** | 三期 |

### 3.2 会员精准营销（增长引擎 + 定向清货通道）

**定位钉死：双引擎。** 引擎一是常规的复购 / 客单 / LTV；**引擎二（这家公司独有、也是真正值钱的）是把会员营销当一条定向清货通道**，去接那 2000 万——它是唯一「既能消化过季库存、又不伤价格形象」的中间路。会员部这个季度被考核的，不只是会员活跃，更是**「私域帮公司止损了多少」**。

**最大单点杠杆是 7 万缺口**（10w 在册 − 3w 企微）。这不是「会员不够」，是「会员有、够不着」。先在驿氪里把 7 万拆成「近 12 个月有交易、未加企微」（暖客，优先抢）和「长期沉睡」（放后面），**一期主攻暖客**。

**一期就干三件事，零技术、全是 SOP + 激励 + 企微配置：**
1. **存量转化**——双通道把暖客搬进企微（驿氪自助拉 + 导购按名单主动加），用企微**渠道活码**自动按门店归属、自动打标签；
2. **增量转化**——把「加企微」写进结账 SOP，**只走企微活码、禁止走导购个人微信**（这是护栏的命门：走个人微信 = 导购私产、人走带走；走企微 = 公司资产）；
3. **流失护栏**——靠企微原生的离职继承 / 在职转接，把「离职交接 = 客户先继承再办离职」写进 HR 流程。

**二期是定向清货试点（引擎二对 2000 万交账的地方）**：从底座清货信号圈滞销款（**按 SKU 看，要圈还配得齐尺码的**）→ 选一个滞销金额大 + 会员基数大 + 调性允许的品牌先跑（DAZZLE 这类最硬的先别碰）→ 用驿氪标签做**人货匹配**（品类 / 尺码 / 价格带 / 品牌四条件叠出精准盘）→ 走企微 1:1 或小社群，框定「VIP 内购」，私密 + 限量 + 限时、**制造稀缺而非常态降价** → 做蚕食检查（别用清货价卖本来能正价的人）→ 算账：

> 私域单件净回收 = 清货成交价 − 导购清货激励 − 履约 − 平台分摊
> **决策规则：私域净回收 > 奥莱地板线 → 私域清；否则甩奥莱。**

**成交形态的岔路口**：先用导购手工 1:1 跑通试点、验证「私域能跑赢奥莱」，**跑赢了且量确实被手工卡住，再决定上不上小程序商城**（二期唯一可能的较大支出）——别为还没验证的规模先砸钱建商城。

**激励是成败所在**（单独拿出来）：6 个点提成是底盘，但加企微、私域维护、推清货这三件不在现有提成里，每件都要单独给钱，否则一期空转。关键拿捏：**加企微按「90 天内有互动」付而非按「加了几个」付**（防刷僵尸号）；**清货提成略高于正价、但货和人都由公司圈定**（把自由裁量权收回公司，激励就能给得大方而不怕滥用）。

### 3.3 统一数据基座（长出来的，不是建出来的）

先把这个词拆对，防两个误区：IT / 外包听到「数据基座」想上中台 / 数据湖（5 亿、IT 弱的体量撑不住，也违背「非为建而建」）；业务方以为它就是帆软看板（看板只是出口）。

**它是三层、且每一期只长到业务当期需要的大小：**
- **语义层（口径字典）**——同一个指标全公司只有一个定义。最便宜、最高杠杆，**一期就起**。
- **数据层（分析数据）**——帆软真正去读的那份干净、对齐、留了历史的数据。
- **治理层（谁拥有口径、怎么改）**——把前两层从临时约定变成公司资产。

**明确边界（写给 IT 和老板）：不做中台、不做数据湖、不做实时流、不自建 ML 平台。**

你们的底子很好——伯俊↔驿氪、驿氪↔企微已打通，身份和交易能对应，最难的「身份打通」在源头已基本解决。所以技术演进只是「中间那层有多重」：

| 期 | 数据怎么放 |
|---|---|
| 一期 | 帆软**直连伯俊只读副本**（不碰 POS 生产库），在帆软里建售罄 / 滞销数据集。**不建分析库**，最省最快出活 |
| 二期 | 两个需求把分析库拉出来——会员看板要 join 三个源、选品血缘要按时间快照留历史。上**一台轻量 MySQL/PG**，ETL 由帆软伙伴建（IT 弱必须外包） |
| 三期 | **收口**：把验证有用的对齐表 + 口径字典固化成「公司官方数据资产」，销售预测坐在这套历史化数据上 |

**两颗必须一期就去验的数据地雷**：① 上市日在伯俊里是否干净、每个 SKC 都有（所有「上市后 N 周」指标都靠它）；② 商品属性是结构化字段还是自由文本（版型 / 价格带 / 面料若是散字段，血缘学不动）。还有一条会员侧待审：交易能挂到会员 ID 的占比有多少（直接决定会员分析的完整度）。

## 四、整合路线图：三条流合一的三期视图

三期不是瀑布、是**叠瓦**——后一期在前一期收尾前就起步；每期把「快见效的」前置、「慢承重的」垫底；**用前一期的 ROI 解锁后一期的预算**。因为预算「看老板心情」，节奏必须是「先花最少的钱止血 → 拿数字说话 → 再要钱」。

### 第一期（0–3 个月）· 最便宜的止血 + 会员地基

只激活现成的 + 改流程，不碰需要开发的东西。

| 流 | 快见效（quick win） | 打地基 |
|---|---|---|
| 商品 | 周度售罄 review + **调拨 SOP**（零技术、第 1 周就能动）；帆软 v1 滞销预警看板 | SKC/SKU 口径、健康基准曲线、上市日 / 属性数据审计 |
| 会员 | —— | 7 万暖客转企微、结账加企微 SOP、流失护栏（零技术） |
| 数据 | 帆软直连伯俊出 v1 看板 | 口径字典 v1（先钉 SKC/SKU + 售罄 / 滞销） |
| 组织 | 第一仗（调拨止血）立威 | 跨域负责人到位、虚拟组挂牌 |

**这一期要撬出的东西**：一份「早看见 + 早调拨 = 少亏多少」的 ROI，拿去要二期预算。
**钱量级**：几乎只有帆软的钱，其余是人力 + 激励盘子。
**依赖 / 风险**：帆软签约是明牌时间风险——所以零技术的流程止血放最前，万一帆软拖了，止血照常发生。

### 第二期（3–9 个月）· 建决策闭环

前提：一期看板被信任、口径稳了，再上——否则信号没人信、机制空转。

| 流 | 快见效 | 打地基 |
|---|---|---|
| 商品 | 补货纠偏（待 cutoff 规则） | 订货模块启用、A 段录入、选品血缘、商品属性字典 |
| 会员 | 驿氪自动化触达开通（配置非采购）；定向清货试点跑一个品牌 | 三层会员 / 清货口径入字典 |
| 数据 | 会员看板 | 轻量分析库 + ETL（外包）、历史化、血缘 link 表 |

**钱量级**：中等。驿氪是已有工具开通；唯一可能的大支出是小程序商城——**取决于试点跑出的量和成交形态实情，先验证再决定**。
**门槛**：补货 lead time / cutoff / 决策人、私域成交形态、奥莱地板线——这三个数不补，二期无法定稿。

### 第三期（9 个月起 / 进入第二年）· 攒资产 + 治理 + 远期

订货会复盘（依赖血缘攒满一季，落在二期后的下一场订货会，真正把「拍脑袋」换成「看战绩」）+ 统一基座收口、口径治理制度化、跨域岗固化 + 远期销售预测起步（预算另算，此时一二期 ROI 已证明，要钱有底气）。

**两条暗线贯穿三期**：口径治理（一期一条 → 二期加会员 → 三期收口）、组织（虚拟组 → 项目制跑顺 → 视成效固化常设岗）。

## 五、组织与口径保障：不治这个，上面全是空话

诊断里「数据按部门分管、口径不统一、无跨域角色」是**所有问题的元问题**。但你现在缺的不是一个数据部门，是**一个有一把手授权、能在三方之间拍口径、调资源、对结果负责的人**。组织要轻。

**核心支点 · 跨域负责人（候选已有、一把手已支持——最大有利条件）。** 他对三大目标的**结果**负责（少亏多少、转化多少），不是对「做了多少报表」负责。手里必须有三样权，缺一个这角色就废：**口径最终解释权 / 跨部门调数调人权 / 直达一把手的汇报线**。他不是 IT 主管升级版，也不该由商品或会员任一部门的人兼任而偏向原部门——一把手授权时要明说：他代表公司口径。

**执行载体 · 虚拟核心小组，不是新部门。** 商品 / 会员 / IT 各出 1 人，人在原部门、活在虚拟组，项目制，不动架构。跑顺了再谈固化。

**外部杠杆补 IT 缺口。** IT 弱是硬约束，解法是分工不是逼 IT 学建模：内部 IT 只做取数 / 对接 / 运维，**帆软伙伴做建模 / 看板 / 实施**，跨域负责人做「业务↔数据」的翻译。

**口径治理怎么真的落地——别想一次做一本大词典，从最痛的一条开始：**
- **载体**是一张活的口径字典（Excel/wiki 即可，别上 MDM 工具），每条记：指标名 / 唯一定义 / 计算逻辑 / 唯一裁定人 / 受影响看板 / 版本。
- **牛鼻子是让口径长在帆软看板里**——各部门停掉手工 Excel 各自拼数,统一看同一张看板的同一个数。这把「口径统一」从靠自觉变成**物理上只有一个数可看**，这才是治理的强制力，不在文档里。
- **以「款 = SKC」为例怎么统一执行**：光定义没用,要落到各部门场景——选品 / 复盘看 SKC，断码 / 售罄 / 清货推款看 SKU，财务两者对应金额。三个动作:① 把定义焊进系统字段、看板按场景默认展示对的那层(让系统替人记住该看哪层,比培训管用);② 字典里写清「谁在什么场景用哪个」;③ 跨域负责人做唯一仲裁。SKC/SKU 之所以排第一,是因为它同时卡着你最痛的两件事——选品和断码 / 清货,统一它 ROI 最高。
- **变更流程**:任何部门可提议 → 跨域负责人裁定 → 裁定后即全公司定义、帆软必须用 → 记版本。一个指标只能有一个裁定人。
- **治理是联邦式拥有 + 中央裁定**:域归属不变(商品拥有商品口径、会员拥有会员口径、财务拥有财务口径),跨域负责人是字典唯一主人。三期升级成制度,设一道「口径审查闸」——新看板上线前必须对齐字典才放行。

# 第一部分 · 我们是谁、现在处在什么局面

## 1.1 定位与经营模式

尚霖盈和是**中高端 / 设计师女装的区域零售代理商**,持有长株潭区域(省内)的独家代理权,以购物中心店为主、少量奥莱店,单品牌单店、不混店经营。年销售额约 5 亿,门店约 60 家,员工约 300 人(大店约 10 名导购、小店约 5 名,导购提成约 6 个点)。

**经营模式的核心是「买断经销」——这一条决定了我们整份方案的底层逻辑,必须先讲透。**

买断经销意味着:我们从品牌方**先把货买断、压在自己手里**,再通过门店卖给消费者。和「联营扣点 / 代销」不同,**卖不掉的库存风险全部落在我方**,品牌方不承担。

这一条带来一个绕不开的结论:

> **对我们来说,卖不掉的货不是「周转慢」的问题,而是「真金白银亏损」的问题。一件压在仓里或最后甩奥莱的货,亏的是我们自己的钱。**

整份方案后面所有的取舍、所有的 ROI 计算,都锚在这句话上——我们衡量每一项投入,看的是「能少亏多少 / 多赚多少钱」,而不是「效率提升了百分之几」这种听上去好听、却不直接对应利润的指标。

## 1.2 代理品牌矩阵

公司代理 DAZZLE、dzzit、JNBY、播 Broadcast、ARIOSE YEARS、REVAN 六个中高端 / 设计师品牌,另有自主品牌 AMIA(体量较小)。这些品牌的共同特征是**价格形象敏感**——中高端的客群买的不只是衣服,还有品牌调性。这一点会反复出现在后文:**无差别打折会伤害价格形象,是一条红线。**

各品牌在两个关键机制上的差异,直接影响我们能动用哪些手段(后文第二部分会用到):

- **订货机制**:每年按季节订货 2–4 次。大部分货量在订货会当天就以「期货」形式一次性下单锁定,季中可补货的比例有限——ARIOSE YEARS 约「期货 6 成、可补 4 成」,其余品牌约「期货 7 成、可补 3 成」。
- **品牌方约束**:可退订货量上限约 10%(订 100 件最多退 10 件),这是一个**稀缺**的纠错额度;门店之间的调拨则基本没有约束。

这两条很重要:它意味着**选品在订货会当天就基本定了生死**(大头锁死、退货额度又少),而**调拨是我们手里几乎免费、却没用足的纠错工具**。

## 1.3 系统与数据现状

公司的系统底子其实不差,问题不在「缺系统」,而在「系统的能力没被用起来、数据没被打通成决策」。

**伯俊 ERP** 覆盖 POS、采购、销售、库存、调拨、盘点、出入库、分拣等,交易 / 商品 / 库存数据齐全。但其中的**订货模块一直没有启用**——这一条后面很关键,它意味着我们「当初订了什么、订了多少、谁拍的」没有结构化地留下来。

**驿氪 CRM**(独立系统)有 10w+ 会员,已有会员分层和标签,但目前**只用了入会和积分兑换两个功能,自动化营销完全没开通**。

**打通情况良好**:伯俊↔驿氪已打通(会员身份与交易能对应),驿氪↔企业微信已打通。这意味着最难的「会员身份识别、交易归属」在源头已经基本解决——这是我们做数据分析最值钱的一块底子。

**企业微信私域**:导购手上的有效私域会员不到 3w——而在册会员有 10w+。这中间 **7 万人的差距**,后面会看到,是全公司最大的一个单点机会。

**正在洽谈**:帆软(数据分析 / 可视化工具)的采购,目前在谈。

## 1.4 组织与决策现状

这是问题的「元层面」,后文所有跨部门动作都受它制约:

- **无统一数据 / 分析层**,报表靠各部门手工 Excel 拼,**口径不统一**(同一个指标,不同部门算法不同,经常对不上)。
- **数据按部门分管**(财务部 / 会员部 / 商品部 / IT 部各管一摊),**没有任何跨部门的数据角色**能统一口径、统一调度。
- **IT 有专职但能力有限**,擅长系统运维,不具备数据建模能力。
- **关键决策主要靠报表 + 经验**,尤其选品环节,基本靠商品经理 + 品牌经理 + 高销凭经验共定,**没有结构化的历史战绩作支撑**。

# 第二部分 · 问题诊断:公司最大的一笔钱,正漏在库存上

## 2.1 从模式推出风险:滞销 = 直接亏损

把第一部分的几条事实串起来,公司当前的核心风险就浮现了:

> 买断经销(库存风险在我方)+ 期货为主(订货会当天锁死大头)+ 退货额度仅 10%(纠错空间小)+ 选品靠经验(没有战绩支撑)
> = **一旦选品押错,货就压在我们自己手里,且很难退回品牌,最终只能打折或甩奥莱消化——每一步都是我方的亏损。**

这不是假设,而是已经发生、并且正在持续发生的事。

## 2.2 这笔钱有多大:沉淀滞销约 2000 万(吊牌)

把当前积压的滞销库存盘一盘:**按吊牌价计,沉淀滞销已超过 2000 万元,对应的进货成本约 700–800 万元。**

这 700–800 万,是公司实打实压在货上、且大概率收不回全额的钱。它就是这份方案要瞄准的第一个、也是最大的一个靶子。

补充一个重要事实,它决定了我们救这笔钱的打法:**当前积压的滞销基本都是当年的货**——往年的陈货已经通过自有奥莱店处理掉了。这说明问题**不在「清理历史陈货」,而在「当季的货,在它还有救的生命周期内,我们动作太慢」**。这是个好消息:当年的货,意味着大部分还有机会在它「死掉」之前救回来,而不是只能贱卖。

## 2.3 根因:不是某个环节坏了,是每个止损动作都「慢了、错了」

2000 万不是单点故障,而是两个时间点上的问题叠加,最后乘成了一笔大钱:

**根因一(源头)· 选品一次性下重注,且没有战绩支撑。**
期货占比高,大头在订货会当天就锁死;而伯俊订货模块没启用,「当初订的某款,最后到底卖成什么样」无法回链到下一次订货会。结果是:**每一季选品,都还在凭经验重新拍一遍,过去的教训没有被结构化地学习。** 这是入口风险。

**根因二(生命周期内)· 下错注之后,反应太慢。**
一款货上市后表现不好,本来有多种补救手段——调拨、补货、适度折扣、私域清货——但当前缺乏实时可视和决策依据,该调的没及时调、该补的没及时补、该清的没及时清。等到季末发现,已经晚了。这是运营风险。

## 2.4 把 2000 万拆开看:五个「止损杠杆」分别在什么状态

要救这笔钱,关键是认清:**同一笔滞销,本可以用不同的手段、在不同的时点止损,每种手段的成本和回收差别很大。** 把它们排出来,问题就具象了:

| 止损杠杆 | 成本 / 约束 | 当前状态 |
|---|---|---|
| **① 提前调拨** | 几乎零成本,60 店之间自由搬货 | 约束最小,却用得最不充分——**这是最便宜、最该先用的止血点** |
| **② 季中补货纠偏** | 有 30–40% 期货空间可补,但受 lead time / 补货截止时点约束 | 真实可用的杠杆,但能动多少取决于补货时效 |
| **③ 私域定向清货** | 有不到 3w 私域可触达,但忌伤中高端调性 | 净回收跑得赢奥莱,才值得做 |
| **④ 返厂** | 仅 10% 额度,非常稀缺 | 应留给最差的款,不能滥用 |
| **⑤ 奥莱兜底** | 净回收最低 | 最后的地板,往年货都丢这里 |

**诊断的最终结论一句话:** 2000 万的根子,是这五个止损杠杆**都没有在正确的时点、按正确的口径、被正确地使用**,累积出来的损失。而它们全部依赖同一个前提——

> **能不能早一点、准一点,按正确的款 / 码口径,看见每一款货的真实健康状态。**

这就解释了为什么我们的第一个动作必须是「把货看清楚」:它本身不直接卖货,但它让上面五个杠杆**看得见、来得及**。看不见,再多手段都用不上。

# 第三部分 · 转型目标与主线逻辑

基于上述诊断,一把手已对齐的三大目标及其优先级如下。这一部分讲清楚**为什么是这三个、为什么是这个顺序、它们之间怎么咬合**——这是整份方案的逻辑骨架。

## 3.1 三大目标各自的角色

**目标一 · 商品运营效率底座 —— 「大脑」。**
把 2000 万滞销从「看不见」变成「看得见、分得清哪些救得回、该走哪个杠杆」。它产出的是**决策信号**:对哪些款、在什么时点、采取什么动作(调拨 / 补货 / 折扣 / 清货)。它直接对着公司最大的痛点。

**目标二 · 会员精准营销 —— 「双重身份」。**
一方面,会员销售占公司销售额的 **90% 以上**,所以会员营销本身就是公司**几乎全部生意的增长引擎**;另一方面,它又是目标一清货信号的**主力执行出口**——「私域定向清货」这个杠杆的执行能力,就在会员这条线上。

**目标三 · 统一数据基座 —— 「收口」。**
把前两个目标在落地中**验证过、确实有用**的口径和数据,从「项目里的临时约定」固化成「公司级资产」。注意:它是被前两个目标用出来的沉淀,**不是先建好等业务来用**。

## 3.2 为什么是这个顺序

**为什么底座打头**:它直接对着最大、最痛、ROI 最清晰的 2000 万,适合用低成本快赢先打出成绩。而且它定义了「要清什么、补什么、调什么」——**没有它,会员侧的私域清货就是无的放矢,乱推过季款反而会伤价格形象。**

**为什么会员紧跟、不能靠后**:90% 的会员占比决定它是最大的增长杠杆,不能等;它同时是底座信号的执行末端,否则会出现「看得见却动不了」。再加上 10w 在册 vs 不到 3w 私域的 **7 万人缺口**、以及「导购离职、会员没加企微就流失」的漏洞——这两件是不依赖目标一的独立地基工程,越早动越好。

**为什么数据基座垫底 / 伴生,而不是打头**:这一点最容易做错,必须讲清。**先建一个大数据中台再谈业务,会掉进「建了没人用、ROI 说不清、预算撑不住」的经典陷阱**,尤其在我们预算轻、IT 弱的体量下。正确的姿势是反过来:目标一、二落地时各自沉淀口径(先从最痛的那条开始)、打通数据源、产出指标;目标三只做「把已被业务验证有用的东西收口、统一、治理」。**这就是「非为建而建」的纪律。**

## 3.3 三者不是瀑布,是螺旋

```
        ┌─────────────────────────────────────────┐
        │  目标一(大脑)产出「该对哪款做什么」的信号    │
        └──────────────────┬──────────────────────┘
                           │ 信号需要出口
                           ▼
        ┌─────────────────────────────────────────┐
        │  目标二(出口+引擎)执行清货,同时拉 90% 增长  │
        └──────────────────┬──────────────────────┘
                           │ 落地中沉淀口径与数据
                           ▼
        ┌─────────────────────────────────────────┐
        │  目标三(收口)把验证有用的固化成公司资产     │
        └─────────────────────────────────────────┘
              业务拉动数据 ⇄ 数据反哺业务(螺旋上升)
```

# 第四部分 · 三条工作流的具体设计

> 本部分讲清每条流「定位 → 核心机制 → 分期落点」。前文是为什么,这里是怎么做。

## 4.1 商品运营底座:对着 2000 万的止血与纠偏

### 核心链路

**早看见(指标)→ 早诊断(信号分诊)→ 早动作(调拨 / 补货 / 折扣 / 清货)→ 攒战绩(订货会复盘,修选品源头)。**

两条口径分工贯穿全程,这是商品数字化的基本功,务必全公司统一:

- **SKC(款,即不含尺码的「色款」)看「款的命运」**——这一款是不是一笔好的买断赌注。**选品、折扣、清货都看 SKC。**
- **SKU(含尺码)看「码段与操作」**——某店某码缺不缺、能不能拼、要不要搬。**断码、售罄、调拨落到 SKU。**

### 智力核心:慢销「三分法」

这是整套商品设计里最关键的一个判断,也是最容易被现有「凭经验」打法做错的地方:

> 同一个症状——**某款 SKC 售罄率低于健康基准**——背后可能是三种完全不同的病。**必须先排除「码」和「店」,再下「款」的结论。**

| 病因 | 识别信号(伯俊数据可算) | 真相 | 正确动作 |
|---|---|---|---|
| **店的问题** | 总量不差,但分布错位:个别店爆 / 断码,多数店压货 | 款没错,铺错了地方 | 调店 / 再平衡调拨 |
| **码的问题** | 核心码早早断、剩的全是边缘码;早期售罄其实不低 | **是好款,但订浅了 / 订错码** | 断码归集调拨 +(若在窗口内)补货,**绝不打折** |
| **款的问题** | 全码段都不动、各店都慢、拉了折扣也起不来 | 真是一笔坏赌注 | 折扣 → 清货 |

**为什么这是核心**:如果把「断码遗憾」(其实是好款,只是订少了 / 断了码)误判成「款滞销」去打折,会同时犯三个错——**杀掉一个本可以补货赚钱的好款、白白损伤价格形象、还把「这类款不好卖」的错误结论喂回订货会,导致下一季继续少订好款。** 一次误诊,亏在当下、还祸及未来。

### 关键设计原则

1. **对着时间轴看,不看绝对值。** 一款卖了 40% 是好是坏,取决于它上市 2 周还是 10 周。所有售罄指标必须挂「上市周数」,跟「按品牌 × 品类 × 上市周设的健康基准曲线」比。基准曲线用伯俊历史数据回溯就能算(取同类历史款各上市周售罄分布的中位数为基准、下四分位为预警线),**不需要任何新系统**。
2. **对着钱排序。** 每个被点名的款都带一个「在险吊牌额 / 在险成本额」,分诊清单**按在险金额倒序**——先处理压钱最多的,ROI 才打得出来。
3. **只用伯俊现成数据。** 上述指标全部能用伯俊现有数据算出,唯一的结构性缺口是「商品结构化属性(廓形 / 风格 / 价位段)」,那是订货会复盘的前提,放在二期处理。

### 季中决策节奏

- **周度 SKC 健康扫描(快循环)**:每周把全网款跑一遍,自动落进 5 个处理桶(补货机会 / 归集调拨 / 再平衡调拨 / 补缺调拨 / 折扣清货候选 / 健康观察)。主战场是**零成本的调拨和早预警,当周就能动手**。
- **节点折扣评审(慢循环)**:打折是对齐品牌 / 商场促销节点的**节点决策,不是周决策**——避免随手打折、无差别打折,护住价格形象。

### 分期落点

| 能力 | 依赖 | 落在哪期 |
|---|---|---|
| SKC/SKU 口径、核心码定义、健康基准曲线 | 跨域负责人拍口径 + 伯俊历史回溯,**无需新系统** | 一期 |
| 周度分诊清单 + 调拨三型 SOP | 手工 Excel → 帆软 v1;调拨是**零技术快赢** | 一期 |
| 补货纠偏规则 | 卡在 lead time / 截止时点 / 现行决策依据〔待确认〕 | 二期 |
| 订货模块启用 + 选品血缘 + 商品属性字典 | 伯俊已有未用 | 二期 |
| 订货会复盘 + 相似款检索 | 依赖血缘攒满一季,落在**二期之后的下一场订货会** | 三期 |

## 4.2 会员精准营销:增长引擎 + 定向清货通道

### 定位钉死:双引擎

会员营销在我们这里**不是普通的 CRM**,否则部门会按「做活跃、做复购」的常规打法去干,把最值钱的那条线漏掉。

- **引擎一(常规)**:把 10w 会员的复购、客单、生命周期价值做起来——任何 CRM 都做的事。
- **引擎二(我们独有、也是真正值钱的)**:会员营销要当一条**定向清货通道**,去接那 2000 万滞销。它是唯一一条「既能消化过季库存、又不伤价格形象」的中间路——无差别打折伤调性,甩奥莱回收低,私域定向是中间那条路。

**这个定位决定了会员部这个季度被考核的,不只是会员活跃,更是「私域帮公司止损了多少」。**

### 最大杠杆:7 万缺口

我们手上其实是**触达能力天差地别的三层会员**:

| 层 | 量级 | 触达方式 | 能干什么 |
|---|---|---|---|
| 驿氪全量会员 | 10w+ | 短信 / 公众号(低频群发) | 广而浅,自动化旅程的盘子 |
| 企微私域 | <3w | 1:1、朋友圈、社群(高频可反复) | 真正能「推得动」过季款的盘子 |
| 导购手工 | 私域里的核心 | 导购个人关系 | 转化最高,但不可规模化、随离职流失 |

**最大的单点杠杆,就是 10w 在册 − 3w 私域 = 7 万人的缺口。** 这不是「会员不够」,是「会员有、但够不着」。一期的会员核心 KPI 就一句话:**把这 7 万里值得救的部分搬进企微,并堵住继续漏的口子。** 注意先拆堆——「近 12 个月有交易、未加企微」(暖客,优先抢)和「长期沉睡」(放后面),一期主攻暖客。

### 一期:私域地基(零技术,全是 SOP + 激励 + 企微配置)

1. **存量转化**:双通道把暖客搬进企微——驿氪自助拉(给暖客推加企微邀请,带钩子)+ 导购按名单主动加。二维码用企微**渠道活码**,自动按门店归属、自动打标签。
2. **增量转化**:把「加企微」写进结账 SOP,**只走企微活码,禁止走导购个人微信**。这是护栏的命门:走个人微信 = 客户是导购私产,人一走就带走;走企微 = 客户是公司资产。
3. **流失护栏**:靠企微原生的离职继承 / 在职转接功能,把「离职交接 = 客户先继承、再办离职」写进 HR 流程。

### 二期:定向清货试点(引擎二对 2000 万交账的地方)

这是会员线的重头戏,作为一个完整试点来设计:

- **选品**:从一期帆软看板的清货信号圈滞销款,**按 SKU 看**——断码款只有还配得齐尺码的才卖得动。
- **选品牌**:选「滞销金额大 + 会员基数大 + 调性允许内购」的品牌先跑(DAZZLE 这类调性最硬的先别碰,机制验证后再说)。
- **人货匹配**(私域跑赢奥莱的关键):用驿氪标签做精准匹配,四个条件叠出来——品类买过、尺码匹配历史尺码、价格带历史客单 ≥ 清货价、买过该品牌。叠出来的才是「看到会心动、且买得起、且穿得了」的精准盘。
- **走私域、保调性**:企微 1:1 或小社群,框定为「VIP 专属内购」,**私密 + 限量 + 限时,制造稀缺,而非常态降价**。
- **护栏**:做蚕食检查——别用清货价卖本来能正价买的人。
- **算账(go/no-go 硬指标)**:

```
私域单件净回收 = 清货成交价 − 导购清货激励 − 履约 − 平台分摊
决策规则:私域净回收 > 奥莱地板线 → 私域清;否则甩奥莱。
```

**关键提醒**:私域清货只有跑赢奥莱才值得做,所以**奥莱净回收地板线这个数,建议一期就摸出来**,否则二期这笔账算不了。

**成交形态岔路口**:先用导购手工 1:1 跑通试点、验证「私域能跑赢奥莱」;**跑赢了、且量确实被手工卡住,再决定上不上小程序商城**(二期唯一可能的较大支出)——别为还没验证的规模先砸钱建商城。

### 贯穿全程:激励机制(成败在此)

6 个点提成是底盘,但要导购多做「加企微、私域维护、推清货」这三件不在现有提成里的事,每件都得单独给钱,否则一期空转。两个关键拿捏:

- **加企微按「90 天内有互动 / 复购」付,而非按「加了几个」付**——否则导购刷僵尸号。
- **清货提成略高于正价、但货和人都由公司圈定**——把自由裁量权收回公司,激励就能给得大方而不怕导购套利(压正价、贱卖冲量)。

## 4.3 统一数据基座:长出来的,不是建出来的

### 先把这个词拆对(防两个误区)

- **误区一(IT / 外包侧)**:听到「数据基座」就想上数据中台 / 数据湖。我们 5 亿的体量、IT 弱的现状根本撑不住,也违背「非为建而建」。**明确边界:不做中台、不做数据湖、不做实时流、不自建 ML 平台。**
- **误区二(业务侧)**:以为它就是「帆软看板」。看板只是出口,基座是看板背后那套让数字**可信、可复用**的东西。

### 它是三层,且每期只长到当期需要的大小

- **语义层(口径字典)**:同一个指标全公司只有一个定义。最便宜、最高杠杆,**一期就起**。
- **数据层(分析数据)**:帆软真正去读的那份干净、对齐、留了历史的数据。
- **治理层**:谁拥有口径、怎么改,把前两层从临时约定变成公司资产。

### 技术演进:中间那层「有多重」随期变

我们的底子很好——伯俊↔驿氪、驿氪↔企微已打通,身份和交易能对应,**最难的身份打通在源头已基本解决**。所以技术演进只是中间层的轻重:

| 期 | 数据怎么放 |
|---|---|
| 一期 | 帆软**直连伯俊只读副本**(不碰 POS 生产库),在帆软里建售罄 / 滞销数据集。**不建独立分析库**,最省最快出活 |
| 二期 | 会员看板要 join 三个源、选品血缘要按时间留快照——上**一台轻量数据库**,ETL 由帆软伙伴建(IT 弱必须外包),帆软改读这个库 |
| 三期 | **收口**:把验证有用的对齐表 + 口径字典固化成「公司官方数据资产」,销售预测坐在这套历史化数据上 |

### 两颗必须一期就去验的「数据地雷」

- **上市日在伯俊里是否干净、每个 SKC 都有**?所有「上市后 N 周」的指标都靠它,它脏了全盘皆输。
- **商品属性是结构化字段,还是自由文本 / 空着**?版型 / 价格带 / 面料若是散字段,选品血缘学不动,攒了等于白攒。

(另需审计:交易能挂到会员 ID 的占比有多少,它决定会员分析的完整度。)

# 第五部分 · 三期路线图

## 5.1 总节奏:叠瓦推进,用前一期 ROI 撬后一期预算

三期不是瀑布、是**叠瓦**——后一期在前一期收尾前就起步;每期把「快见效的」前置、「慢承重的」垫底。因为公司预算尚未敲定、需要逐步说服,**节奏必须是「先花最少的钱止血 → 拿数字说话 → 再要预算」**,不能反过来。

## 5.2 第一期(0–3 个月)· 最便宜的止血 + 会员地基

只激活现成的 + 改流程,不碰需要开发的东西。

| 流 | 快见效(Quick Win) | 打地基 |
|---|---|---|
| 商品 | 周度售罄 review + 调拨 SOP(零技术、第 1 周可动);帆软 v1 滞销预警看板 | SKC/SKU 口径、健康基准曲线、上市日 / 属性数据审计 |
| 会员 | —— | 7 万暖客转企微、结账加企微 SOP、流失护栏(零技术) |
| 数据 | 帆软直连伯俊出 v1 看板 | 口径字典 v1(先钉 SKC/SKU + 售罄 / 滞销定义) |
| 组织 | 用第一仗(调拨止血)立威 | 跨域负责人到位、虚拟组挂牌 |

- **要撬出什么**:一份「早看见 + 早调拨 = 少亏多少」的 ROI,拿去要二期预算。
- **钱量级**:几乎只有帆软的钱,其余是人力 + 激励盘子。
- **风险**:帆软签约是明牌时间风险——所以零技术的流程止血放最前,万一帆软拖了,止血照常发生。

## 5.3 第二期(3–9 个月)· 建决策闭环

前提:一期看板被信任、口径稳了,再上——否则信号没人信,机制空转。

| 流 | 快见效 | 打地基 |
|---|---|---|
| 商品 | 补货纠偏(待截止规则确认) | 订货模块启用、选品血缘、商品属性字典 |
| 会员 | 驿氪自动化触达开通(配置非采购);定向清货试点跑一个品牌 | 三层会员 / 清货口径入字典 |
| 数据 | 会员看板 | 轻量分析库 + ETL(外包)、历史化、血缘表 |

- **钱量级**:中等。驿氪是已有工具开通;唯一可能的大支出是小程序商城——**取决于试点跑出的量,先验证再决定**。

## 5.4 第三期(9 个月起 / 进入第二年)· 攒资产 + 治理 + 远期

订货会复盘(依赖血缘攒满一季,落在二期后的下一场订货会,真正把「拍脑袋」换成「看战绩」)+ 统一基座收口、口径治理制度化、跨域岗固化 + 远期销售预测起步(预算另算;此时一二期 ROI 已证明,要钱有底气)。

**两条暗线贯穿三期**:口径治理(一期一条 → 二期加会员 → 三期收口制度化)、组织(虚拟组 → 项目制跑顺 → 视成效固化常设岗)。

# 第六部分 · 组织与口径保障:不治这个,上面全是空话

诊断里「数据按部门分管、口径不统一、无跨域角色」是**所有问题的元问题**。但要看清:**我们现在缺的不是一个数据部门,而是一个有一把手授权、能在商品 / 会员 / IT 三方之间拍口径、调资源、对结果负责的人。** 组织要轻。

## 6.1 核心支点:跨域负责人

候选已有、一把手已支持,这是最大的有利条件。把这个角色定死:

- **他对什么负责**:对三大目标的**结果**负责(少亏多少、转化多少),不是对「做了多少报表」负责。
- **他手里必须有的三样权**(缺一个这角色就废):口径最终解释权 / 跨部门调数调人权 / 直达一把手的汇报线。
- **他不是什么**:不是 IT 主管的升级版,也不该由商品或会员任一部门的人兼任而偏向原部门——一把手授权时要明说:他代表公司口径。

## 6.2 执行载体:虚拟核心小组(不是新部门)

```
            一把手(授权 + 看 ROI + 撬预算)
                     │
        跨域负责人(口径解释权 + 调度权 + 直达汇报)
                     │
   ┌──────────┬──────────┬───────────┬──────────────┐
 商品代表    会员代表    IT 代表    外部帆软伙伴
(选品/补货/  (驿氪/企微/ (取数/对接/  (建模/看板/
 调拨)       导购私域)   运维)        实施)
```

各部门出 1 人,人在原部门、活在虚拟组,项目制,不动现有架构。跑顺了再谈固化。**IT 弱是硬约束,解法是分工不是逼 IT 学建模**:内部 IT 只做取数 / 对接 / 运维,帆软伙伴做建模 / 看板 / 实施。

## 6.3 口径治理:从最痛的一条开始,焊进看板

口径治理最容易死在「想做一本大词典」上。正确姿势是**跟着业务用数生长,谁先要用谁先统一**:

- **载体**:一张活的口径字典(Excel / wiki 即可,别上专门工具),每条记:指标名 / 唯一定义 / 计算逻辑 / 唯一裁定人 / 受影响看板 / 版本。
- **牛鼻子是让口径长在帆软看板里**:各部门停掉手工 Excel 各自拼数,**统一看同一张看板的同一个数**。这把「口径统一」从靠自觉,变成物理上只有一个数可看——治理的强制力在看板里,不在文档里。
- **以「款 = SKC」为例怎么真的统一**:光定义没用,要落到各部门场景——选品 / 复盘看 SKC,断码 / 售罄 / 清货推款看 SKU,财务两者对应金额。三个动作:① 把定义焊进系统字段、看板按场景默认展示对的那层(让系统替人记住该看哪层,比培训管用);② 字典里写清「谁在什么场景用哪个」;③ 跨域负责人做唯一仲裁。SKC/SKU 之所以排第一,是因为它同时卡着最痛的两件事——选品(SKC)和断码 / 清货(SKU),统一它 ROI 最高。
- **治理是「联邦式拥有 + 中央裁定」**:域归属不变(商品拥有商品口径、会员拥有会员口径、财务拥有财务口径),跨域负责人是字典唯一主人,裁定冲突。三期升级成制度,设一道「口径审查闸」——新看板上线前必须对齐字典才放行。

# 第七部分 · 需要现在拍板的决策点(开工门槛)

这些问题不答,方案落不了地。按「不答会卡住哪一期」排序:

| # | 决策 | 不答会卡住 | 谁拍 | 时限 |
|---|---|---|---|---|
| 1 | **跨域负责人的授权强度**:只是「牵头协调」,还是真给「口径拍板 + 调人调数 + 直达汇报」 | 整套组织能不能跑 | 一把手 | 一期前 |
| 2 | **会员归属 / 分配规则**:7 万转进来归谁、店内怎么分 | 一期加人(导购抢客撞单) | 会员部 | 一期前 |
| 3 | **激励预算盘子 + 清货提成点位** | 一期加人和清货都推不动 | 一把手 + 会员 | 一期前 |
| 4 | **是否真没有固定售罄 review 节奏** | 一期第 1 周先动什么 | 商品部 | 一期前 |
| 5 | **补货 lead time / 最晚截止时点 / 现行决策依据** | 二期补货纠偏定稿 | 商品部 | 二期前 |
| 6 | **私域成交形态**(手工 1:1?)→ 决定要不要上小程序 | 二期唯一可能的大支出 | 会员部 | 二期前 |
| 7 | **奥莱净回收地板线**(具体数字,**建议一期就摸出来**) | 二期清货 ROI 算不了 | 商品 + 财务 | 一期摸、二期定 |

**其中 1、2、3、4 是一期开跑前必须有答案的;5、6、7 可一期边跑边摸,但二期定稿前必须有结论。**

# 第八部分 · 几条「别理想化」的现实提醒

写在最后,是为了不让这份方案变成一张漂亮但落不了地的饼:

1. **帆软没签是一期的明牌风险**——所以零技术的流程止血放最前,不依赖帆软也能先止血。
2. **IT 能力有限是硬约束**——帆软实施必须外包,本方案没有任何「IT 自己建模型」的假设。
3. **首年别指望 AI 选品**——选品血缘要攒满一季,三期才谈复盘,远期才谈预测。谁承诺一年内 AI 选品,谁在画饼。
4. **别新建数据部门、别上中台**——预算轻 + IT 弱时这是最贵的错。先用一个角色 + 虚拟组 + 一张口径字典 + 一个帆软,跑通再说。
5. **中高端调性是红线**——忌无差别打折,清货走私域定向、制造稀缺而非常态降价。

## 结语:这份方案的承重逻辑

> 买断模式让滞销直接等于亏损 → 2000 万沉在「看不见 + 反应慢」→ 先用商品底座看清并指挥五个止损杠杆(目标一)→ 会员 / 私域当主力出口、同时拉动 90% 的增长(目标二)→ 数据资产在这个过程里自然沉淀并收口(目标三)→ 全程靠一个跨域负责人 + 一张统一口径字典兜底。

它**不贵、不重,可以下周就开始第一仗**(周度售罄 review + 调拨止血),用最便宜的动作证明 ROI,再撬后面的预算。
